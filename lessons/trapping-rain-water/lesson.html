Trapping Rain Water

LC #42 Hard Arrays · Two Pointers

Before you code

Clarifying questions to ask first

Ask these before touching any code. Each answer constrains the design.

What does height[i] represent?

The height of a wall at position i. Non-negative integers.

→ water above bar = water level − bar height ≥ 0

Can heights be zero?

Yes — a zero-height bar is a gap; it can hold water if bounded on both sides.

→ no special-casing, the formula handles it

Can the array be empty or length 1?

Yes. No pair of walls means no trapped water.

→ while L≤R handles this — loop never runs

What do we return?

int — total units of water trapped across the entire array.

→ accumulate a running sum, not a per-index array

Assumptions we carry forward

Non-negative integer heights. Water at the edges is always 0 — nothing bounds them on the outside. Return a single integer total.

The Insight

Water level at any bar is set by its shortest surrounding wall

At any bar i, water rises only as high as the shorter of its tallest left wall and tallest right wall. Trapped water = that shorter ceiling minus the bar's own height. Two pointers from the outside in let us commit water at whichever side's running max is the bottleneck — one pass, no extra arrays.

The kernel

water[i] = min(maxL, maxR) − height[i]  ·  commit water at the side whose running max is smaller
The bottleneck side's max bounds the water; the other side's bigger bar only widens the safety margin.

Step 1

Brute force: scan left and right for every bar

Apply the formula naively: for each bar, scan leftward to find maxLeft, scan rightward to find maxRight. Two scans per bar — O(n) work per index.

processing index —  ·  —  ·  comparisons: 0

Cost: O(n²) time

Two nested scans per bar — O(n) work for each of n bars.

int trap_BF(vector<int>& h) {
    int n = h.size(), water = 0;
    for (int i = 0; i < n; i++) {
        int maxL = 0, maxR = 0;
        for (int j = 0; j <= i; j++) { maxL = max(maxL, h[j]); }  // scan left O(n)
        for (int j = i; j < n; j++) { maxR = max(maxR, h[j]); }  // scan right O(n)
        water += min(maxL, maxR) - h[i];
    }
    return water;
}

Step 2

Three translations to O(n) time, O(1) space

The brute force recomputes maxLeft and maxRight from scratch for every bar. Three translations eliminate that work entirely. Read all three before the code.

1

Translation 1 — Precompute both max arrays (DP)

One left-to-right pass builds maxL[i]. One right-to-left pass builds maxR[i]. A third pass applies the formula. Three O(n) passes instead of n×O(n).

Before
O(n²) / O(1)
After T1
O(n) / O(n)
Target
O(n) / O(1)

→ time fixed. Space still O(n) — two arrays remain.

2

Translation 2 — The bottleneck observation

We don't need both maxL and maxR simultaneously. We only need the smaller one — that's the bottleneck. If our running maxL ≤ maxR, the right wall is at least as tall as maxL, so the water ceiling at L is exactly maxL — regardless of what lies further right. Process L now. Same logic applies symmetrically for R.

maxL ≤ maxR → process L: water += maxL − h[L]
maxR < maxL → process R: water += maxR − h[R]

→ only one running max needed at a time. Arrays not needed.

3

Translation 3 — Two inward-converging pointers

Replace the two stored arrays with two integer variables maxL, maxR and two pointers L=0, R=n−1. At each step, update the smaller side's running max, add its water contribution, advance that pointer inward. L and R meet after exactly n steps.

→ space: O(n) → O(1). Four integers replace two arrays.

Step 3

The algorithm in plain English

Say this before writing any code.

1.Initialize L=0, R=n−1, maxL=0, maxR=0, water=0.
2.While L ≤ R: compare maxL and maxR to find which side is the bottleneck.
3.If maxL ≤ maxR: update maxL = max(maxL, h[L]), add maxL − h[L] to water, advance L++.
4.Else: update maxR = max(maxR, h[R]), add maxR − h[R] to water, retreat R--.
5.When L > R, every bar processed. Return water.

Why update maxL before adding water

maxL = max(maxL, h[L]) runs first — maxL now accounts for h[L] itself. So maxL − h[L] is always ≥ 0. If h[L] is a new maximum, maxL equals h[L] and water contribution is 0 (a wall, not a pool).

Step 4

Canonical C++ solution

Try writing this from the five steps above before revealing.

int trap(vector<int>& height) {
    int L = 0, R = (int)height.size() - 1;
    int maxL = 0, maxR = 0, water = 0;

    while (L <= R) {
        if (maxL <= maxR) {
            maxL = max(maxL, height[L]);   // update before adding water
            water += maxL - height[L];        // always >= 0
            L++;
        } else {
            maxR = max(maxR, height[R]);
            water += maxR - height[R];
            R--;
        }
    }
    return water;
}

Step 7

Corner cases

1

Empty or single-element array

L=0, R≤0: loop condition L≤R is false immediately. Returns 0 with no guard needed.

2

Monotonically increasing — [1,2,3,4,5]

Each bar is the new maxL, so maxL = h[L] at every step and water += maxL − h[L] = 0. Returns 0.

3

Plateau — [3,3,3,3]

maxL = maxR = 3 throughout. water += 3 − 3 = 0 at every step. A flat roof holds no water.

4

Single valley — [5,0,5]

L=0: maxL=5, maxR=5, water+=0, L++. L=1: maxL=5≤5, water+=5−0=5, L++. L>R. Returns 5.

5

All zeros — [0,0,0]

maxL=maxR=0, water+=0−0=0 every step. Returns 0. No risk of negative contributions.

Step 8

Production readiness

✓

Empty array: L=0, R=-1 → while false → return 0.

✓

Water never negative: maxL updated before water+=maxL−h[L], so maxL≥h[L] always.

✓

Integer overflow: n≤20000, heights≤100000. Max water ≈ 10⁹, fits in int. Use long long if constraints loosen.

✓

Every index visited exactly once: L and R advance monotonically inward until they cross.

✓

L == R case: when they meet at the same index, the loop processes it once and then advances so L > R. No double-counting.

Step 9

Approaches

Time O(n)Space O(1)

Single pass, two inward-converging pointers, two running-max variables. Processes whichever side has the smaller running max — that side's water is finalized without seeing the other side. The algorithm above.

Time O(n)Space O(n)

Clearest proof of correctness — explain this in an interview first, then derive the two-pointer version. Precompute both max arrays, then apply the formula in one pass.

int trap(vector<int>& h) {
    int n = h.size();
    vector<int> lMax(n), rMax(n);
    lMax[0] = h[0];
    for (int i=1; i<n; i++)   lMax[i] = max(lMax[i-1], h[i]);
    rMax[n-1] = h[n-1];
    for (int i=n-2; i>=0; i--) rMax[i] = max(rMax[i+1], h[i]);
    int water = 0;
    for (int i=0; i<n; i++) water += min(lMax[i], rMax[i]) - h[i];
    return water;
}
Time O(n²)Space O(1)

Rebuild maxLeft and maxRight by scanning from each bar. Correct, but TLE on large inputs. The starting point for explaining the three translations above.

Take home

What to remember for similar problems

The bottleneck principle: once you know one side's running max is ≤ the other's, that side's water is finalized. You don't need to look further in that direction. This insight compresses O(n) DP space to O(1) by eliminating the need to store both max arrays.

In an interview: explain the DP formulation first — it's the easiest proof. Then point out you only ever use the smaller max, so you can keep just one running max per side and compress to two pointers. The two-pointer solution is the DP solution with arrays removed.
