Majority Element

LC #169 Easy Array

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

Is the majority element guaranteed to exist?

Yes — the problem guarantees exactly one element appears more than ⌊n/2⌋ times.

→ Boyer-Moore's surviving candidate is always correct; no second-pass verification needed.

Can we modify the input array?

Not required. Boyer-Moore scans in one pass with no writes to the array.

→ O(1) extra space is achievable — no auxiliary storage needed.

What are the input constraints?

1 ≤ n ≤ 5×10⁴; elements are 32-bit integers.

→ Even O(n log n) sort fits; the interesting goal is O(n) time, O(1) space.

Why not just use a hash map?

A hash map gives O(n) time and O(n) space — it works.

→ Boyer-Moore achieves O(1) space via vote cancellation; this is the insight worth learning.

Assumptions we carry forward

Majority always exists; no modification of input needed; target is O(n) time, O(1) auxiliary space.

The Insight

Pair each majority vote with a non-majority vote — the majority always has one left.

If one element appears more than ⌊n/2⌋ times, no coalition of the others can outvote it. Walk once with one tentative candidate and a count: matches add a vote, mismatches cancel one, count=0 swaps in a new candidate. Cancellations discard equal counts from both camps, so the majority is mathematically the last one standing.

The kernel

candidate, count = nums[0], 0; for each x: if count == 0 → candidate = x; count += (x == candidate ? 1 : −1)
Every cancellation discards equal counts of majority and non-majority; the survivor must be the majority.

Step 1

Brute force — feel the cost

For each element at index i, scan the entire array to count how many times it appears. If count > n/2, return it. This is O(n²): the outer loop is O(n), each inner scan is O(n). For n = 5×10⁴ that's 2.5 billion operations.

Checks: 0 Count so far: 0 
int majorityElement(vector<int>& nums) {
    int n = nums.size();
    for (int i = 0; i < n; i++) {
        int count = 0;
        for (int j = 0; j < n; j++) {
            if (nums[j] == nums[i]) { count++; }
        }
        if (count > n / 2) { return nums[i]; }
    }
    return -1; // unreachable — majority guaranteed
}

Step 2

Translations — every optimisation, named

Two independent improvements take the brute-force O(n²)/O(1) to Boyer-Moore O(n)/O(1). Read both before reading the code.

1

Translation 1 — Full rescan → hash map

The O(n²) approach rescans the entire array once per candidate element. Instead, one pass builds a frequency map: for nums = [2,2,1,1,2], the map is {2:3, 1:2}. A second scan (or inline check) finds count > n/2 = 2 → return 2. No rescanning needed.

→ O(n²) → O(n) time; O(1) auxiliary → O(n) auxiliary (the hash map)

2

Translation 2 — Hash map → Boyer-Moore vote

The hash map stores counts for every distinct element, but we only need one answer. Key observation: when a non-candidate element cancels a candidate vote (count drops to 0), both cancel out — the majority relationship for the remaining elements is unchanged. Discard both and start fresh. We never need more than one candidate and one counter.

[2, 1, 1, 2, 2]: candidate=2 meets 1, count→0. Discard pair. Resume at idx 2.
idx 2: count=0 → candidate=1, count=1. idx 3: 2≠1 → count=0. Discard again.
idx 4: count=0 → candidate=2, count=1. Return 2. ✓

→ O(n) time, O(n) space → O(n) time, O(1) space

Step 3

The algorithm in plain English

1.Set candidate = 0 and count = 0.
2.For each num in the array:
3.   If count == 0, reassign candidate = num — start a fresh tally.
4.   Update count: add 1 if num == candidate, subtract 1 otherwise.
5.Return candidate — the majority element always survives vote cancellation.

Step 4

Code

Try writing it from the five steps above. Reveal when ready to compare.

int majorityElement(vector<int>& nums) {
    int candidate = 0, count = 0;
    for (int num : nums) {
        if (count == 0) { candidate = num; }
        count += (num == candidate) ? 1 : -1;
    }
    return candidate;
}

Step 7

Corner cases

1

n = 1 — single element (e.g. [7])

count = 0 at start → candidate = 7, count = 1. Loop ends immediately. Return 7. A single element trivially satisfies "appears more than ⌊1/2⌋ = 0 times."

2

All identical (e.g. [3, 3, 3, 3])

candidate = 3 at i = 0, count climbs 1→2→3→4. count never reaches 0; candidate never resets. Return 3. No vote cancellation needed when majority dominates completely.

3

Minority element at the start (e.g. [1, 2, 2, 2, 2])

candidate = 1 at i = 0. i = 1: num ≠ candidate → count = 0. Wipe: candidate = 2, count = 1. count then builds to 3. Return 2. The initial wrong guess is discarded after the first wipe.

4

Two-value alternating (e.g. [1, 2, 1, 2, 1])

count resets to 0 every two elements. Candidate flips: 1→wipe→2→wipe→1. At the final reset, candidate = 1, count = 1. Return 1. The majority (3 out of 5) claims the last reset.

5

Candidate changes multiple times (e.g. [2, 1, 1, 2, 2])

Candidate changes 2→1→2 across two wipes (see dry-run Ex 3). A mid-stream candidate change never means the wrong final answer — the majority always has enough votes to reclaim the last slot.

Step 8

Production readiness

✓n = 1 — loop runs once, candidate = nums[0], returns immediately. Correct.
✓All identical — count climbs to n; candidate never resets. Return nums[0]. Correct.
✓Majority at end — wrong initial candidate gets wiped; majority reclaims the last reset. Correct.
✓Integer range — count is at most n (≤ 5×10⁴); no overflow on 32-bit int. candidate holds a value from the input — no arithmetic on it.
✓Guarantee dependency — Boyer-Moore is only correct when majority is guaranteed. Without the guarantee, add a second O(n) verification pass: recount candidate's occurrences and check count > n/2.
✓O(1) auxiliary space — candidate and count are the only variables. No extra allocation of any kind.

Step 9

Approaches — trade-offs

O(n)O(1)

One pass, two variables. The most space-efficient solution and the one interviewers expect after you mention "we can do better than a hash map." Requires the majority guarantee — without it, a second O(n) verification pass is needed. Same code as Step 4.

O(n)O(n)

Build an unordered_map<int,int> of frequencies in one pass. Return the key with count > n/2. Straightforward — no special insight needed. Good first answer in an interview before optimising to Boyer-Moore.

int majorityElement(vector<int>& nums) {
    unordered_map<int,int> freq;
    for (int x : nums) { freq[x]++; }
    for (auto& [k, v] : freq) {
        if (v > (int)nums.size() / 2) { return k; }
    }
    return -1;
}
O(n log n)O(1)

Sort the array; nums[n/2] is always the majority element — since it occupies more than half the positions, it must cover the median. Elegant correctness argument but O(n log n) is wasteful when O(n) is achievable. Useful when the array is already nearly sorted.

int majorityElement(vector<int>& nums) {
    sort(nums.begin(), nums.end());
    return nums[nums.size() / 2];
}
