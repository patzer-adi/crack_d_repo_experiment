Subsets

LC #78 Medium Backtracking

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

Are the elements distinct?
Yes — LC 78 guarantees unique integers. No subset is produced twice, so there is no de-dup work.
→ the include/skip tree has no repeated leaves; duplicates are a separate problem (Subsets II)
Does the empty set count? The full set?
Both are valid subsets. The empty set is the "skip everything" path; the full set is "include everything".
→ record a subset at every leaf, including the all-skip one
Does the output order matter?
No — the 2ⁿ subsets may come back in any order. We pick the order the recursion naturally emits.
→ skip-branch first, so ∅ comes out first and the full set last
How large can n get?
Up to ~20 — the output is 2ⁿ. Any method is Θ(n·2ⁿ) because the output itself is that big.
→ no sub-exponential trick to chase; aim for clarity, not asymptotics

The Insight

Every element is one yes/no choice — so there are exactly 2ⁿ subsets, one per branch of a decision tree

You likely tried to enumerate subsets by size, or with nested loops, and kept missing some or repeating others. Step back: a subset is nothing more than one yes/no answer per element — keep it, or leave it out. Make those choices one element at a time and every subset appears exactly once.

Read the animation as a binary decision tree:

Start with one empty path
Before any decision there is a single possibility — the empty subset ∅. Nothing has been kept or skipped yet.
i
Each element forks every path in two
Decide element i: every partial subset spawns two children — one that skips it (unchanged) and one that includes it (gains the element). The count doubles: 1 → 2 → 4 → 8.
2ⁿ
Each leaf is one subset
After all n elements are decided there are 2ⁿ root-to-leaf paths, and each spells out exactly one subset — no misses, no repeats. The recursion in §6 walks these paths depth-first instead of level by level, but reaches the same 2ⁿ leaves.

The kernel

Treat each element as an independent yes/no choice and lay the choices out one at a time: at depth i branch on element i — skip it or include it. The n choices form a binary tree with 2ⁿ root-to-leaf paths, and every path is one distinct subset. Walk the tree depth-first with a single shared path: push the element before the include branch and pop it after, so one array is reused across all 2ⁿ paths and a finished subset is recorded at every leaf.

Step 1

Brute force — feel the cost

The most mechanical idea: every subset is one membership pattern, so just number the patterns. Count an n-bit integer mask from 0 to 2ⁿ−1; bit (n−1−i) tells you whether element i is in. Decode each pattern into a subset. It is correct, and watch the bit-test counter — n tests per pattern, so n·2ⁿ in all.

patterns tried: 0 bit-tests: 0 subsets: 0

The catch: Θ(n·2ⁿ) time — but so is everything

The output has 2ⁿ subsets, so no method beats Θ(n·2ⁿ). The bitmask is not slower — it is just rigid: it hard-codes the 2ⁿ loop bound and leans on bit tricks, and it does not extend to the variants where you must skip duplicates or stop a branch early. The recursive include/skip view expresses the same choices more naturally and generalizes.

vector<vector<int>> subsets(vector<int>& nums) {
    int n = nums.size();
    vector<vector<int>> res;
    for (int mask = 0; mask < (1 << n); mask++) {   // every membership pattern
        vector<int> sub;
        for (int i = 0; i < n; i++) {
            if (mask & (1 << (n - 1 - i))) {        // bit set → element i is in
                sub.push_back(nums[i]);
            }
        }
        res.push_back(sub);
    }
    return res;
}

Step 2

Translations — every optimisation, named

Three swaps turn the rigid bitmask loop into clean recursive backtracking — the same 2ⁿ work, expressed as a decision tree that generalizes.

1
Membership bitmask → recursive include/skip
Instead of decoding integers, branch on each element directly: one call skips it, one includes it. The recursion is the decision tree, and it extends to pruning and to the duplicate / constrained variants where a flat loop cannot.
same 2ⁿ, but expressive and general
2
Rebuild each subset from scratch → one shared path with undo
Keep a single array. Before the include branch push_back(nums[i]); after it returns, pop_back(). The array is mutated in place and copied only at a leaf. This push / recurse / pop trio is backtracking.
O(n) working memory instead of copying at every node
3
"When do I stop?" → record at every leaf
When i == n all elements are decided, so the current path is exactly one finished subset. Copy it into the result once and return.
one subset per leaf, no misses or repeats

Step 3

The algorithm in plain English

1
Hold a result list and one reusable path. res collects finished subsets; path is the current set of decisions.
2
At a leaf, record. In dfs(i), if i == n every element is decided — push a copy of path into res and return.
3
Skip branch first. Recurse with dfs(i + 1) leaving path unchanged — this explores every subset that omits element i.
4
Include branch, then undo. path.push_back(nums[i]), recurse with dfs(i + 1), then path.pop_back() to backtrack so the caller's path is clean.
5
Kick off and return. Call dfs(0); when it returns, res holds all 2ⁿ subsets.

Step 4

Code

class Solution {
    vector<vector<int>> res;

    void dfs(vector<int>& nums, int i, vector<int>& path) {
        if (i == (int)nums.size()) {   // all elements decided → one subset
            res.push_back(path);
            return;
        }
        dfs(nums, i + 1, path);        // branch 1: skip nums[i]
        path.push_back(nums[i]);       // branch 2: include nums[i]
        dfs(nums, i + 1, path);
        path.pop_back();               // undo, keep the caller's path clean
    }

public:
    vector<vector<int>> subsets(vector<int>& nums) {
        vector<int> path;
        dfs(nums, 0, path);
        return res;
    }
};

Step 7

Corner cases

1
Empty input
nums = []: n = 0, so dfs(0) immediately hits i == n and records the empty subset. The answer is [[]] — one subset, not zero. The empty set is always a subset.
2
Single element
nums = [0]: two leaves — skip 0 → [], include 0 → [0]. Answer [[],[0]]. The smallest case that still shows both branches.
3
Copy the path, don't store a reference
At a leaf you must push a copy of path (res.push_back(path) copies in C++). Storing a pointer/reference would leave every recorded subset pointing at the same array, which the later pop_backs mutate — you would end up with 2ⁿ copies of [].
4
Forgetting to backtrack
Drop the pop_back() and the include of element i leaks into its sibling skip branch — you get wrong, oversized subsets. Every push_back in the include branch needs its matching pop_back.
5
Duplicates change the problem
nums = [1,2,2] would make this code emit [2] and [1,2] twice. LC 78 forbids duplicates; the duplicate case (Subsets II) needs sorting plus a "skip equal siblings" guard. Don't bolt it on here unless asked.

Step 8

Production readiness

✓
Empty input returns [[]], not [] — the base case fires once even with no elements.
✓
Push a copy at each leaf so later pop_backs never mutate an already-recorded subset.
✓
Pair every push with a pop. The include branch's push_back must be undone by pop_back before returning.
✓
Recursion depth is exactly n — well within limits for n ≤ 20; no stack-overflow risk. An explicit stack or the bitmask loop is available if recursion is unwelcome.
✓
Reserve the output if n is known. res.reserve(1 << n) avoids 2ⁿ reallocations on the growing result vector.
✓
Decide the output contract. LC accepts any order; if a caller needs a stable order, sort or fix the branch order — don't assume.

Step 9

Approaches — trade-offs

O(n·2ⁿ)O(n)

Recurse on the include/skip decision tree with one shared path and push/pop backtracking. This is the intended solution — it expresses the choices directly and is the template you extend for Subsets II, Combinations, Permutations, and Combination Sum (just change what each level decides and add pruning).

O(n·2ⁿ)O(1) extra

No recursion: start with {{}} and, for each element, append a copy of every existing subset with the element added. The result doubles per element. Elegant and iterative, but it materializes the whole list as it goes and does not offer a place to prune — harder to adapt to constrained variants.

vector<vector<int>> res = {{}};
for (int x : nums) {
    int sz = res.size();
    for (int i = 0; i < sz; i++) {
        vector<int> cur = res[i];
        cur.push_back(x);
        res.push_back(cur);
    }
}
return res;
O(n·2ⁿ)O(1) extra

The brute force from Step 1: number every subset 0..2ⁿ−1 and read the bits. Compact and branch-free, great when n is a known small constant, but it hard-codes the 2ⁿ bound, needs bit manipulation, and cannot prune — so it does not generalize to the harder backtracking problems.

Step 10

Complexity

Time
O(n·2ⁿ)
There are 2ⁿ subsets and copying each finished path into the result costs up to O(n). The output size alone forces this bound.
Space
O(n)
Auxiliary: recursion depth n plus the single shared path. The output itself is O(n·2ⁿ) but is required, not extra.

Take home

Related problems that use this pattern

LC 90 — Subsets II: same include/skip tree, but with duplicate elements. Sort first, then within a level skip an element equal to its previous sibling so identical subsets are not produced twice.

LC 46 — Permutations: the decision at each level is "which unused element goes next" instead of "in or out". Same shared-path + backtrack skeleton, a used[] marker replaces the index.

LC 77 — Combinations / LC 39 — Combination Sum: the same tree with a target size or running sum, and a pruning condition that cuts branches that can no longer succeed.

The trick to carry: whenever the answer is "all ways to choose", model each item as a branch in a decision tree and recurse with one shared path — push before you descend, pop when you come back up.
