LC #542 Medium Graphs — BFS / DFS

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

How is distance measured — diagonal or orthogonal?
One step per orthogonal move (up/down/left/right). It is the grid shortest path, not Euclidean.
→ a 4-direction neighbour helper, distance +1 per hop
Is there always at least one 0 in the matrix?
Yes — the problem guarantees it. So every 1 has some 0 to measure to.
→ the BFS queue is never empty; no unreachable case
Should I search outward from each 1, or inward from the 0s?
Flip it: flood out from every 0 at once. The first wave to touch a cell carries its answer.
→ multi-source BFS seeded with every 0
Can I reuse the input grid for output?
Cleaner to allocate a dist matrix initialised to -1, which doubles as the "visited" marker.
→ dist == -1 means "not reached yet"

The Insight

Don't search from each 1 — flood outward from every 0 at once

You probably stood on each 1 and searched outward for the nearest 0 — re-walking the grid once per cell. Flip it: drop every 0 into one queue and let distance spread in synchronized rings. The first ring to reach a cell comes from its nearest 0, so the wave number it arrives on is that cell's answer.

0-cell — source, distance 0 not reached yet filled with its distance just reached this wave
Read the animation as expanding rings:
0
Seed every source at once
Distance 0 — every 0-cell goes into one shared queue. They are all equal starting points; none waits its turn.
k
One ring per distance
On wave k, the whole current frontier reaches its not-yet-visited orthogonal neighbours (blue ring). Those cells are exactly distance k from their nearest 0 — stamp them and they become the next ring.
∎
First touch wins
Because waves expand one ring per step, the first wave to land on a cell is the closest 0. We never overwrite — a cell, once stamped, is done.

The kernel

Seed a BFS queue with every 0-cell at distance 0 (multi-source). Pop cells in FIFO order; for each unvisited orthogonal neighbour, set its distance to the current cell's distance + 1 and enqueue it. Because all sources start together and BFS expands one ring at a time, the first time a cell is reached is its distance to the nearest 0. One pass fills the whole matrix.

Step 1

Brute force — feel the cost

The naive idea takes the question literally: stand on each 1-cell and BFS outward until you hit the nearest 0, recording how many steps that took. Correct, but each of the up-to-m·n ones re-explores a large slice of the grid — so the whole thing is O((m·n)²). Watch the cell-scan counter climb as every cell repeats almost the same search its neighbour just did.

cells resolved: 0 cell-scans: 0

Cost: O((m·n)²) time, O(m·n) space

Every 1-cell runs its own independent search, re-walking cells its neighbours already walked. The cell-scan counter is the point — adjacent ones repeat nearly identical work instead of sharing it.

vector<vector<int>> updateMatrix(vector<vector<int>>& mat) {
    int m = mat.size(), n = mat[0].size();
    vector<vector<int>> dist(m, vector<int>(n, 0));
    int dr[] = {1,-1,0,0}, dc[] = {0,0,1,-1};
    for (int sr = 0; sr < m; sr++) {
        for (int sc = 0; sc < n; sc++) {
            if (mat[sr][sc] == 0) { continue; }
            // BFS from this single 1-cell until the nearest 0
            vector<vector<bool>> seen(m, vector<bool>(n, false));
            queue<array<int,3>> q;
            q.push({sr, sc, 0}); seen[sr][sc] = true;
            while (!q.empty()) {
                auto [r, c, d] = q.front(); q.pop();
                if (mat[r][c] == 0) { dist[sr][sc] = d; break; }
                for (int k = 0; k < 4; k++) {
                    int nr = r+dr[k], nc = c+dc[k];
                    if (nr<0||nr>=m||nc<0||nc>=n||seen[nr][nc]) { continue; }
                    seen[nr][nc] = true; q.push({nr, nc, d+1});
                }
            }
        }
    }
    return dist;
}

Step 2

Translations — every optimisation, named

Three swaps turn the per-cell re-search into a single linear flood.

1
Search from each 1 → flood from every 0
Invert the direction. Instead of "where is the nearest 0 to me", ask "how far has each 0 reached". Seed one queue with every 0-cell (multi-source BFS).
drops the "which 1-cell" outer factor
2
Re-walking settled cells → visit each cell once
A dist matrix starts at -1; the moment a cell is stamped it is never revisited. Settled regions are never re-explored.
O((m·n)²) → O(m·n)
3
"Find the min over sources" → first touch wins
BFS expands one ring per step, so the first wave to reach a cell is necessarily the closest source. No min-over-sources comparison — just check dist == -1.
O(1) per neighbour; no distance comparison

Step 3

The algorithm in plain English

1
Initialise. Make a dist matrix: 0 for every 0-cell, -1 for every 1-cell. -1 means "not reached".
2
Seed all sources. Enqueue every 0-cell. They are the entire distance-0 frontier.
3
Flood. While the queue is non-empty, pop a cell and look at its four orthogonal neighbours.
4
Stamp first touches only. For each neighbour still at -1, set its distance to dist[cur] + 1 and enqueue it. Skip neighbours already stamped — they were reached by a closer 0.
5
Return. When the queue drains, every cell holds its distance to the nearest 0. Return dist.

Step 4

Code

vector<vector<int>> updateMatrix(vector<vector<int>>& mat) {
    int m = mat.size(), n = mat[0].size();
    vector<vector<int>> dist(m, vector<int>(n, -1));
    queue<pair<int,int>> q;
    for (int r = 0; r < m; r++) {
        for (int c = 0; c < n; c++) {
            if (mat[r][c] == 0) { dist[r][c] = 0; q.push({r, c}); }
        }
    }
    int dr[] = {1, -1, 0, 0}, dc[] = {0, 0, 1, -1};
    while (!q.empty()) {
        auto [r, c] = q.front(); q.pop();
        for (int d = 0; d < 4; d++) {
            int nr = r + dr[d], nc = c + dc[d];
            if (nr < 0 || nr >= m || nc < 0 || nc >= n) { continue; }
            if (dist[nr][nc] != -1) { continue; }   // already reached by a closer 0
            dist[nr][nc] = dist[r][c] + 1;            // first touch = nearest
            q.push({nr, nc});
        }
    }
    return dist;
}

Step 7

Corner cases

1
All zeros
[[0,0],[0,0]]: every cell is a source at distance 0. The queue drains with no neighbour ever at -1, so the answer is the all-zero matrix.
2
A single 0 in a sea of ones
One source feeds the entire grid. Distances grow as the Manhattan distance to that cell — the farthest corner is the deepest wave. Still one linear pass.
3
Two sources reaching the same cell
A middle cell may sit between two 0s. Whichever wave arrives first stamps it; the dist != -1 guard makes the later wave skip it, so it keeps the smaller distance for free.
4
A single row or column
[[1,1,0,1,1]]: distances ripple left and right from the 0 → [[2,1,0,1,2]]. The 4-direction helper still works; out-of-row neighbours are just bounds-rejected.
5
Don't seed only one 0
Seeding a single 0 and re-running per source loses the "all rings advance together" guarantee and overcounts. Every 0 must be in the queue at distance 0 before the first pop.

Step 8

Production readiness

✓
Bounds-check all four neighbours before indexing — an out-of-range read is undefined behaviour in C++.
✓
Use -1 as the visited marker in dist itself — no separate visited matrix needed.
✓
Seed every 0 before the first pop so all sources expand at the same rate. This is what makes "first touch = nearest" true.
✓
Never overwrite a stamped cell. The dist != -1 guard means each cell is finalised on first reach — no min comparison.
✓
Each cell is enqueued exactly once, so the queue and time are both O(m·n) — no risk of revisiting blowups.
✓
Distances are bounded by m·n, so plain int never overflows even on the largest grids.

Step 9

Approaches — trade-offs

O(m·n)O(m·n)

Seed the queue with every 0 and expand ring by ring. Each cell is enqueued once; the first wave to reach it carries its answer. This is the intended solution — simple, linear, and the queue's level structure maps exactly onto distance.

O(m·n)O(1) extra

No queue at all: two sweeps over dist. First top-left → bottom-right, taking the min of the up and left neighbour + 1; then bottom-right → top-left, taking the min of the down and right neighbour + 1. The two passes together cover all four directions of shortest path. Same time, but O(1) auxiliary space.

// dist[r][c] = 0 if mat==0 else BIG
// pass 1 (r,c increasing): min(self, up+1, left+1)
// pass 2 (r,c decreasing): min(self, down+1, right+1)
// the two diagonally-opposite sweeps cover every shortest path.
O((m·n)²)O(m·n)

The brute force from Step 1: BFS outward from each 1-cell until the nearest 0. Correct and literal, but adjacent ones repeat almost identical searches, so it is quadratic. Useful only to motivate flipping the search direction.

Step 10

Complexity

Time
O(m·n)
Each cell is enqueued at most once and its four neighbours inspected a constant number of times.
Space
O(m·n)
The BFS queue can hold up to every cell in the worst case (e.g. a grid that is all zeros at the start).

The trick to carry: when you want the nearest target for every cell, don't search from each cell — flood out from all the targets at once and let BFS layers double as a distance ruler.
