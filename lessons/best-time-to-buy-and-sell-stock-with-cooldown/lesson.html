Best Time to Buy and Sell Stock with Cooldown

LC #309 Medium Dynamic Programming

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

Can I hold more than one share at once?

No — at most one share at a time; you must sell before buying again.

→ the day's state is one of three labels, not a share count

What exactly does "cooldown" mean?

The day immediately after a sell, you may not buy.

→ a "just sold" state must be distinct from "free to buy"

How many transactions are allowed?

As many as you like, subject to the one-share and cooldown rules.

→ the buy/sell cycle must be allowed to repeat

What are the input bounds?

1 ≤ n ≤ 5000, 0 ≤ prices[i] ≤ 1000.

→ an O(n) pass with three running ints is plenty fast

Assumptions we carry forward

One share at a time, unlimited transactions, a one-day cooldown after every sell, and small bounds. The answer is a single number — the maximum achievable profit — and we never need to end the timeline still holding a share.

The Insight

Three states per day; carry the best profit in each

Forget about tracking which specific days you bought and sold. On any given day you are in exactly one of three situations: you hold a share, you have just sold today (so tomorrow is a forced cooldown), or you are resting with no share and free to buy. The transitions between these are completely fixed — from resting you may stay or buy, from holding you may stay or sell, and from just-sold you can only drift into resting. So instead of searching over buy/sell schedules, carry the best profit reachable in each of the three states from one day to the next; cooldown is captured simply by routing "just sold" only into "rest", never straight back into a buy.

prices = [1, 2, 3, 0, 2]  ·  profit ending each day in each state
hold (own a share) sold (cooldown next) rest (free to buy)

The kernel

Track three running values: hold (best profit while owning a share), sold (best profit if you sell today), and rest (best profit while idle and free to buy). Each new day: hold = max(hold, rest − p), sold = hold + p, rest = max(rest, sold) — all computed from yesterday's snapshot. The cooldown lives entirely in that last line: today's rest can absorb yesterday's sold, so a freshly-sold position is never allowed to buy on the very next day. Answer: max(sold, rest).

Step 1

Brute force — feel the cost

Without the state insight, the only sure way is to try every decision at every day: when free, branch into buy or skip; when holding, branch into sell or hold; after a sell, the next day is forced cooldown. That is a binary decision tree of depth n — roughly 2ⁿ paths. Watch the "States explored" counter detonate even on a five-day input; the same sub-situations are re-derived over and over, which is exactly the redundancy the three running variables eliminate.

int rec(vector<int>& prices, int day, int state) {  // state: 0 free, 1 hold, 2 cooldown
    if (day >= (int)prices.size()) {
        return 0;
    }
    if (state == 1) {                    // holding
        return max(prices[day] + rec(prices, day + 1, 2),  // sell
                   rec(prices, day + 1, 1));            // keep holding
    } else if (state == 0) {             // free to buy
        return max(-prices[day] + rec(prices, day + 1, 1), // buy
                   rec(prices, day + 1, 0));            // skip
    } else {                            // cooldown
        return rec(prices, day + 1, 0);
    }
}

Step 2

Translations — every optimisation, named

From the exponential search to three O(1) variables, each step squeezes out a layer of redundant work.

1

Name the day's situation: hold / sold / rest

Replace "which days did I trade?" with "which of three states does today end in?" Each state stores the best profit achievable ending the day that way — the entire history collapses into one of three numbers.

2ⁿ paths → 3 states per day

2

Encode the cooldown by splitting "not holding"

A single "no share" state can't express "but you can't buy yet". Splitting it into sold (today) and rest (later) makes the rule a one-liner: rest = max(rest, sold) routes yesterday's sale into today's idle state, never into a buy.

O(n) DP table, O(n) time

3

Only yesterday matters → three rolling ints

Every transition reads only the previous day's three values, so there is no need to keep the whole table. Snapshot the trio, compute the new trio, assign together.

O(n) space → O(1) space

Step 3

The algorithm in plain English

1.Seed hold = −prices[0], sold = 0, rest = 0 for day 0.
2.For each day from 1 to n−1, read p = prices[day].
3.Compute new_hold = max(hold, rest − p) — keep holding, or buy today out of rest.
4.Compute new_sold = hold + p and new_rest = max(rest, sold).
5.Assign all three at once, from the snapshot — never mix today's and yesterday's values.
6.Return max(sold, rest) — the best profit ending without a share.

Step 4

Code

int maxProfit(vector<int>& prices) {
    int n = prices.size();
    int hold = -prices[0], sold = 0, rest = 0;
    for (int day = 1; day < n; day++) {
        int p = prices[day];
        int nh = max(hold, rest - p);
        int ns = hold + p;
        int nr = max(rest, sold);
        hold = nh; sold = ns; rest = nr;
    }
    return max(sold, rest);
}

Step 7

Corner cases

1

Single day

[5] → 0. The loop body never runs; max(sold, rest) = max(0, 0) = 0. No special-casing needed beyond seeding day 0.

2

Monotonically decreasing

[3,2,1] → 0. hold stays negative and sold never beats 0, so rest holds the no-trade baseline. Don't seed sold to −∞ — 0 is correct.

3

All same price

[4,4,4,4] → 0. Any sell exactly cancels its buy: sold = hold + p = −p + p = 0. The algorithm returns 0 without a guard.

4

Cooldown forbids the greedy chain

On [1,2,3] the answer is 2 (buy day 0, sell day 2). A "sum every up-step" greedy would want to also sell day 1 and re-buy — but that buy is illegal during cooldown. The state machine rejects it automatically.

5

Forgetting to snapshot

Using the just-updated hold inside the sold formula mixes today's value with yesterday's. Always compute nh, ns, nr first, then assign all three together.

Step 8

Production readiness

✓Empty / single input: n == 0 returns 0; n == 1 seeds and returns max(0,0)=0.
✓Baseline initialisation: sold and rest start at 0 (the no-trade outcome), not −∞ — losing inputs correctly yield 0.
✓Snapshot discipline: compute all three new values before assigning any, so transitions read a consistent previous day.
✓Cooldown correctness: the rule lives solely in rest = max(rest, sold); there is no path from a same-day sell straight into a buy.
✓Overflow: values fit comfortably in int at these bounds; use long long if bounds widen.
✓Answer state: return max(sold, rest), never hold — ending while holding an unsold share is never optimal.

Step 9

Approaches — trade-offs

Time O(n)Space O(1)

The chosen answer. Only the previous day matters, so the DP collapses to three variables. One pass, constant space — the interview answer.

int hold = -prices[0], sold = 0, rest = 0;
for (int day = 1; day < n; day++) {
    int p = prices[day];
    int nh = max(hold, rest - p), ns = hold + p, nr = max(rest, sold);
    hold = nh; sold = ns; rest = nr;
}
return max(sold, rest);
Time O(n)Space O(n)

The same recurrence tabulated in dp[day][state]. Easy to debug because you can print the whole table, but it keeps memory you never re-read at this n.

vector<array<int,3>> dp(n);
dp[0] = {-prices[0], 0, 0};   // hold, sold, rest
for (int d = 1; d < n; d++) {
    dp[d][0] = max(dp[d-1][0], dp[d-1][2] - prices[d]);
    dp[d][1] = dp[d-1][0] + prices[d];
    dp[d][2] = max(dp[d-1][2], dp[d-1][1]);
}
return max(dp[n-1][1], dp[n-1][2]);
Time O(2ⁿ)Space O(n)

Recurse over every buy/sell/hold decision. Correct but exponential — useless past n≈20. It is the search space the "feel the cost" counter visualises, and memoising it is exactly how you arrive at the DP.

int rec(int day, int state) {
    if (day >= n) return 0;
    if (state == 1) return max(prices[day] + rec(day+1,2), rec(day+1,1));
    if (state == 0) return max(-prices[day] + rec(day+1,1), rec(day+1,0));
    return rec(day+1, 0);
}
