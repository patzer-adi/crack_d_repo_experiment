Assumptions we carry forward

Linear array of n ≥ 1 non-negative integers; forbid two adjacent indices; return the max sum. No need to reconstruct the chosen subset.

The Insight

At every house: rob it (pair with two-back) or skip it (carry one-back). The whole history collapses to two scalars.

Standing at house i, you face exactly two mutually-exclusive choices because adjacent houses are off-limits: rob it (collect nums[i], plus the best total you could have gotten up to two houses ago) or skip it (keep the best you had one house ago). Take the bigger. The clever bit: each decision only consults the two prior best totals, so you never build a length-n table — you slide two scalars prev2 and prev1 across the array.

Walking through nums = [2, 7, 9, 3] — each step does one thing: either DECIDE (rob vs skip) or SLIDE (advance the rolling pair).

The kernel

For each i, compute best[i] = max(best[i-1], best[i-2] + nums[i]) with best[-1] = best[-2] = 0. The recurrence only reads its last two values, so two scalars prev2, prev1 replace the array. After the loop, prev1 holds the answer. One pass, no auxiliary memory.

Why the answer collapses from a table to two variables:

Pick a subset of indices from nums, no two adjacent, maximising the sum.

Step 1

Brute force — feel the cost

We don't yet know any clever trick, so the safest first move is to try every possible plan and keep the best legal one.

A "plan" is one yes/no decision per house: rob it or leave it. With n houses that's n independent yes/no decisions, so the total number of plans is 2 × 2 × … × 2 = 2^n. For 4 houses → 16 plans, for 5 → 32, for 6 → 64, and the LeetCode constraint allows n = 100 which is hopeless.

For each plan we ask two questions: (1) Is it legal? — no two robbed houses sit next to each other. (2) If legal, what's the total money? — just add up the values of the robbed houses. Keep the best legal total seen so far.

The widget below shows each plan as a binary mask: a string of 0s and 1s, one bit per house, where 1 means "rob this house" and 0 means "leave it". Watch the counter at the bottom — every new house doubles the number of plans we have to try.

subset mask · adjacency check · running best
mask = 0000  ·  sum = 0  ·  legal = —  ·  best = 0
Subsets tried: 0 / 2n

Cost: O(2^n · n) time, O(n) space

Why this is too slow. Each new house doubles the count of plans. n = 20 already means ~1 million plans; n = 30 means a billion; n = 100 is more plans than there are atoms in the visible universe. Even worse, most plans we try are illegal (they pick two next-door houses) so the work is mostly wasted. We need a smarter approach — one that never enumerates plans at all.

int robBrute(vector<int>& nums) {
    int n = nums.size();
    int best = 0;
    // enumerate all 2^n subsets via bitmask
    for (int mask = 0; mask < (1 << n); mask++) {
        bool legal = true;
        int sum = 0;
        int prevBit = -2;
        for (int i = 0; i < n; i++) {
            if ((mask >> i) & 1) {
                if (i - prevBit == 1) { legal = false; break; }
                sum += nums[i];
                prevBit = i;
            }
        }
        if (legal) { best = max(best, sum); }
    }
    return best;
}

Step 2

Translations — every optimisation, named

The brute force is correct but tries 2^n plans. We fix it in five small steps. Each step introduces one idea and assumes nothing from the previous step except its end result. By step 5, an exponential search has become a left-to-right loop that uses two integers of memory.

1
Step 1 — Stop listing plans. Decide one house at a time.
Instead of generating all 2^n plans up front, walk the houses from left to right and ask one question per house: rob this house, or skip it? If we rob house i we collect nums[i] and must skip house i+1 (adjacency rule); the rest of the problem is the same kind of "best total from here onward" question on houses i+2 …. If we skip house i, the rest is the same question on houses i+1 …. Write that as a function: best(i) = max(nums[i] + best(i+2), best(i+1)) — the first branch is "rob i", the second is "skip i". A function defined in terms of smaller calls to itself like this is called a recurrence.
→ O(2^n · n) → O(2^n)   (adjacency is now built into the recursion; no rescans)
2
Step 2 — Save the answers you've already computed (memoisation).
The recursion above is wasteful. best(i+2) gets called from two different paths: from the "rob i" branch directly, and from the "skip i, then rob i+1" branch a step later. Both paths arrive at the same subproblem and solve it from scratch — so the same value is recomputed many times, and the total work stays exponential. The fix is mechanical: the first time we compute best(i), store it in memo[i]; every later call for best(i) returns the cached value instead of recursing. This caching trick is called memoisation. Now there are exactly n distinct subproblems, each solved once.
→ O(2^n) → O(n) time, plus O(n) memo array + O(n) recursion stack
3
Step 3 — Flip the direction: build the table bottom-up.
Memoisation works, but it relies on recursion — function calls, an extra call stack, and the headache of figuring out which subproblem to compute first. We can avoid all that by iterating. Rewrite the recurrence as dp[i] = max(dp[i-1], dp[i-2] + nums[i]) and fill the dp array left to right starting from seeds dp[-1] = dp[-2] = 0 (meaning "no houses considered yet, best total is 0"). By the time we compute dp[i], both dp[i-1] and dp[i-2] are already there waiting. Same complexity as memoisation, but it's just a plain for-loop you can print and trace by hand. This pattern — solving small subproblems first and combining them into bigger ones — is the heart of dynamic programming.
→ same O(n) time and O(n) memory, but no recursion stack
4
Step 4 — Notice we only ever read the last two cells.
Look hard at dp[i] = max(dp[i-1], dp[i-2] + nums[i]). The right-hand side mentions dp[i-1] and dp[i-2] — and nothing else from the dp array. Once we've finished computing dp[i], the value at dp[i-2] is never read again (the next iteration needs dp[i-1] and dp[i], not dp[i-2]). So we're carrying around an array of n numbers but at any moment only two of them are actually used. The middle of the array is dead weight. This is just an observation — no code change yet — but it sets up step 5.
→ no change yet; this is the insight that enables the final step
5
Step 5 — Throw away the array; keep just two variables.
Replace the whole dp array with two integers: prev2 (the value that used to live at dp[i-2]) and prev1 (the value that used to live at dp[i-1]). For each new house i we compute cur = max(prev1, prev2 + nums[i]), then "slide" the two memory slots one position to the right: prev2 = prev1; prev1 = cur. Slide order matters. If you accidentally write prev1 = cur before prev2 = prev1, then prev2 will pick up the new cur instead of the old prev1, and the next iteration uses the wrong value. Always save the old prev1 before overwriting it.
→ O(n) time, O(1) memory  — this is the final answer

Step 3

The algorithm in plain English

1
Initialise prev2 = 0 and prev1 = 0. They stand for "best up to two houses before the first" and "best up to the house before the first" — both empty, both zero.
2
For each house x in nums (left to right):
3
Compute the two candidates: rob_it = prev2 + x (take this house, plus the best from two back) and skip = prev1 (leave it, keep the best from one back).
4
Take cur = max(rob_it, skip) — the new best up to this house.
5
Slide the window: prev2 = prev1 first, then prev1 = cur. Order matters — capture the old prev1 before overwriting it.
6
Return prev1 after the loop. By the slide rule it holds best[n-1] — the answer.

Step 4

Code

int rob(vector<int>& nums) {
    int prev2 = 0;
    int prev1 = 0;
    for (int x : nums) {
        int rob_it = prev2 + x;
        int skip   = prev1;
        int cur    = max(rob_it, skip);
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}

Step 7

Corner cases

1
Single house — [5] → 5
The loop body runs exactly once. rob_it = 0 + 5 = 5, skip = 0, cur = 5. Both seeds being 0 is what makes the single-house case return the house's own value without a special branch.
2
Two houses — [3, 10] → 10
Adjacency makes them mutually exclusive. At i=1: rob_it = 0 + 10 = 10 (because prev2 is still 0 from the seed), skip = 3. The algorithm correctly picks the larger.
3
Tie between rob and skip — [4, 4] → 4
At i=1: rob_it = 0 + 4 = 4 and skip = 4. max resolves the tie either way; the answer is still 4. No tie-break logic needed.
4
All zeros — [0, 0, 0, 0] → 0
Every iteration gives rob_it = skip = cur = 0. Because the constraint forbids negatives, "rob it" is never worse than "skip it" at zero, but it doesn't matter — both branches return the same number.
5
Bait at position 1 — [1, 100, 1, 1, 100] → 200
A greedy "rob every other house starting at index 0" picks {0, 2, 4} → 102 and misses the optimum. The DP correctly skips house 0 entirely and robs {1, 4} → 200. The running table is dp = [1, 100, 100, 101, 200] — proof that the rolling pair handles non-greedy interleavings.

Step 8

Production readiness

✓
Empty input — guard with if (nums.empty()) return 0; if the problem allows it; the loop already does the right thing on an empty range.
✓
Single-element input — handled by the prev2 = prev1 = 0 seeds; no special branch needed.
✓
Slide-order bug — write prev2 = prev1 before prev1 = cur; otherwise prev2 picks up the new value and the next iteration is wrong.
✓
Integer overflow — constraints cap each nums[i] ≤ 400 and n ≤ 100, so the sum fits in an int; if a variant relaxes either bound, switch to long long.
✓
Greedy intuition trap — "rob every other house" fails on inputs like [1,100,1,1,100]; only the DP recurrence is correct.
✓
Subset reconstruction — if the problem asks which houses, you must keep the DP array (not just two scalars) and walk back from dp[n-1] comparing to dp[n-2].
✓
Variant awareness — name the related problems (House Robber II/III, Delete and Earn) before the interviewer does; it signals you recognise the pattern.

Step 9

Approaches — trade-offs

O(n) time O(1) space

The expected production answer. Same loop body as the DP array, but only the last two dp values are kept as scalars. Hardest to write correctly the first time (the slide order traps everyone once), easiest to defend in an interview after you've written the array version on the whiteboard and pointed at the two cells you actually use.

int rob(vector<int>& nums) {
    int prev2 = 0, prev1 = 0;
    for (int x : nums) {
        int cur = max(prev1, prev2 + x);
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
O(n) time O(n) space

The version you'd write first on the whiteboard. Iterative, easy to print step-by-step, makes the recurrence completely visible. Linear extra memory is the only downside — and it's the natural stepping stone to the rolling-pair optimisation.

int rob(vector<int>& nums) {
    int n = nums.size();
    if (n == 0) { return 0; }
    vector<int> dp(n, 0);
    dp[0] = nums[0];
    for (int i = 1; i < n; i++) {
        int rob_it = (i >= 2 ? dp[i - 2] : 0) + nums[i];
        int skip   = dp[i - 1];
        dp[i] = max(rob_it, skip);
    }
    return dp[n - 1];
}
O(n) time O(n) memo + O(n) stack

Most natural translation of the recurrence — write it as a function and cache. Useful pedagogically: the two recursive calls map exactly to "rob this" and "skip this". Pays an extra O(n) recursion stack on top of the memo and is therefore never the production answer, but it's the version interviewers ask you to write when they want to see if you can derive the recurrence cold.

class Solution {
    vector<int> memo;
    int solve(vector<int>& nums, int i) {
        if (i >= (int)nums.size()) { return 0; }
        if (memo[i] != -1) { return memo[i]; }
        int rob_it = nums[i] + solve(nums, i + 2);
        int skip   = solve(nums, i + 1);
        return memo[i] = max(rob_it, skip);
    }
public:
    int rob(vector<int>& nums) {
        memo.assign(nums.size(), -1);
        return solve(nums, 0);
    }
};

Step 10

Complexity

Time
O(n)
One pass through nums; every iteration does constant work — two additions, one max, two assignments.
Space
O(1)
Two integers prev2, prev1 plus a per-iteration temporary cur. No array, no recursion stack.
