Product of Array Except Self

LC #238 Medium Arrays

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer locks in a design decision — and rules out an entire family of "obvious" solutions.

Can the input contain zeros?

Yes — and possibly more than one. Zero values are explicitly allowed.

→ rules out total ÷ nums[i]: division by zero crashes, and a single zero collapses the total product to 0.

Am I allowed to use the division operator?

No. The problem explicitly forbids it.

→ each answer[i] must be built from products of other elements, never from a quotient.

Does the output array count toward extra space?

No. Only auxiliary structures count toward the O(1) extra-space target.

→ answer[] can double as the prefix-product scratchpad — no second array needed.

Will every prefix product fit in a 32-bit int?

Yes — the problem promises it.

→ no big-int arithmetic; one running multiplier per pass is enough.

Assumptions we carry forward

Integer array of length ≥ 2; zeros and negatives allowed; no division; the returned answer[] doesn't count as extra space; every product fits in int.

The Insight

Split at i: every answer is left-product × right-product.

For any index i, the product of every element except nums[i] factors into two halves: everything strictly to the left, and everything strictly to the right. Knowing those two products, the answer at i is one multiplication. Two sweeps build both halves — a left-to-right pass for prefix products, then a right-to-left pass for suffix products.

The kernel

answer[i] = (∏ nums[0..i−1]) × (∏ nums[i+1..n−1])
L-pass writes prefix products into out[] (left-to-right). R-pass folds suffix products in (right-to-left). Two passes, one running accumulator per pass, O(1) extra space.

Step 1

Brute force — multiply every other element, for every index

For each index i, walk the entire array and multiply together every element whose index is not i. That is one full pass per output cell — n outputs × n elements = O(n²) multiplications. Correct, but quadratic.

i = —  ·  j = —  ·  prod = —  ·  multiplications: 0

Cost: O(n²) time

Re-multiplying everything-except-i for every i discards work that could be reused. Each prefix product is computed n times instead of once.

vector<int> productExceptSelf_BF(vector<int>& nums) {
    int n = nums.size();
    vector<int> out(n);
    for (int i = 0; i < n; i++) {
        int prod = 1;
        for (int j = 0; j < n; j++) {
            if (j != i) { prod *= nums[j]; }   // skip self
        }
        out[i] = prod;
    }
    return out;
}

Step 2

Four translations to O(n) time, O(1) extra space

The brute force recomputes the same prefix and suffix products n times each. These four named translations remove every duplicated multiplication and then collapse the auxiliary storage to a single integer.

1

Translation 1 — Split the product at i

Rewrite "product of all elements except nums[i]" as (prefix product up to i−1) × (suffix product from i+1). The two halves are independent — neither depends on which i we are computing.

→ identifies what to cache: prefix products and suffix products, not the full per-i product.

2

Translation 2 — Precompute both arrays (DP)

One left-to-right pass builds L[i] = ∏ nums[0..i−1]. One right-to-left pass builds R[i] = ∏ nums[i+1..n−1]. A third pass writes answer[i] = L[i] × R[i]. Three O(n) passes instead of n × O(n).

→ time fixed at O(n). Space still O(n) — two arrays of length n.

3

Translation 3 — Reuse answer[] as the prefix scratchpad

The first pass writes prefix products into answer[] directly. Now answer[i] already holds L[i]; the suffix array is the only extra storage left.

→ one of the two O(n) auxiliary arrays is gone.

4

Translation 4 — Replace the suffix array with one running variable

Walk right-to-left carrying a single integer right = 1. At each step, multiply answer[i] *= right, then update right *= nums[i]. The suffix product flows through one cell of memory.

→ space: O(n) → O(1) extra. One integer replaces the second array.

Step 3

The algorithm in plain English

1.Allocate answer[n] and a running multiplier left = 1.
2.Sweep left → right. At each i: write answer[i] = left, then update left *= nums[i]. After this pass, answer[i] holds the product of everything strictly left of i.
3.Reset a second running multiplier right = 1.
4.Sweep right → left. At each i: multiply answer[i] *= right, then update right *= nums[i].
5.Return answer.

Why write before update

In the L-pass, we write answer[i] = left before multiplying nums[i] in. That is what makes the stored value the product of elements strictly to the left of i — not including nums[i] itself. The R-pass mirrors this: multiply first, then update right.

Step 4

Canonical C++ solution

Try to reproduce this from the five steps before revealing.

vector<int> productExceptSelf(vector<int>& nums) {
    int n = nums.size();
    vector<int> out(n, 1);

    int left = 1;                            // L-pass: prefix products into out[]
    for (int i = 0; i < n; i++) {
        out[i] = left;                       // write BEFORE updating
        left *= nums[i];
    }

    int right = 1;                           // R-pass: fold in suffix products
    for (int i = n - 1; i >= 0; i--) {
        out[i] *= right;                     // multiply BEFORE updating
        right *= nums[i];
    }
    return out;
}

Step 7

Corner cases

1

Single zero in the array — e.g. [1, 2, 0, 4]

Only the index of the zero ends up non-zero; every other cell's product still contains that zero. The algorithm handles it without a branch — once left or right sees the zero, it propagates 0 into every subsequent multiplication.

2

Two or more zeros — e.g. [0, 1, 0, 4]

Every cell of the output is 0: each cell's product still contains at least one zero. No special case needed — both passes carry a 0 through their respective accumulators.

3

Negative numbers — e.g. [-1, 1, 0, -3, 3]

Sign of answer[i] is determined by the parity of negatives outside index i. The multiplications handle this automatically; nothing changes in the algorithm.

4

Length 2 — e.g. [a, b] → [b, a]

L-pass writes [1, a]; R-pass multiplies in b, 1 giving [b, a]. The smallest valid input — confirms accumulator initial value 1 is correct.

5

All ones — [1, 1, 1, 1]

Every cell of the output is 1. Sanity check that left and right both initialise to 1, not 0 — initialising to 0 would zero out every answer.

Step 8

Production readiness

✓

No division: meets the problem's hard constraint and avoids the divide-by-zero hazard.

✓

O(1) extra space: only two integer accumulators beyond the output array.

✓

Each cell visited exactly twice: once per pass — total work is 2n multiplications and 2n writes.

✓

Accumulators start at 1: not 0 — the multiplicative identity is 1. Verified by the all-ones case.

✓

Write before update (and multiply before update): guarantees each stored value excludes nums[i] itself.

✓

Integer overflow: per the problem's guarantee, every prefix product fits in int. Switch to long long if constraints loosen.

Step 9

Approaches — trade-offs

Time O(n)Space O(1) extra

Two passes; the first writes prefix products into out[], the second folds suffix products in using a single integer accumulator. The algorithm above. Strictly less memory than the DP variant; same correctness.

Time O(n)Space O(n)

Build two helper arrays L[i] and R[i] explicitly, then combine in a third pass. Easiest to read and the natural step in an interview before compressing to the optimal.

vector<int> productExceptSelf(vector<int>& nums) {
    int n = nums.size();
    vector<int> L(n, 1), R(n, 1), out(n);
    for (int i = 1; i < n; i++)   L[i] = L[i-1] * nums[i-1];
    for (int i = n-2; i >= 0; i--) R[i] = R[i+1] * nums[i+1];
    for (int i = 0; i < n; i++)   out[i] = L[i] * R[i];
    return out;
}
Time O(n²)Space O(1) extra

For each i, multiply every other element. TLEs on large n. Useful only as the derivation anchor for the translations above. Note: a "total product ÷ nums[i]" trick is O(n) but disqualified — the problem forbids division and zeros break it.

Step 10

Complexity

Brute force

O(n²) / O(1)

Prefix + suffix arrays

O(n) / O(n)

Three passes; two helper arrays of length n.

Two-pass, O(1) extra ✓

O(n) / O(1)

Two passes; output array reused as the prefix scratchpad; one suffix accumulator.

Take home

Related problems that use this pattern

The prefix–suffix decomposition: any per-index quantity that depends on "everything to the left and everything to the right" can be built with a left-pass plus a right-pass. The output array often doubles as the prefix scratchpad, saving an O(n) buffer.

In an interview: explain the prefix + suffix array variant first (it's the cleanest proof), then point out the output array can absorb one of the two halves, then compress the other half to a single running variable.
