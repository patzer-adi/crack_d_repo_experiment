Longest Repeating Character Replacement

LC #424 Medium Sliding Window

Before you code

Clarifying questions to ask first

Ask these before writing any code. Each answer constrains a specific design choice.

What's the alphabet?

Uppercase English letters only (A–Z). Per the constraints, s is non-empty and at most 10⁵ characters.

→ an int[26] freq array is enough; no hash map

Do we have to use all k replacements?

"At most" k — fewer is fine. We're maximising the resulting same-letter run length, not the number of edits performed.

→ validity is the inequality len − maxCount ≤ k

What if k ≥ |s|?

Then we can repaint every letter — the answer is just |s|. No bounds clamp needed; the algorithm naturally never invalidates.

→ window can span the whole string

Does maxCount need to be recomputed when the window shrinks?

No. The answer only grows when a *larger* valid window appears, which requires maxCount ≥ previousMax — only an R-side add can do that.

→ "sticky" maxCount, O(1) work per shrink

Assumptions we carry forward

s is non-empty A–Z, k ≥ 0, and "longest" is measured by length, not replacement count. We return a single integer — the length of the longest valid window.

The Insight

Keep the majority letter, replace the rest — and never count again on shrink.

In any window of length L, the cheapest way to make it uniform is to keep the most frequent letter and replace everything else. The number of replacements needed is exactly L − maxCount, where maxCount is the count of the most frequent letter inside that window. The window is "valid" when that quantity is ≤ k. So the problem reduces to: find the largest L for which a length-L window has L − maxCount ≤ k.

The kernel

Maintain a window [L..R] over s, plus freq[26] and a running maxCount. For each R: bump freq[s[R]] and update maxCount. If (R−L+1) − maxCount > k, decrement freq[s[L]] and advance L by one — the window stays the same size or grows; it never shrinks. maxCount is never decremented because the answer only updates on larger valid windows, and any such window must have a maxCount at least as large. The answer is the largest R−L+1 seen.

Step 1

Brute force — feel the cost

Enumerate every substring s[L..R]. For each one, count letter frequencies, find the max, and check if (R−L+1) − maxCount ≤ k. If so, update the answer. O(n²) substrings × O(n) to count = O(n²·n) = O(n³); with a per-substring freq array it's O(n²·26). Either way, TLE at n=10⁵. Step through to feel how much rescanning the same prefix wastes.

Cost: O(n²·26) time, O(26) space

Each (L, R) pair re-counts letter frequencies from scratch. The checks counter shows how many letter-bumps we do across all (L,R) — every L-restart throws away all the freq counts we built on the previous L. The sliding window below pays each character exactly twice (once on enter, once on leave) — total 2n bumps.

int characterReplacement_BF(string s, int k) {
    int n = s.size();
    int ans = 0;
    for (int L = 0; L < n; L++) {
        int freq[26] = {0};
        int maxC = 0;
        for (int R = L; R < n; R++) {
            freq[s[R] - 'A']++;
            if (freq[s[R] - 'A'] > maxC) {
                maxC = freq[s[R] - 'A'];
            }
            if ((R - L + 1) - maxC <= k) {
                ans = max(ans, R - L + 1);
            }
        }
    }
    return ans;
}

Step 2

Translations — every optimisation, named

Three independent moves take us from O(n²·26) to O(n). Each removes a distinct kind of waste: re-counting frequencies, re-finding the max-count letter, and recomputing maxCount on shrink.

1
Brute force — every substring
For each starting index L, walk R rightward and count freq from scratch. Check (R−L+1) − maxCount ≤ k at each step. Every L-restart rebuilds the freq array.
O(n²·26) time, O(26) space
2
Sliding window — incremental freq with full maxCount recompute
Use one window [L..R] and maintain freq[26] incrementally. Whenever the window becomes invalid, shrink L and rescan all 26 freq slots to refresh maxCount. Avoids re-counting; still pays O(26) per shrink.
O(n·26) time, O(26) space
3
Sticky maxCount — never decrement on shrink
Skip the 26-slot rescan. maxCount can lag behind the true max in the current window, but the answer only updates on larger valid windows — and any such window has a maxCount at least as big. Stale maxCount cannot cause a wrong answer; it only postpones invalidation.
O(n) time, O(26) space — taught

Step 3

The algorithm in plain English

1
Initialise freq[26] = {0}, L = 0, maxCount = 0, ans = 0.
2
For each R from 0 to n−1: freq[s[R]]++, then maxCount = max(maxCount, freq[s[R]]).
3
If the window is invalid ((R − L + 1) − maxCount > k): freq[s[L]]--, then L++. One shrink per outer step is enough — the window can only fall out of bounds by one position per R.
4
Update ans = max(ans, R − L + 1).
5
Return ans.

Step 4

Code

int characterReplacement(string s, int k) {
    int n = s.size();
    int freq[26] = {0};
    int L = 0, maxC = 0, ans = 0;
    for (int R = 0; R < n; R++) {
        freq[s[R] - 'A']++;
        if (freq[s[R] - 'A'] > maxC) {
            maxC = freq[s[R] - 'A'];
        }
        if ((R - L + 1) - maxC > k) {
            freq[s[L] - 'A']--;
            L++;
        }
        if (R - L + 1 > ans) {
            ans = R - L + 1;
        }
    }
    return ans;
}

Step 7

Corner cases

1
Single letter "A", k=0
Loop runs once. freq[A]=1, maxCount=1, len−max=0 ≤ 0. ans=1. The trivial baseline.
2
Already one letter "AAAA", k=2
maxCount climbs to n; len − maxCount = 0 on every step; never shrinks. ans=n. The k budget is wasted but the algorithm doesn't care.
3
k=0 boundary "AABCDE", k=0
Reduces to "longest run of the same letter". The window may grow only while the new letter equals the dominant one. Best is "AA" → ans=2.
4
All distinct "ABCDE", k=1
maxCount never exceeds 1; the window is valid iff len − 1 ≤ k = 1, i.e. len ≤ 2. Shrink fires every step from R=2 onward. ans=2.
5
k ≥ n: "ABCD", k=10
The full string is always valid; never invalidates. ans=n. No clamp on k needed.
6
Stagnant best: "AABABBA", k=1
Best window [0..3] = "AABA" found at R=3 → ans=4. Subsequent R's all slide the window right at the same size — ans never grows, and maxCount stays at 3 even though the current window's true max may be 2.

Step 8

Production readiness

✓
Never decrement maxCount on shrink. Even if the current window's true max is smaller, a stale maxCount only delays invalidation. The answer cannot be wrong because larger valid windows must rebuild maxCount via R-side adds.
✓
One shrink per outer iteration is sufficient. Each R adds exactly one letter; the window can become invalid by at most 1. An if beats a while — same correctness, simpler code, monotone L.
✓
Use int[26] over hash map. Constants matter at n=10⁵; the alphabet is fixed, so direct indexing by ch − 'A' wins on cache locality and avoids hashing overhead.
✓
Update maxCount only from the R-side bump. maxCount = max(maxCount, freq[s[R]]) after incrementing — checking the just-bumped letter is enough; no need to scan all 26 slots.
✓
No bounds clamp on k. If k ≥ n, the window is never invalid; if k = 0, the shrink fires whenever a non-dominant letter enters. Both cases are handled by the same code path.
✓
Watch for ASCII assumptions. The problem says uppercase A–Z; ch − 'A' works. If extended to mixed case or Unicode, switch to unordered_map<char,int> — the algorithm is unchanged.
✓
Return ans, not R − L + 1. The final window may not be the best — the answer is the max ever seen, not the current.

Step 9

Approaches — trade-offs

Time O(n²·26) Space O(26)

For each L, walk R rightward, rebuilding freq from scratch each L-restart. Simple but TLE on the LC bound. Worth knowing because it makes the cost of recounting visible.

int characterReplacement(string s, int k) {
    int n = s.size(), ans = 0;
    for (int L = 0; L < n; L++) {
        int freq[26] = {0}, maxC = 0;
        for (int R = L; R < n; R++) {
            freq[s[R] - 'A']++;
            maxC = max(maxC, freq[s[R] - 'A']);
            if ((R - L + 1) - maxC <= k) {
                ans = max(ans, R - L + 1);
            }
        }
    }
    return ans;
}
Time O(n·26) Space O(26)

Sliding window with incremental freq, but rescan all 26 slots after each shrink to refresh maxCount. Honest and easy to argue from correctness — but always slower than the sticky version. Pick this if interviewer wants no clever invariants.

int characterReplacement(string s, int k) {
    int n = s.size(), L = 0, ans = 0;
    int freq[26] = {0};
    for (int R = 0; R < n; R++) {
        freq[s[R] - 'A']++;
        int maxC = 0;
        for (int c = 0; c < 26; c++) { maxC = max(maxC, freq[c]); }
        while ((R - L + 1) - maxC > k) {
            freq[s[L] - 'A']--;
            L++;
            maxC = 0;
            for (int c = 0; c < 26; c++) { maxC = max(maxC, freq[c]); }
        }
        ans = max(ans, R - L + 1);
    }
    return ans;
}
Time O(n) Space O(26)

Never decrement maxCount; shrink at most once per R. maxCount acts as a high-water mark — it tracks the largest the most-frequent letter has ever been inside any valid window so far. The answer can only beat this when a real window beats it too. Canonical answer.

int characterReplacement(string s, int k) {
    int n = s.size(), L = 0, maxC = 0, ans = 0;
    int freq[26] = {0};
    for (int R = 0; R < n; R++) {
        freq[s[R] - 'A']++;
        maxC = max(maxC, freq[s[R] - 'A']);
        if ((R - L + 1) - maxC > k) {
            freq[s[L] - 'A']--;
            L++;
        }
        ans = max(ans, R - L + 1);
    }
    return ans;
}

Step 10

Complexity

Time
O(n)
Each R bumps one freq slot and may trigger one L shrink. Both pointers march left-to-right and never backtrack — total work is bounded by 2n.
Space
O(1)
An int[26] freq array plus a handful of scalars. The fixed alphabet keeps this constant regardless of input length.
