Interactive Lesson

Move Zeroes

LC #283 Easy Two Pointers

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

Must I preserve the order of the non-zero elements?

Yes. The relative order of non-zeros must stay the same; only the zeros move to the end.

→ rules out sorting; demands a stable compaction

In-place, or may I allocate a new array?

In-place — O(1) extra space is the target. A copy is allowed only as a brute-force baseline.

→ pushes us from "copy non-zeros out" to a two-pointer swap

What counts as a zero — only integer 0?

Yes, the literal value 0. No negatives-as-zero, no nulls.

→ the predicate is simply nums[i] != 0

Can the array be empty or all zeros?

Yes to both. Empty returns immediately; all-zeros is a no-op that must not crash.

→ the loop body must be safe when no non-zero is ever found

Assumptions we carry forward

Stable order of non-zeros, in-place with O(1) extra space, the predicate is != 0, and empty / all-zero inputs are valid. Minimise writes: an already-placed element should not be re-written.

The Insight

Keep one slot for "where the next non-zero belongs"

The zeros are noise; the non-zeros are the signal, and their order is sacred. So stop thinking about moving zeros at all. Instead, walk a read pointer across the array, and keep a write slot pointing at the first position that hasn't yet received a confirmed non-zero. Every time the reader lands on a non-zero, drop it into the write slot and advance the slot by one. Because you visit non-zeros left to right and place them left to right, their relative order is preserved automatically — and every position the write slot leaves behind is, by construction, a finished non-zero. Whatever the write slot never reaches must be zeros, so they end up trailing at the back for free.

nums = [0, 1, 0, 3, 12]  ·  w = write slot  ·  r = reader
reader (r) write slot (w) settled non-zero

The kernel

Maintain slow = the index where the next non-zero should land, starting at 0. Sweep fast from left to right. Whenever nums[fast] != 0, swap it into nums[slow] and increment slow. After the sweep, [0, slow) holds every non-zero in original order and [slow, n) is all zeros — no second pass needed.

Why one read pointer plus one write slot is enough:

Move every 0 to the end, keep the non-zeros in their original relative order, in place.

Step 1

Brute force — feel the cost

The most literal solution allocates a second array: scan the input, append every non-zero to the new array, then pad the remainder with zeros, then copy it back. It is correct and even O(n) time — but it spends O(n) extra memory and writes every element twice. Watch the "Writes" counter: the new array is filled, then copied back, so the work is doubled compared to the one-pass swap we will build next.

void moveZeroes(vector<int>& nums) {
    int n = nums.size();
    vector<int> out(n, 0);   // O(n) extra space
    int w = 0;
    for (int i = 0; i < n; i++) {
        if (nums[i] != 0) {
            out[w] = nums[i];      // write #1
            w++;
        }
    }
    for (int i = 0; i < n; i++) {
        nums[i] = out[i];          // write #2 (copy back)
    }
}

Step 2

Translations — every optimisation, named

From the copy-based baseline to the one-pass in-place swap, two ideas do all the work: drop the second array, and avoid touching slots that are already correct.

1

Reuse the front of the array as the output buffer

The non-zeros always land in slots 0, 1, 2, … — exactly the front of the array we are reading. Since the reader is always at or ahead of the write slot (fast ≥ slow), writing to nums[slow] never clobbers a value we still need to read.

O(n) extra space → O(1)

2

Swap instead of overwrite-then-zero-fill

Overwriting forces a second pass to fill the tail with zeros. Swapping sends the zero that was at nums[slow] back to nums[fast], so zeros accumulate at the tail automatically. One pass, no clean-up.

two passes → one pass

3

Skip the no-op swap when slow == fast

Until the first zero is seen, slow and fast move in lockstep and the swap is an element with itself. Guarding with if (slow != fast) turns those into pure increments — fewer memory writes on zero-light inputs.

writes ∝ non-zeros after first 0, not n

Step 3

The algorithm in plain English

1.Set slow = 0 — the index where the next non-zero element belongs.
2.Sweep fast from 0 to n − 1 over every element.
3.If nums[fast] is zero, skip it — leave slow where it is.
4.Otherwise swap nums[slow] and nums[fast], then advance slow by one.
5.Stop when the sweep ends: [0, slow) is the non-zeros in order, [slow, n) is all zeros.

Step 4

Code

void moveZeroes(vector<int>& nums) {
    int slow = 0;
    for (int fast = 0; fast < (int)nums.size(); fast++) {
        if (nums[fast] != 0) {
            if (slow != fast) {
                swap(nums[slow], nums[fast]);
            }
            slow++;
        }
    }
}

Step 7

Corner cases

1

Empty array

[] — the loop never runs, slow stays 0, nothing is written. Safe by construction.

2

All zeros

[0,0,0] — every element fails the != 0 test, slow never moves, the array is left untouched. Correct: it is already "all zeros at the end".

3

No zeros

[1,2,3] — every step has slow == fast, so the if (slow != fast) guard skips the swap and the array is unchanged with zero memory writes.

4

Leading zeros

[0,0,1] — the reader skips both zeros, then swaps 1 into slot 0. The two zeros it passed over slide to the tail via that single swap.

5

Single element

[0] or [7] — one iteration, at most one self-swap. Nothing to reorder; returns immediately.

Step 8

Production readiness

✓Stability: non-zeros are visited and placed left-to-right, so their relative order is provably preserved.
✓In-place: only two integer pointers are allocated — O(1) auxiliary space regardless of input size.
✓Empty / all-zero inputs: handled without special-casing; the loop body is a no-op when no non-zero is found.
✓Index type: compare fast against (int)nums.size() (or use size_t) to avoid signed/unsigned mismatch warnings.
✓Write minimisation: the slow != fast guard avoids redundant self-swaps on zero-free prefixes.
✓Generality: the predicate is the only problem-specific part — swap != 0 for any "keep these, push the rest back" rule.

Step 9

Approaches — trade-offs

Time O(n)Space O(1)

The optimal answer. One pass, in place, stable, with the fewest writes when the slow != fast guard is used. This is what to write in an interview.

int slow = 0;
for (int fast = 0; fast < (int)nums.size(); fast++) {
    if (nums[fast] != 0) {
        if (slow != fast) swap(nums[slow], nums[fast]);
        slow++;
    }
}
Time O(n)Space O(1)

Overwrite the front with non-zeros, then fill the remaining tail with zeros in a second pass. Same complexity, but it always writes every slot at least once and needs two passes — strictly more writes than the swap.

int w = 0;
for (int i = 0; i < (int)nums.size(); i++) {
    if (nums[i] != 0) nums[w++] = nums[i];
}
while (w < (int)nums.size()) nums[w++] = 0;
Time O(n)Space O(n)

The brute-force baseline: build a separate array of non-zeros padded with zeros, then copy it back. Easiest to reason about, but the extra array violates the in-place requirement and doubles the writes.

vector<int> out(nums.size(), 0);
int w = 0;
for (int x : nums) if (x != 0) out[w++] = x;
nums = out;
