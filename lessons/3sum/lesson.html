3Sum

LC #15 Medium Arrays · Two Pointers

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

Can the same element be used twice?

No — indices must be distinct (i ≠ j ≠ k).

→ L starts at i+1, never at i

Can there be duplicate values in the input?

Yes — e.g. [-1,-1,0,1,2]. Multiple copies of the same value are possible.

→ dedup logic required at both loops

Is the array sorted?

No — unsorted input.

→ must sort first; O(n log n) is acceptable

What do we return?

All unique triplets [a,b,c] such that a+b+c=0 — no duplicate triplets in output.

→ dedup is part of correctness, not optional

Assumptions we carry forward

Array may be empty or contain fewer than 3 elements — return empty. Integers may be negative, zero, or positive. Output order does not matter. No two triplets in the result may be identical even if different indices produce them.

The Insight

Fix one number. Find a pair that sums to its negation.

The problem asks for three numbers that sum to zero: a + b + c = 0. Rewrite it as b + c = −a. If we fix a, the problem becomes: find two numbers in the remaining array that sum to −a. That's the classic two-sum problem — and on a sorted array, two-sum runs in O(n) with two pointers.

The kernel

Sort the array. Fix one element with index i. Run two pointers (L=i+1, R=n−1) inward: if sum < 0, L++ to increase it; if sum > 0, R-- to decrease it; if sum == 0, record and squeeze both. Repeat for each i. The entire algorithm falls out of this one idea.

Step 1

Brute force: check every triple

Try all combinations of three indices i < j < k. Check if nums[i]+nums[j]+nums[k]==0. Three nested loops.

i=—  j=—  k=—  ·  checks: 0

Cost: O(n³) time

Three nested loops over n elements. Even with dedup, worst case is C(n,3) ≈ n³/6 checks.

vector<vector<int>> threeSum_BF(vector<int>& nums) {
    int n = nums.size();
    set<vector<int>> seen;  // dedup via set
    for (int i=0; i<n-2; i++) {
        for (int j=i+1; j<n-1; j++) {
            for (int k=j+1; k<n; k++) {
                if (nums[i]+nums[j]+nums[k] == 0) {
                    vector<int> t = {nums[i],nums[j],nums[k]};
                    sort(t.begin(), t.end());
                    seen.insert(t);
                }
            }
        }
    }
    return {seen.begin(), seen.end()};
}

Step 2

Two translations from O(n³) to O(n²)

The brute force tests every triple blindly. Two translations eliminate the innermost loop entirely.

1

Translation 1 — Fix one element, reduce to 2Sum

Lock index i. The problem becomes: find pairs (L, R) in the subarray nums[i+1..n-1] such that nums[L]+nums[R] = −nums[i]. The three-variable search collapses to a two-variable search. This eliminates one loop conceptually — but finding the pair still costs O(n) unless the subarray is sorted.

→ problem shape: O(n) outer × O(?) inner

2

Translation 2 — Sort first → two-pointer squeeze finds pairs in O(n)

Sort the array once: O(n log n). Now the subarray nums[i+1..n-1] is sorted. On a sorted array, the two-pointer technique finds all pairs summing to a target in O(n): start L and R at both ends, advance L if sum is too small, retreat R if too large. Sorting is the key that makes the inner search O(n) instead of O(n²).

sum < 0 → L++ // left side too small, move right to increase sum
sum > 0 → R-- // right side too large, move left to decrease sum
sum = 0 → record, skip duplicates, squeeze both

→ O(n log n) sort + O(n) outer × O(n) inner = O(n²) total

Why dedup is built into the pointer movement

After recording a triplet, advance L past any equal values (while nums[L]==nums[L+1]: L++) and retreat R past equal values. This guarantees the next pair tried is different. At the outer loop, skip nums[i]==nums[i-1] to avoid repeating the same fixed element. No set or hash map needed — dedup is free.

Step 3

The algorithm in plain English

Say this before writing any code.

1.Sort the array. This is what makes the inner search O(n).
2.For each index i from 0 to n−3: if nums[i]==nums[i-1], skip (duplicate outer). Set L=i+1, R=n−1.
3.While L < R: compute sum = nums[i]+nums[L]+nums[R].
4.If sum < 0: L++ (need a larger value). If sum > 0: R-- (need a smaller value). If sum == 0: record triplet, skip duplicate neighbors on both sides, then L++ and R--.
5.Return the collected triplets. No set needed — dedup is handled inline.

Step 4

Canonical C++ solution

Try writing from the five steps above before revealing.

vector<vector<int>> threeSum(vector<int>& nums) {
    sort(nums.begin(), nums.end());            // Translation 2: sort first
    vector<vector<int>> result;
    int n = nums.size();

    for (int i = 0; i < n - 2; i++) {
        if (i > 0 && nums[i] == nums[i-1]) { continue; }  // skip dup outer

        int L = i + 1, R = n - 1;
        while (L < R) {
            int sum = nums[i] + nums[L] + nums[R];
            if (sum < 0) {
                L++;                                      // need larger
            } else if (sum > 0) {
                R--;                                      // need smaller
            } else {
                result.push_back({nums[i], nums[L], nums[R]});
                while (L < R && nums[L] == nums[L+1]) { L++; }  // skip dup L
                while (L < R && nums[R] == nums[R-1]) { R--; }  // skip dup R
                L++; R--;
            }
        }
    }
    return result;
}

Step 7

Corner cases

1

Fewer than 3 elements

Outer loop runs i < n−2. If n < 3, the loop never starts. Returns empty vector correctly.

2

All zeros — [0,0,0,0]

i=0: L=1, R=3, sum=0 → record [0,0,0]. Dedup skips same neighbors. i=1: nums[1]==nums[0] → skip. Only one triplet returned.

3

All positive or all negative — [1,2,3,4]

After sorting, the smallest element is positive. No three elements can sum to 0. The inner while loop immediately fails the sum check and the loop exhausts. Returns empty.

4

Duplicates in input — [-1,-1,-1,0,1,1]

After sort: [-1,-1,-1,0,1,1]. i=0 fix=-1, finds [-1,0,1]. i=1: nums[1]==nums[0] → skip. i=2: nums[2]==nums[1] → skip. Only one [-1,0,1] triplet despite three copies of -1.

5

Exactly one valid triplet — [−1, 0, 1, 2]

i=0 fix=-1: L=1(0), R=3(2) → sum=1 > 0 → R--. L=1(0), R=2(1) → sum=0 → record [-1,0,1]. L=2, R=1 → loop ends. i=1 fix=0: no pair sums to 0. Returns [[-1,0,1]].

Step 8

Production readiness

✓

n < 3: outer loop condition i < n-2 handles this — loop never runs.

✓

Duplicate outer: i > 0 && nums[i]==nums[i-1] — the i > 0 guard prevents out-of-bounds on the first iteration.

✓

Duplicate inner after match: skip L/R neighbors before the final L++/R-- — never skip before recording the triplet.

✓

Integer overflow: three integers summed — worst case 3×10⁴ for typical constraints. int is safe.

✓

Early termination: if nums[i] > 0, break — all subsequent fixed elements are also positive, sum can never be zero. Optional but speeds up in practice.

Step 9

Approaches

Time O(n²)Space O(1)

Sort once, then for each fixed i run two pointers inward. Dedup is free — handled by skipping equal neighbors. No extra data structures beyond the output.

Time O(n²)Space O(n)

Sort first. For each fixed i, iterate j from i+1 to n-1. Use a hash set to check if −nums[i]−nums[j] exists in the remaining elements. Same asymptotic time but requires O(n) extra space and more careful dedup logic. Two-pointer is cleaner.

Time O(n³)Space O(n)

Three nested loops, collect matches in a set to deduplicate. Correct but TLE for n > 500. The starting point for explaining the two translations above.

Step 10

Complexity

Time

O(n²)

Sort: O(n log n). Outer loop: O(n). Inner two-pointer: O(n) per iteration. Dominant term: O(n²).

Space

O(1)

No extra data structures beyond the output vector. Sort is in-place. Four integer variables: i, L, R, sum.

Take home

What to remember for similar problems

The fix-one, search-two pattern reduces kSum to (k−1)Sum. 3Sum → 2Sum. 4Sum → 3Sum → 2Sum. At the base level, two-pointer on a sorted array finds all pairs in O(n).

Sorting is not just a convenience — it's what enables the two-pointer to work. On an unsorted array you need a hash set (O(n) space). On a sorted array you get O(1) space for free.

The dedup logic is the hardest part to get right under pressure. The rule is: skip duplicates after processing, never before. Skipping before means you might miss valid triplets.
