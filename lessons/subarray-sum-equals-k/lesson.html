Subarray Sum Equals K

LC #560 Medium Arrays · Hash Map · Prefix Sum

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

What is a 'contiguous subarray'?

A contiguous subarray is defined by a start and end index. All elements between (inclusive) must be included.

→ track positions; compute sums over ranges

If no subarray sums to K, what do I return?

Return 0 — no such subarray exists.

→ answer is always ≥ 0; count subarrays

Can K be negative, or elements be negative?

Yes — K can be any integer, and elements can be negative.

→ prefix-sum approach handles negative numbers naturally

Do I need to return indices, or just the count?

Just the count of subarrays. Return type is an integer.

→ count occurrences; use a frequency map

Assumptions we carry forward

Input is an array of integers (positive, negative, or zero). K is an integer (positive, negative, or zero). We want the count of contiguous subarrays that sum to K. Output is a single integer: the count.

The Insight

Trade 'check every subarray' for 'prefix sums and their complements'.

The naive approach checks every subarray and sums it — O(n²) subarrays times O(n) summing each = O(n³), or O(n²) with a running sum. The key insight: if the cumulative sum up to index j is S_j and the cumulative sum up to index i is S_i (where i < j), then the subarray [i+1, j] sums to S_j − S_i. So if we want a subarray summing to K, we ask: "for the current cumulative sum S, how many times have I seen the value (S − K) before?" Each prior occurrence marks the start of a subarray that ends here with sum K.

The kernel

Walk i from 0 to n−1. Keep a hash map prefix_count from cumulative sum to frequency. Initialize it with {0: 1}. At each i, add nums[i] to prefix_sum. Check if (prefix_sum - K) exists in the map; if yes, add its count to the result. Then increment the map entry for the current prefix_sum. The initial entry {0: 1} handles subarrays starting at index 0.

Step 1

Brute force: check every subarray

For each start index i, try every end index j ≥ i; compute the sum of the subarray, and if it equals K, increment a counter. About n²/2 subarrays to check. Each sum is O(n), so total is O(n³), or O(n²) with a running sum.

i=—  j=—  ·  sum: 0  count: 0

Cost: O(n²) time, O(1) space

Two nested loops over n elements. In the worst case (answer at the very end), we check all n(n+1)/2 ≈ n²/2 subarrays. With a running sum, we avoid recalculating, giving O(n²) total. For LC's 10⁴ limit that is up to 5×10⁷ operations — borderline TLE.

int subarraySum_BF(vector<int>& nums, int k) {
    int n = nums.size();
    int count = 0;
    for (int i = 0; i < n; i++) {
        int sum = 0;
        for (int j = i; j < n; j++) {
            sum += nums[j];
            if (sum == k) {
                count++;
            }
        }
    }
    return count;
}

Step 2

Two translations from O(n²) to O(n)

The brute force checks "does this subarray sum to K?" once per subarray. Two translations turn that into one lookup per element.

1

Translation 1 — Subarray sums → prefix sum complements

Instead of summing each subarray [i, j] individually, note that every subarray sum is the difference of two prefix sums: nums[i..j] = prefix[j] - prefix[i-1]. So if we want a subarray summing to K, we ask: "for the current prefix sum, how many times have I seen (current_sum - K) before?" Each occurrence tells us about a different subarray ending at this position that sums to K.

→ the problem is now "count prefix-sum complements", not "check each subarray"

2

Translation 2 — Track frequency of prefix sums, in one pass

For each prefix sum value, maintain its frequency (how many times it's appeared). At each position, compute the current prefix sum and ask: "how many times have I seen (current_sum - K)?" Add that count to the result. Then increment the frequency of the current sum. One pass; each step is O(1) average. Initialize with {0: 1} because an empty prefix has sum 0.

prefix_sum += nums[i]
complement = prefix_sum - k
if complement in prefix_count → count += prefix_count[complement]
prefix_count[prefix_sum]++  // record this sum

→ O(n²) pair-check becomes O(n) hash-map lookup

Why initialise prefix_count[0] = 1?

The empty prefix (before any elements) has sum 0. If a subarray from index 0 to j sums to K, then prefix[j] - prefix[-1] = K, i.e., prefix[j] = K. When we compute (prefix[j] - K), we'd look for value 0 (the empty prefix). By pre-storing {0: 1}, we automatically count subarrays starting at index 0 without special-casing.

Step 3

The algorithm in plain English

1.Initialise a hash map prefix_count with entry {0: 1}.
2.Set count = 0 and prefix_sum = 0.
3.Walk i from 0 to n−1.
4.Update prefix_sum by adding nums[i].
5.Compute complement = prefix_sum - K.
6.If complement is in prefix_count, add prefix_count[complement] to count.
7.Increment prefix_count[prefix_sum] by 1.
8.Return count after the loop completes.

Step 4

Code

int subarraySum(vector<int>& nums, int k) {
    unordered_map<int, int> prefix_count;  // prefix_sum → frequency
    prefix_count[0] = 1;                          // empty prefix
    int count = 0;
    int prefix_sum = 0;
    for (int i = 0; i < nums.size(); i++) {
        prefix_sum += nums[i];
        int complement = prefix_sum - k;
        if (prefix_count.count(complement)) {
            count += prefix_count[complement];    // add frequency
        }
        prefix_count[prefix_sum]++;               // record this prefix
    }
    return count;
}

Step 7

Corner cases

1

All elements are 0, K = 0 — [0, 0, 0]

Prefix sums are all 0. At i=0, prefix=0, complement=0, found 1 (the initial entry). At i=1, prefix=0, complement=0, found 2 (initial + i=0). At i=2, found 3. Total: 1+2+3 = 6 = n(n+1)/2. Correct.

2

All elements are K — [5, 5, 5], K = 5

Prefix sums are 0, 5, 10, 15. At i=0, prefix=5, complement=0, found 1. At i=1, prefix=10, complement=5, found 1. At i=2, prefix=15, complement=10, found 1. Total: 3 (subarrays [0], [1], [2] alone). Correct.

3

No subarray sums to K — [1, 2, 3], K = 100

Prefix sums are 0, 1, 3, 6. Complements are 100, 99, 97, 94 — none match. Count stays 0. Correct.

4

Negative elements — [1, -1, 1, 1], K = 1

Prefix sums are 0, 1, 0, 1, 2. At i=0, prefix=1, complement=0, found 1. At i=1, prefix=0, complement=−1, not found. At i=2, prefix=1, complement=0, found 2. At i=3, prefix=2, complement=1, found 2. Total: 1+2+2=5. Subarrays: [0..0]=[1], [0..2]=[1,−1,1], [1..3]=[−1,1,1], [2..2]=[1], [3..3]=[1]. Correct.

5

Single element equals K — [5], K = 5

At i=0, prefix=5, complement=0, found 1 (the initial entry). Count=1. Correct.

6

Duplicate prefix sums — [1, 1, -1, 1], K = 2

Prefix sums are 0, 1, 2, 1, 2. At i=1, prefix=2, complement=0, found 1. At i=2, prefix=1, complement=-1, not found. At i=3, prefix=2, complement=0, found 1. Total: 1+1=2. The map correctly tracks frequency: {0:1, 1:2, 2:2} at the end. Each occurrence of value 2 represents a different subarray summing to K. Correct.

Step 8

Production readiness

✓

Initialise prefix_count[0] = 1: the empty prefix (sum 0) represents subarrays starting at index 0. Do not omit.

✓

Count, not just check: use a frequency map. When (prefix_sum - K) is found, add its frequency to the result, not just 1.

✓

Use count() or find(), not operator[]: prefix_count[complement] would insert a default-zero entry on a miss, corrupting the map. Use if (prefix_count.count(complement)) to check safely.

✓

Order of operations: probe before increment: compute the complement, check the map (which contains only indices < i), then increment. This ensures we don't count an element with itself.

✓

K and prefix_sum must be signed: both can be negative. Use int or long long depending on input bounds.

Step 9

Approaches

Time O(n)Space O(n)

The solution taught above. Walk once, maintain a prefix-sum frequency map. Optimal time complexity. You must read every element at least once, and each step involves O(1) average lookups.

Time O(n²)Space O(1)

Nested loops over all subarrays; compute each sum. Correct and simple, but slow. Passes LC's 10⁴ limit with tight constants, but a clear signal of not reaching for the optimal O(n) technique.

Step 10

Complexity

Time

O(n)

One pass; each step does an O(1) average hash probe and an O(1) increment. Worst case is O(n) per step under adversarial hashing, but amortised guarantees on unordered_map give O(n) total in practice.

Space

O(n)

The map stores at most n unique prefix sums. In practice, many prefixes may repeat (especially with large arrays and random values), so the map size is often much smaller. No recursion, no stack concerns.

Take home

What to remember for similar problems

The pattern: scan once with a running prefix value, count how many times the complement (value - target) has been seen, and maintain a frequency map. This technique applies to any problem asking for the count of subarrays with a cumulative property tied to prefix value.

Key difference from Contiguous Array: instead of checking "balance returns to previous value", we ask "how many times has the complement appeared?" The frequency map is essential.

Related problems:

LC 525 — Contiguous Array — same prefix-sum technique, but checking for balance (equal 0s and 1s) instead of a target sum. Only tracks first occurrence, not frequency.

LC 523 — Continuous Subarray Sum — asks if there exists a subarray whose sum is divisible by K. Use (sum % K) as the prefix key; same structure, different modulo condition.

LC 974 — Subarray Sums Divisible by K — asks for the count of subarrays whose sum is divisible by K. Use (sum % K) as the prefix key; otherwise identical to this problem.

LC 1099 — Two Sum Less Than K — asks for the maximum sum *less than* K. Hash map breaks (range query); optimal is sort + two-pointer.
