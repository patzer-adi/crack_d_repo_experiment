As Far from Land as Possible

LC #1162 Medium Graphs — BFS / DFS

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

How is distance measured — diagonal or orthogonal?
One step per orthogonal move (up/down/left/right). It is the grid (Manhattan) shortest path, not Euclidean.
→ a 4-direction neighbour helper, distance +1 per hop
Do we return the water cell, or just the distance?
Only the distance — the single largest "distance to nearest land" over all water cells.
→ track one running max; no coordinates need remembering
What if the grid is all land, or all water?
Return -1. With no water there is no cell to measure; with no land there is nothing to measure to.
→ guard for an empty or a completely full queue first
Search outward from each water cell, or flood from all land?
Flood out from every land cell at once. The first wave to reach a water cell carries its answer; the last cell reached is the most isolated.
→ multi-source BFS seeded with every 1

The Insight

Don't search from each water cell — flood inward from all land, and the last cell reached is the answer

You probably stood on each water cell and searched outward for the nearest land — re-walking the grid once per cell. Flip it: drop every land cell into one queue and let the flood spread in synchronized rings. The most isolated water is simply whatever the flood reaches last — and the wave it arrives on is its distance to land.

land — source, distance 0 water, not reached yet flooded — distance to land farthest (the answer)
Read the animation as expanding rings:

Seed every source at once
Distance 0 — every land cell goes into one shared queue. They are all equal starting points; none waits its turn.
k
One ring per distance
On wave k, the whole current frontier reaches its not-yet-flooded orthogonal neighbours. Those water cells are exactly distance k from their nearest land — stamp them and they become the next ring.
∎
The last ring is the answer
The flood fills closer water first. Whatever it reaches on the final wave is the most isolated — and that wave number is the largest distance-to-land. No need to inspect every cell; the deepest wave is the answer.

The kernel

Seed a BFS queue with every land cell at distance 0 (multi-source). Pop cells in FIFO order; for each unvisited water neighbour, set its distance to the current cell's distance + 1 and enqueue it. Because all land starts together and BFS expands one ring at a time, the first wave to reach a water cell is its distance to the nearest land. The deepest wave — the last water cell filled — is the answer. One linear pass.

Step 1

Brute force — feel the cost

The naive idea takes the question literally: stand on each water cell and BFS outward until you hit land, remembering the largest such distance. Correct, but each of the up-to-n² water cells re-explores a large slice of the grid — so the whole thing is O((n²)²). Watch the cell-scan counter climb as adjacent water cells repeat almost the same search their neighbour just did.

water resolved: 0 cell-scans: 0 farthest so far: 0

Cost: O((n²)²) time, O(n²) space

Every water cell runs its own independent search, re-walking cells its neighbours already walked. The cell-scan counter is the point — adjacent water cells repeat nearly identical work instead of sharing it.

int maxDistance(vector<vector<int>>& grid) {
    int n = grid.size(), ans = -1;
    int dr[] = {1,-1,0,0}, dc[] = {0,0,1,-1};
    for (int sr = 0; sr < n; sr++) {
        for (int sc = 0; sc < n; sc++) {
            if (grid[sr][sc] == 1) { continue; }   // only water cells
            // BFS outward from this water cell until the nearest land
            vector<vector<bool>> seen(n, vector<bool>(n, false));
            queue<array<int,3>> q;
            q.push({sr, sc, 0}); seen[sr][sc] = true;
            while (!q.empty()) {
                auto [r, c, d] = q.front(); q.pop();
                if (grid[r][c] == 1) { ans = max(ans, d); break; }
                for (int k = 0; k < 4; k++) {
                    int nr = r+dr[k], nc = c+dc[k];
                    if (nr<0||nr>=n||nc<0||nc>=n||seen[nr][nc]) { continue; }
                    seen[nr][nc] = true; q.push({nr, nc, d+1});
                }
            }
        }
    }
    return ans;
}

Step 2

Translations — every optimisation, named

Three swaps turn the per-cell re-search into a single linear flood.

1
Search from each water cell → flood from all land
Invert the direction. Instead of "where is the nearest land to me", ask "how far has the land reached". Seed one queue with every land cell (multi-source BFS).
drops the "which water cell" outer factor
2
Re-walking settled cells → visit each cell once
A dist matrix starts at -1; the moment a water cell is stamped it is never revisited. Settled regions are never re-explored.
O((n²)²) → O(n²)
3
"Max over per-cell searches" → the deepest wave
BFS expands one ring per step, so the last water cell reached is the most isolated. Keep one running ans = max(ans, dist) as you stamp — no separate pass over the grid.
answer falls out of the same flood, O(1) per cell

Step 3

The algorithm in plain English

1
Initialise. Make a dist matrix: 0 for every land cell, -1 for every water cell. -1 means "not reached".
2
Seed all sources. Enqueue every land cell. They are the entire distance-0 frontier.
3
Guard the degenerate grids. If the queue is empty (no land) or holds every cell (no water), return -1 — there is no answer.
4
Flood, tracking the max. While the queue is non-empty, pop a cell and look at its four orthogonal neighbours. For each one still at -1, set its distance to dist[cur] + 1, update ans = max(ans, dist), and enqueue it. Skip already-stamped neighbours.
5
Return. When the queue drains, ans is the largest distance any water cell reached. Return it.

Step 4

Code

int maxDistance(vector<vector<int>>& grid) {
    int n = grid.size();
    vector<vector<int>> dist(n, vector<int>(n, -1));
    queue<pair<int,int>> q;
    for (int r = 0; r < n; r++) {
        for (int c = 0; c < n; c++) {
            if (grid[r][c] == 1) { dist[r][c] = 0; q.push({r, c}); }
        }
    }
    if (q.empty() || (int)q.size() == n*n) { return -1; }   // all water or all land
    int dr[] = {1, -1, 0, 0}, dc[] = {0, 0, 1, -1}, ans = 0;
    while (!q.empty()) {
        auto [r, c] = q.front(); q.pop();
        for (int d = 0; d < 4; d++) {
            int nr = r + dr[d], nc = c + dc[d];
            if (nr < 0 || nr >= n || nc < 0 || nc >= n) { continue; }
            if (dist[nr][nc] != -1) { continue; }    // already reached by closer land
            dist[nr][nc] = dist[r][c] + 1;            // first touch = nearest
            ans = max(ans, dist[nr][nc]);             // deepest wave so far
            q.push({nr, nc});
        }
    }
    return ans;
}

Step 7

Corner cases

1
All water
[[0,0],[0,0]]: no land at all, so the queue is empty and no water cell can ever reach land. Return -1 — there is nothing to measure to.
2
All land
[[1,1],[1,1]]: every cell is a source and the queue holds all n² of them, but there is no water cell to be far from land. Return -1.
3
A single land cell in a sea of water
One source feeds the entire grid. Distances grow as the Manhattan distance to that cell — the farthest corner is the deepest wave and the answer. Still one linear pass.
4
Two land cells reaching the same water
A middle water cell may sit between two land cells. Whichever wave arrives first stamps it; the dist != -1 guard makes the later wave skip it, so it keeps the smaller distance — exactly the nearest land.
5
Don't seed only one land cell
Seeding a single land cell and re-running per source loses the "all rings advance together" guarantee and overcounts distances. Every land cell must be in the queue at distance 0 before the first pop.

Step 8

Production readiness

✓
Handle the all-land / all-water grids up front — both return -1. An empty queue or a queue holding every cell are the two tells.
✓
Bounds-check all four neighbours before indexing — an out-of-range read is undefined behaviour in C++.
✓
Use -1 as the visited marker in dist itself — no separate visited matrix needed.
✓
Seed every land cell before the first pop so all sources expand at the same rate. This is what makes "first touch = nearest" true.
✓
Track the max as you stamp. The last water cell flooded carries the answer — no second sweep over the grid is needed.
✓
Each cell is enqueued exactly once, so the queue and time are both O(n²) — distances are bounded by n², so plain int never overflows.

Step 9

Approaches — trade-offs

O(n²)O(n²)

Seed the queue with every land cell and flood ring by ring. Each cell is enqueued once; the last water cell reached carries the answer. This is the intended solution — simple, linear, and the queue's level structure maps exactly onto distance.

O(n²)O(1) extra

No queue at all: two sweeps over dist. First top-left → bottom-right, taking the min of the up and left neighbour + 1; then bottom-right → top-left, taking the min of the down and right neighbour + 1. The two passes together compute every water cell's distance to the nearest land; take the maximum at the end. Same time, O(1) auxiliary space.

// dist[r][c] = 0 if land else BIG
// pass 1 (r,c increasing): min(self, up+1, left+1)
// pass 2 (r,c decreasing): min(self, down+1, right+1)
// answer = max over all cells (or -1 if all land / all water)
O((n²)²)O(n²)

The brute force from Step 1: BFS outward from each water cell until the nearest land, keeping the largest distance. Correct and literal, but adjacent water cells repeat almost identical searches, so it is quartic in n. Useful only to motivate flipping the search direction.

Step 10

Complexity

Time
O(n²)
Each of the n² cells is enqueued at most once and its four neighbours inspected a constant number of times.
Space
O(n²)
The BFS queue can hold up to every cell in the worst case (e.g. a grid that is almost all land at the start).
