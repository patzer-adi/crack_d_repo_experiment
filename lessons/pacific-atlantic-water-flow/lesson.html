Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

Can water flow diagonally?
No — only to up / down / left / right neighbours.
→ unlocks: a 4-direction neighbour step, not 8
Does water flow between equal heights?
Yes — water flows to any neighbour of height ≤ the current cell, so equal cells connect both ways.
→ unlocks: the reverse-flood test is >=, not strict >
What touches each ocean?
Pacific = top row + left column. Atlantic = bottom row + right column. Corners touch both.
→ unlocks: the two seed sets for the two floods
Output order or duplicates?
Any order, each cell once. We emit them row-major.
→ unlocks: one final grid scan collecting cells in both sets

Assumptions we carry forward

4-directional movement; a drop flows to neighbours of height ≤ its own; the Pacific is the top/left border and the Atlantic the bottom/right border; output is every cell that can reach both, in any order.

The Insight

Don't trace every drop downhill — flood uphill from each shore, then keep the overlap

The naive question — "where does this cell's water end up?" — forces a separate flood from every cell, which is expensive. Flip it around. Stand on an ocean's shore and walk inland and uphill: from a cell, step to any neighbour that is as tall or taller, because that taller neighbour can send its water back down to you. Every cell you can reach this way is exactly a cell whose water can drain to that ocean. Do this once for the Pacific shore and once for the Atlantic shore; the cells reached by both floods are the answer.

The kernel

Reverse the flow. From each ocean's border cells, BFS/DFS inland visiting any neighbour whose height is ≥ the current cell's height. The set this reaches is "all cells that drain to that ocean." Run it twice — once seeded from the Pacific border, once from the Atlantic — and intersect the two visited sets. Two linear floods replace a flood-per-cell: O(m·n) instead of O((m·n)²).

Step 1

Brute force — feel the cost

The literal reading: for each cell, flood downhill (to neighbours of height ≤ current) and see whether the flood ever touches the Pacific border and the Atlantic border. Correct — but it runs a fresh flood from every one of the m·n cells, so the total work is O((m·n)²). Watch the flood counter climb.

Cost: O((m·n)²) time, O(m·n) space

Each cell triggers its own flood that can visit the whole grid. On a 200×200 grid that is 40 000 floods of up to 40 000 cells each. The reverse-flood insight does the same job in two floods total.

bool drains(vector<vector<int>>& h, int sr, int sc) {
    int m = h.size(), n = h[0].size();
    vector<vector<bool>> seen(m, vector<bool>(n));
    vector<pair<int,int>> st = {{sr, sc}};
    seen[sr][sc] = true;
    bool pac = false, atl = false;
    while (!st.empty()) {
        auto [r, c] = st.back(); st.pop_back();
        if (r == 0 || c == 0)       { pac = true; }
        if (r == m-1 || c == n-1)   { atl = true; }
        int dirs[4][2] = {{1,0},{-1,0},{0,1},{0,-1}};
        for (auto& d : dirs) {
            int nr = r + d[0], nc = c + d[1];
            if (nr<0||nr>=m||nc<0||nc>=n) { continue; }
            if (seen[nr][nc])              { continue; }
            if (h[nr][nc] > h[r][c])       { continue; }
            seen[nr][nc] = true; st.push_back({nr, nc});
        }
    }
    return pac && atl;
}
// caller: for every (r,c), push {r,c} if drains(h,r,c) — O((mn)^2)

Step 2

Translations — every optimisation, named

One idea carries the whole optimisation: stop asking the question per cell and ask it per ocean. Here is the chain that gets us from O((mn)²) to O(mn).

1
Per-cell forward flood → per-ocean reverse flood
A cell drains to an ocean iff that ocean's shore can climb up to it. So flood once from each shore instead of once from each cell — e.g. from the Pacific border, visiting neighbours of height ≥ current.
→ mn floods → 2 floods
2
"Reaches ocean X" → membership in set X
Replace the per-cell boolean search with a single visited set per ocean, filled by the flood. Checking "does this cell reach the Pacific?" becomes a set lookup.
→ O(mn) search per cell → O(1) lookup
3
Two sets → one intersection scan
Keep two visited grids, pac and atl. The answer is every cell with pac[r][c] && atl[r][c], found in one final pass over the grid.
→ O(mn) total to collect the answer

Step 3

The algorithm in plain English

1Seed a Pacific queue with every cell on the top row and left column; seed an Atlantic queue with every cell on the bottom row and right column. Mark each seed visited in its grid.
2Flood each queue: pop a cell, and for each 4-direction neighbour that is unvisited and has height ≥ the popped cell, mark it visited and enqueue it.
3Run the flood for the Pacific queue, then for the Atlantic queue, filling the two visited grids independently.
4Scan every cell once; whenever it is visited in both grids, append {r, c} to the result.
5Return the collected coordinates.

Step 4

Code

vector<vector<int>> pacificAtlantic(vector<vector<int>>& h) {
    int m = h.size(), n = h[0].size();
    vector<vector<bool>> pac(m, vector<bool>(n)), atl(m, vector<bool>(n));
    queue<pair<int,int>> qp, qa;
    for (int c = 0; c < n; c++) {
        pac[0][c] = atl[m-1][c] = true;
        qp.push({0, c}); qa.push({m-1, c});
    }
    for (int r = 0; r < m; r++) {
        pac[r][0] = atl[r][n-1] = true;
        qp.push({r, 0}); qa.push({r, n-1});
    }
    flood(h, pac, qp);
    flood(h, atl, qa);
    vector<vector<int>> res;
    for (int r = 0; r < m; r++) {
        for (int c = 0; c < n; c++) {
            if (pac[r][c] && atl[r][c]) { res.push_back({r, c}); }
        }
    }
    return res;
}

void flood(vector<vector<int>>& h, vector<vector<bool>>& seen,
           queue<pair<int,int>>& q) {
    int m = h.size(), n = h[0].size();
    int dirs[4][2] = {{1,0},{-1,0},{0,1},{0,-1}};
    while (!q.empty()) {
        auto [r, c] = q.front(); q.pop();
        for (auto& d : dirs) {
            int nr = r + d[0], nc = c + d[1];
            if (nr<0||nr>=m||nc<0||nc>=n) { continue; }
            if (seen[nr][nc])              { continue; }
            if (h[nr][nc] < h[r][c])       { continue; }
            seen[nr][nc] = true; q.push({nr, nc});
        }
    }
}

Step 7

Corner cases

1
Single row or single column — [[1,2,3]]
The one row is the top and the bottom, so every cell touches both oceans; all cells are in the answer. The seed loops already cover this — no special case needed.
2
1×1 grid — [[5]]
The single cell touches all four borders, so it is seeded into both queues; the answer is [[0,0]].
3
A low "sink" corner — (0,0)=1 in [[1,2,2],[3,2,3],[2,4,1]]
Being on a shore is not enough to reach the other ocean. The top-left cell touches the Pacific but every neighbour is taller, so the Atlantic flood never climbs into it — it is excluded. Same for the bottom-right sink.
4
All-equal plateau — [[7,7],[7,7]]
Because the flood uses ≥, equal neighbours connect freely; both floods reach every cell, so all of them are in the answer. A strict > would wrongly drop them.

Step 8

Production readiness

✓Empty grid — guard h.empty() || h[0].empty() and return an empty result before touching h[0].size().
✓Equal heights — the comparison is >= (reverse) / <= (forward), never strict, or plateaus break.
✓Visited before enqueue — mark a cell visited when you push it, not when you pop it, so it is never queued twice.
✓Bounds first — check nr/nc in range before indexing the grid or the visited array.
✓Corners seeded once — a corner sits on two borders; the set/visited check keeps it from being processed twice.
✓Recursion depth — a DFS version can recurse O(m·n) deep on a monotone grid; prefer the iterative BFS/stack shown here for large inputs.

Step 9

Approaches — trade-offs

O(m·n) O(m·n)

Two queue-based floods, one per ocean, then an intersection scan. Iterative, so no stack-overflow risk on large monotone grids. This is the code in Step 4.

// Same code as Step 4: seed both border queues, flood each with

O(m·n) O(m·n)

Same reverse-flood logic, but recursion instead of a queue: from every border cell call dfs(pac, r, c). Cleaner to write, but the call stack can reach O(m·n) depth on an all-increasing grid.

void dfs(vector<vector<int>>& h, vector<vector<bool>>& seen, int r, int c) {
    int m = h.size(), n = h[0].size();
    seen[r][c] = true;
    int dirs[4][2] = {{1,0},{-1,0},{0,1},{0,-1}};
    for (auto& d : dirs) {
        int nr = r + d[0], nc = c + d[1];
        if (nr<0||nr>=m||nc<0||nc>=n) { continue; }
        if (seen[nr][nc] || h[nr][nc] < h[r][c]) { continue; }
        dfs(h, seen, nr, nc);
    }
}
O((m·n)²) O(m·n)

Flood downhill from every cell and test which borders it touches. Easy to reason about and fine for tiny grids, but quadratic in the cell count — the version animated in Step 1.

Step 10

Complexity

Time
O(m·n)
Each cell is enqueued at most once per ocean, so each flood is O(m·n); the final scan is O(m·n) too.
Space
O(m·n)
Two visited grids plus the BFS queues, each bounded by the number of cells.
