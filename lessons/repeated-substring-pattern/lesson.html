Repeated Substring Pattern

LC #459 Easy String

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

Q1. Does "one copy" count? Can the substring equal s itself?

A. No — the problem requires multiple copies. The pattern length d must be strictly less than n, and at least two copies must tile s.

→ unlocks: candidate period d is bounded to 1 ≤ d ≤ n/2.

Q2. What are the input constraints?

A. 1 ≤ n ≤ 10⁴, lowercase English letters only.

→ unlocks: O(n·√n) is fine (~10⁶ ops worst case). No need for KMP unless you want to flex.

Q3. What about n = 1?

A. Returns false. A single character is not "multiple copies" of anything.

→ unlocks: the loop body never runs when n/2 == 0; default-false fall-through handles it.

Q4. Could the answer be true for a d that does not divide n?

A. Never. If k copies of length d tile s, then n = k·d, so d must divide n.

→ unlocks: only check the divisors of n — prunes the candidate set from n/2 down to ~√n.

The Insight

If s tiles, the tile length must divide s's length

"Built from multiple copies of a substring t" means s is literally k copies of t glued together, with k ≥ 2. So |s| = k · |t|, which forces |t| to be a divisor of |s|. Nothing else can tile s exactly.

Picture it. For s = "abcabcabcabc" (n = 12), the substring "abc" of length 3 tiles s into 4 copies. The substring "abcab" of length 5 cannot — 5 ∤ 12 leaves a partial tile at the end.

The kernel

s of length n is tiled by some pattern of length d (with k ≥ 2 copies) iff there exists d with 1 ≤ d ≤ n/2, d divides n, and s[i] == s[i − d] for every i in [d, n). Two facts do the work: (1) only divisors of n can be tile lengths; (2) "s is d-periodic" is exactly the condition that every character at offset i equals the character d slots earlier. No string slicing, no concatenation.

Step 1

Brute force — try every length, rebuild and compare

The most literal reading: for each candidate length d from 1 to n/2, build the string s[0:d] repeated n/d times (when d divides n) and check if it equals s.

built: —
candidate d: —   ·   char comparisons so far: 0
—

Cost: O(n²) time

For each of the ≤ n/2 candidate lengths, we build a fresh n-character string and compare. Worst case ≈ n²/2 character operations, plus allocation churn. We also can't tell a candidate is bogus until after we've built the full string.

bool repeatedSubstringPattern_BF(string s) {
    int n = s.size();
    for (int d = 1; d <= n / 2; d++) {
        if (n % d != 0) { continue; }  // lengths won't match — can't tile
        string built = "";
        for (int k = 0; k < n / d; k++) {
            built += s.substr(0, d);            // rebuild full n-char string
        }
        if (built == s) { return true; }
    }
    return false;
}

Step 2

Two translations from idea to O(n·√n)

Two independent optimisations sit between the brute force above and the optimal version. Read both before reading the code — they are easy to merge in your head and then hard to debug separately.

1

Translation 1 — Build-and-compare → in-place periodicity check

Naively, for each candidate d we build s[0:d] * (n/d) and string-compare to s. That allocates a fresh n-char string per try, and only tells us "match / no match" at the end. Instead, observe that "s equals s[0:d] repeated" iff s[i] == s[i − d] for every i ≥ d. No new string — just n − d single-character comparisons with an early exit on the first mismatch.

s = "abcabc", d = 3
i=3: s[3]='a' vs s[0]='a' ✓
i=4: s[4]='b' vs s[1]='b' ✓
i=5: s[5]='c' vs s[2]='c' ✓   → d=3 works, no string built

→ O(n) memory per candidate → O(1) memory; early-exit on first mismatch

2

Translation 2 — All lengths → divisors of n only

A blind search tries every d from 1 to n/2 — that's n/2 candidates, each costing up to n work, so O(n²). But if k copies of length d tile s, then k·d = n, so d must divide n. We skip every d with n % d != 0 in O(1) — for n = 12, that prunes d = 5, 7, 8, 9, 10, 11 instantly. The number of divisors of n is on average O(√n).

n = 12. Candidates 1..6.
d=1: 12 % 1 = 0 → check
d=2: 12 % 2 = 0 → check
d=3: 12 % 3 = 0 → check
d=4: 12 % 4 = 0 → check
d=5: 12 % 5 = 2 → skip (cheap)
d=6: 12 % 6 = 0 → check

→ O(n²) trials → O(n · d(n)) ≈ O(n·√n) where d(n) is the divisor count of n

Step 3

The algorithm in plain English

1.Let n = len(s). If n < 2, return false — single chars can't be "multiple copies."
2.For each d from 1 to n/2 (inclusive):
3.   If n % d != 0, skip — d cannot tile s.
4.   Otherwise scan i = d, d+1, …, n−1. If any s[i] != s[i − d], abandon this d.
5.   If the inner scan finished cleanly, return true — s is n/d copies of s[0:d].
6.No d worked → return false.

Why s[i] == s[i − d] is the whole condition

If every character matches the one d slots back, then by induction s[i] = s[i − d] = s[i − 2d] = … = s[i mod d]. That's exactly the statement "s is n/d copies of s[0:d]."

Step 4

Code

Try writing it from the six steps above. Reveal when ready to compare.

bool repeatedSubstringPattern(string s) {
    int n = s.size();
    if (n < 2) { return false; }

    for (int d = 1; d <= n / 2; d++) {
        if (n % d != 0) { continue; }   // only divisors of n can tile s

        bool ok = true;
        for (int i = d; i < n; i++) {
            if (s[i] != s[i - d]) {        // periodicity check
                ok = false;
                break;
            }
        }
        if (ok) { return true; }            // s is n/d copies of s[0:d]
    }
    return false;
}

Step 7

Corner cases

1

n = 1 (e.g. "a")

n/2 = 0, so the outer loop body never runs. Function falls through to return false. A single character cannot be "multiple copies" of anything shorter.

2

All identical (e.g. "aaaa")

Returns true immediately at d = 1: every s[i] == s[i − 1] holds. The smallest period always wins because the outer loop scans d in increasing order.

3

Prime length, no repetition (e.g. "abc")

The only divisor of 3 with d ≤ 1 is d = 1, which fails (b ≠ a). Returns false. Highlights why most lengths get skipped via the modulo check.

4

Late inner-loop mismatch (e.g. "abcabcabd")

At d = 3, the inner scan matches at i = 3, 4, 5, 6, 7 and only fails at i = 8 ('d' ≠ 'c'). We can't short-circuit on a partial-prefix match — the inner loop must keep going until either a mismatch or the end.

5

Largest valid period (e.g. "abcabc", d = 3 = n/2)

Boundary of the search range. The loop condition is d <= n/2, not d < n/2 — we must include d = n/2 (exactly two copies).

Step 8

Production readiness

✓

n < 2 early return: avoids running the loop with n/2 = 0; documents the "multiple copies" requirement.

✓

Modulo gate before inner scan: if (n % d != 0) continue; — keeps the inner loop only on lengths that could possibly work, the whole point of Translation 2.

✓

Inclusive upper bound d <= n/2: off-by-one matters — d = n/2 gives exactly two copies, which is valid.

✓

Inner break on first mismatch: abandons the bad d in O(1) extra work after the failing comparison.

✓

Index safety: i starts at d, so i − d is always in [0, n − d) — no out-of-bounds read.

✓

No allocations in the hot path: compare characters in place; no substr, no temporary strings.

Step 9

Approaches — trade-offs

Time O(n · √n)Space O(1)

For each divisor d of n with d ≤ n/2, verify s[i] == s[i − d] for i ∈ [d, n). Easy to derive from first principles, easy to debug — no library calls, no special algorithms. The version above.

Time O(n)Space O(n)

A famous one-liner: return (s + s).substr(1, 2*n − 2).find(s) != string::npos;. If s has a proper period p, then s appears in s+s at offset p; stripping the first and last characters removes the trivial occurrences at offsets 0 and n, so any remaining hit proves periodicity. Stunning, but the correctness argument leans on the periodicity lemma — write only if you can explain it.

bool repeatedSubstringPattern(string s) {
    int n = s.size();
    if (n < 2) { return false; }
    string t = (s + s).substr(1, 2 * n - 2);
    return t.find(s) != string::npos;
}
Time O(n)Space O(n)

Compute the KMP lps array (longest proper prefix that is also a suffix). Let L = lps[n − 1]. Then s is periodic iff L > 0 and (n − L) divides n; the period is n − L. Algorithmically clean — but KMP machinery is overkill for an Easy problem.

bool repeatedSubstringPattern(string s) {
    int n = s.size();
    vector<int> lps(n, 0);
    for (int i = 1, k = 0; i < n; i++) {
        while (k > 0 && s[i] != s[k]) { k = lps[k - 1]; }
        if (s[i] == s[k]) { k++; }
        lps[i] = k;
    }
    int L = lps[n - 1];
    return L > 0 && n % (n - L) == 0;
}

Step 10

Complexity

Time

O(n · √n)

n has at most O(√n) divisors on average; each divisor check costs O(n) in the worst case (when the candidate period almost works). Worst observed cases are highly-composite n like 12, 24, 60.

Space

O(1)

Two integers (d, i) and a bool. No allocations — the in-place periodicity check is the whole point of Translation 1.

Take home

Related problems that use this pattern

The periodicity move — "if a string is built from k copies of a substring, the substring's length divides the whole length" — is the entire engine of this problem. Whenever you see "is X built by repeating Y" or "what's the smallest repeating unit," reach for divisor enumeration + s[i] == s[i − d].
