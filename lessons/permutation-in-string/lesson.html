LC #567 Medium Sliding Window

Before you code

Clarifying questions to ask first

In an interview, ask these before touching any code. Each answer unlocks a specific design decision.

Are both strings lowercase only?

Yes — constraints guarantee lowercase English letters.

→ int[26] is enough, no hash map needed

Can s1 be longer than s2?

Yes. If |s1| > |s2|, no window of size |s1| fits in s2.

→ early return if k > n

Can s1 have duplicate characters?

Yes — e.g. s1="aab" requires exactly 2 a's and 1 b in the window.

→ need counts, not just presence

What do we return?

bool — true if any permutation of s1 appears as a substring of s2.

→ stop at first match, no need to find all

Assumptions we carry forward

Both strings are non-empty lowercase English strings. Characters not in s1 may appear in s2 — they must not cause a false match. We return as soon as the first permutation is found.

The Insight

A permutation = same characters, different order

"ba" is a permutation of "ab" because it uses the exact same characters — just rearranged. To check whether two strings are permutations, you don't sort them. You compare character counts. Slide a fixed-size window of length |s1| across s2; at each step, check whether the window's letter frequencies match s1's.

Step 1

Brute force: check every window

For every starting position in s2, extract the window of size k and compare its character counts to s1's. If they match, return true.

comparisons so far: 0

Cost: O(n · k) time

For each of the n−k+1 starting positions, we scan k characters to build the window's frequency count. With large inputs this is too slow.

bool checkInclusion_BF(string s1, string s2) {
    int k = s1.size(), n = s2.size();
    if (k > n) { return false; }

    int freq1[26] = {};
    for (char c : s1) { freq1[c - 'a']++; } // 'a'-'a'=0, 'b'-'a'=1 ... 'z'-'a'=25

    for (int i = 0; i <= n - k; i++) {
        int freq2[26] = {};
        for (int j = i; j < i + k; j++) {
            freq2[s2[j] - 'a']++;          // rebuild window freq from scratch
        }
        if (memcmp(freq1, freq2, sizeof(freq1)) == 0) { return true; }
    }
    return false;
}

Step 2

Four translations from idea to O(n)

The brute force recomputes the window's frequency map from scratch at every position. Four independent optimizations eliminate that work. Understand all four before reading the final code.

1

Translation 1 — Permutation → frequency map equality

Two strings are permutations iff their character counts match exactly. No sorting needed. Already shown above.

→ enables comparison without O(k log k) sort

2

Translation 2 — Frequency map → int[26]

Lowercase letters only. Use a fixed array of 26 integers. Index a character with c - 'a': 'a' has ASCII value 97, so 'a'−'a'=0, 'b'−'a'=1, … 'z'−'a'=25. No hash map, no heap allocation.

'a'=97→0   'b'=98→1   'c'=99→2   …   'z'=122→25   (for s1="ab")

→ O(1) lookup and update, no hash map overhead

3

Translation 3 — Full array comparison → diff counter

Instead of comparing all 26 slots after every slide (O(26) each time), maintain a single integer: diff = number of slots where the two frequency arrays disagree. When a character enters or leaves the window, at most one slot changes — update diff by ±1. When diff == 0, it's a permutation.

Translation 4 — Slide → two cell updates per step

Adjacent windows differ by exactly two characters: one enters on the right, one leaves on the left. Instead of rebuilding the frequency array, update only those two cells. diff changes by at most ±2 per slide.

s2 = "eidb…" → "eidb…"
out: 'e' leaves freq['e'-'a']++ // one update
in: 'b' enters freq['b'-'a']-- // one update

→ O(k) rebuild per step → O(1) per step → O(n) total

Step 3

The algorithm in plain English

This is exactly what you say out loud in an interview before writing any code.

1.Build freq[26] from s1 (s1 increments each slot). Count diff = number of non-zero slots.
2.Prime the first window of size k over s2: for each char c, freq[c-'a']--. A slot that hits 0 means the two strings agree on that character — diff decrements.
3.If diff == 0 after priming, return true — the first window is already a permutation.
4.Slide one step at a time. Add incoming char (freq[in]--, update diff). Remove outgoing char (freq[out]++, update diff). If diff == 0, return true.
5.If no window matched after all positions, return false.

Why one array encodes both strings

s1 increments (+), s2 decrements (−). A slot at zero means the two strings agree on that character's count. diff tracks how many slots are non-zero — the number of disagreements. Window is valid when diff == 0.

Step 4

Canonical C++ solution

Try writing this from the five steps above. Reveal only when ready to compare.

bool checkInclusion(string s1, string s2) {
    int k = s1.size(), n = s2.size();
    if (k > n) { return false; }

    int freq[26] = {};
    for (char c : s1) { freq[c - 'a']++; }  // s1 increments

    int diff = 0;
    for (int i = 0; i < 26; i++) {
        if (freq[i] != 0) { diff++; }
    }

    // Prime: consume first window
    for (int i = 0; i < k; i++) {
        int c = s2[i] - 'a';
        if      (freq[c] == 1) { diff--; }  // slot 1→0: mismatch resolved
        else if (freq[c] == 0) { diff++; }  // slot 0→-1: new mismatch
        freq[c]--;
    }
    if (diff == 0) { return true; }

    // Slide
    for (int R = k; R < n; R++) {
        int in  = s2[R]     - 'a';
        int out = s2[R - k] - 'a';

        if      (freq[in] == 1)  { diff--; }
        else if (freq[in] == 0)  { diff++; }
        freq[in]--;

        if      (freq[out] == -1) { diff--; }
        else if (freq[out] == 0)  { diff++; }
        freq[out]++;

        if (diff == 0) { return true; }
    }
    return false;
}

Step 7

Corner cases

1

|s1| > |s2|

No window of size k fits inside s2. Return false immediately before any allocation. The check if (k > n) return false handles this.

2

s1 has duplicate characters — s1="aab"

freq starts with freq['a']=2, freq['b']=1. The window needs exactly 2 a's to bring the 'a' slot to zero. A window with only 1 'a' leaves freq['a']=1 (non-zero), so diff > 0. Correctly not a match.

3

s1 == s2 (perfect match)

After priming the first (and only) window covers the entire string. diff == 0. Return true immediately — the slide loop never runs.

4

Characters in s2 not in s1

freq for those characters starts at 0. When they enter the window, freq goes negative (non-zero), increasing diff. They prevent a false match. When they leave, diff drops back. They never cause a spurious true.

5

s1 is a single character

k=1. Every slide is one character. Any occurrence of that character in s2 produces diff==0. Essentially a linear scan.

Step 8

Production readiness

Run through this before calling it done in an interview.

✓

k > n: early return — no undefined loop bounds.

✓

All same character: s1="aaa", s2="aaaa" — freq['a']=3, priming subtracts 3 → slot hits 0 → diff==0. Returns true correctly.

✓

No match at all: diff never reaches 0, loop exhausts all n−k positions, returns false.

✓

Integer overflow: freq values bounded by |s1| ≤ 10⁴. int is safe.

✓

ASCII arithmetic: c - 'a' always in [0,25] for lowercase input. No out-of-bounds access.

Step 9

Approaches

Time O(n)Space O(1)

Single int[26] encoding both strings. diff counter avoids per-step array comparison. Priming + sliding. The approach in Step 4 above.

Time O(n)Space O(1)

Keep two separate int[26] arrays — one for s1, one for the current window. After each slide, compare with memcmp or a 26-element loop. Same asymptotic complexity but O(26) comparison per step instead of O(1). Easier to reason about; slightly slower in practice.

Time O(n·k)Space O(1)

Rebuild window frequency from scratch for each position. Fine for small inputs; TLE on LeetCode for large ones.

Step 10

Complexity

Time

O(n)

n=|s2|. Build freq: O(k). Prime: O(k). Slide: O(n−k). Each character in s2 visited exactly once.

Space

O(1)

Single int[26] — fixed size regardless of input. No dynamic allocation in the hot path.

Take home

What to remember for similar problems

The diff counter pattern is the signature move for fixed-window anagram problems. Whenever you need "does the window match this target distribution," maintain a mismatch count instead of comparing arrays each step.

The single-array encoding (s1 increments, s2 decrements, zero = agreement) is reusable in any problem comparing two character distributions incrementally.
