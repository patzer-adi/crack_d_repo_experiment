LC #209 Medium Sliding Window Two Pointers

Before you code

→ unlocks: no empty-array guard needed; but check "no valid subarray" case at the end.

Assumptions we carry forward

All elements are strictly positive; target ≥ 1; we return the minimum window length, or 0 if no subarray can reach target. Because elements are positive, window sum is monotonically non-decreasing as R grows — which is the single property that makes a variable-size sliding window correct here.

The Insight

Grow until you hit target, then shrink from the left — record the length each time you shrink.

The brute force checks every subarray (L, R) — O(n²) pairs. But since every element is positive, adding an element to the right can only increase the sum, and removing from the left can only decrease it. That monotone property means once window sum ≥ target, you never need to re-try a smaller R for the same L — you can just shrink L. This shrink-while-valid loop turns the nested loops into a single linear pass: R moves right n times, L moves right at most n times, so every element is visited at most twice.

Example · nums = [2, 3, 1, 2, 4, 3] · target = 7

The kernel

Use two pointers L and R. Advance R one step at a time, adding nums[R] to a running sum. Whenever sum ≥ target, record the window length (R−L+1) as a candidate answer, then subtract nums[L] and advance L — repeat until sum < target. Because all elements are positive, sum can only grow by expanding R and shrink by contracting L; the sliding window visits each element at most twice, giving O(n) time and O(1) space.

Step 1

Brute force — feel the cost

Try every starting index L. For each L, extend R rightward accumulating a sum until it hits target — then record the length and move to the next L. This is O(n²) in the worst case because every pair (L, R) might be tested. The "Checks" counter below counts how many (L, R) pairs the brute force examines.

Cost: O(n²) time, O(1) space

For each of the n starting positions, we scan up to n elements rightward. On an array of 10⁵ elements that's 10¹⁰ operations — far too slow. The "Checks" counter above makes that visible even on tiny inputs.

int minSubArrayLen(int target, vector<int>& nums) {
    int n = nums.size(), ans = INT_MAX;
    for (int L = 0; L < n; L++) {
        int s = 0;
        for (int R = L; R < n; R++) {
            s += nums[R];
            if (s >= target) {
                ans = min(ans, R - L + 1);
                break; // no shorter window starting at L exists
            }
        }
    }
    return ans == INT_MAX ? 0 : ans;
}

Step 2

Translations — every optimisation, named

The brute force has one key inefficiency: after finding a valid window at (L, R), it throws away the running sum and starts fresh at L+1 from scratch. Since all values are positive, there is a smarter way to reuse work: instead of restarting, advance L while the window is still valid. Two named translations get you there.

1
Two nested loops → one expanding pointer + one shrinking pointer
Instead of a full inner loop restarting at L every time, keep a running sum s and a left pointer L. As R advances, add nums[R] to s. When s ≥ target, shrink from L: record the window length, subtract nums[L], advance L — repeat until s < target. No inner loop needed because positive elements guarantee shrinking always decreases sum.
→ O(n²) with break → O(n) amortized (each element enters and exits the window at most once)
2
INT_MAX sentinel → 0-return for impossible case
Initialize ans = INT_MAX. After the single pass, if ans is still INT_MAX no valid subarray was found — return 0. This is cleaner than a boolean flag and avoids any special-case branching inside the loop. The final return is simply ans == INT_MAX ? 0 : ans.
→ same O(1) space — just a cleaner termination condition

Step 3

The algorithm in plain English

1
Initialise L = 0, s = 0, ans = ∞. These are the only variables you need.
2
Expand R from 0 to n−1. At each step, add nums[R] to the running sum s.
3
While s ≥ target: record ans = min(ans, R−L+1), then subtract nums[L] from s and advance L++. This shrinks the window from the left as long as it stays valid.
4
After R reaches the end, return ans == ∞ ? 0 : ans. If ans was never updated, no subarray reached target.

Step 4

Code

int minSubArrayLen(int target, vector<int>& nums) {
    int n = nums.size();
    int ans = INT_MAX;
    int s = 0, L = 0;
    for (int R = 0; R < n; R++) {
        s += nums[R];
        while (s >= target) {
            ans = min(ans, R - L + 1);
            s -= nums[L++];
        }
    }
    return ans == INT_MAX ? 0 : ans;
}

Step 7

Corner cases

1

No valid subarray — return 0

[1,1,1,1,1], target=11 — the total sum (5) is less than target. The while-loop never fires, ans stays INT_MAX. Return 0.

2

Single element equals target

[7], target=7 — R=0: s=7 ≥ 7, ans=min(∞,1)=1, s−=7, L=1. Loop ends. Return 1. The answer is 1 (trivially), but the algorithm still runs through both the expand and shrink phases.

3

Answer is the whole array

[1,2,3,4,5], target=15 — the window must include every element; ans=5. The shrink loop fires only once (at R=4), and immediately s < target again. Confirm ans=5, not 0.

4

First element alone satisfies target

[7,2,2,3], target=7 — on R=0 the window [0,0] already has sum=7, ans=1, shrink fires. The rest of the array is irrelevant; ans stays 1. Confirm early-shrink doesn't advance L past R.

5

All elements equal target

[4,4,4], target=4 — each single element satisfies the condition. At R=0: s=4 ≥ 4, ans=1, shrink. R=1: s=4 ≥ 4, ans still 1. R=2 likewise. Return 1. Confirm that repeated equals don't produce ans=0 or overflow.

Step 8

Production readiness

✓Initialise ans = INT_MAX, not −1 or 0. Returning ans == INT_MAX ? 0 : ans is cleaner than a boolean found flag.
✓Use while, not if, for the shrink loop. Multiple shrinks can be valid for the same R (e.g. when nums[R] is very large). An if leaves the window too large.
✓Record before shrinking: ans = min(ans, R − L + 1) happens before s −= nums[L++]. Swapping the order would record a window one element too small.
✓Correctness depends on positive elements. If the constraint ever changes (e.g. negative values allowed), this algorithm is wrong and you need a prefix-sum + binary search or deque approach.
✓No overflow risk in practice: n ≤ 10⁵, values ≤ 10⁴ → max sum ≤ 10⁹, fits in a 32-bit int. If constraints change, use long long for s.
✓Time O(n), Space O(1) — suitable for any n ≤ 10⁵ and real-time / embedded settings where extra memory is forbidden.

Step 9

Approaches — trade-offs

Time O(n) Space O(1) Positive elements only

Two pointers L, R with a running sum. The sliding window works because all values are positive — adding an element increases the sum, removing decreases it. This monotone property allows the shrink loop to be correct. If negative values were allowed this approach would fail.

int minSubArrayLen(int target, vector<int>& nums) {
    int n = nums.size(), ans = INT_MAX, s = 0, L = 0;
    for (int R = 0; R < n; R++) {
        s += nums[R];
        while (s >= target) {
            ans = min(ans, R - L + 1);
            s -= nums[L++];
        }
    }
    return ans == INT_MAX ? 0 : ans;
}
Time O(n log n) Space O(n) Works with positive elements

Build a prefix sum array P where P[i] = nums[0]+…+nums[i−1]. For each L, binary-search for the smallest R such that P[R+1] − P[L] ≥ target. Because all elements are positive, P is strictly increasing, making binary search valid. This approach is O(n log n) — useful in interviews to show you know multiple approaches, but strictly dominated by the sliding window.

int minSubArrayLen(int target, vector<int>& nums) {
    int n = nums.size(), ans = INT_MAX;
    vector<int> P(n + 1, 0);
    for (int i = 0; i < n; i++) { P[i + 1] = P[i] + nums[i]; }
    for (int L = 0; L < n; L++) {
        int need = P[L] + target;
        auto it = lower_bound(P.begin(), P.end(), need);
        if (it != P.end()) {
            int R = it - P.begin() - 1;
            ans = min(ans, R - L + 1);
        }
    }
    return ans == INT_MAX ? 0 : ans;
}
Time O(n²) Space O(1) TLE on large inputs

Try every starting index L; for each L scan right until sum ≥ target or R reaches the end. Record the length. This is the most intuitive approach but fails the time limit for n = 10⁵. Use only as a reference implementation to sanity-check the optimal solution.

int minSubArrayLen(int target, vector<int>& nums) {
    int n = nums.size(), ans = INT_MAX;
    for (int L = 0; L < n; L++) {
        int s = 0;
        for (int R = L; R < n; R++) {
            s += nums[R];
            if (s >= target) {
                ans = min(ans, R - L + 1);
                break;
            }
        }
    }
    return ans == INT_MAX ? 0 : ans;
}

Step 10

Complexity

Time
O(n)
R advances n times; L advances at most n times across the entire run — each element is added to and removed from the window at most once.
Space
O(1)
Only four integers (n, ans, s, L) — no auxiliary arrays or hash maps required.
