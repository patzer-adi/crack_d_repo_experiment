Find the Duplicate Number

LC #287 Medium Array

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

Can I modify the input array?
The problem doesn't forbid it, but a good solution should not. Modifying the input breaks reusability and can cause side effects.
→ Solutions must trade off between time and space; optimal is O(n) time with O(1) space and no modification.
What if all numbers are unique?
The problem guarantees at least one duplicate. But a robust solution should handle the no-duplicate case gracefully.
→ Algorithm must terminate correctly even on edge cases.
Can the duplicate appear just once?
No. "Duplicate" means it appears at least twice, sometimes more.
→ The duplicate is guaranteed to be present; algorithm will always find it.
How can we treat the array as a linked list?
Index i contains value nums[i]; treat nums[i] as a pointer to the next index. Follow: i → nums[i] → nums[nums[i]] → ...
→ This linked-list view reveals a cycle whose entry point is the duplicate.

The Insight

Treat indices as a linked list — the duplicate is the cycle entry.

Read the array as an implicit linked list: index i has a "next pointer" equal to nums[i]. With n+1 elements but only n distinct values in [1,n], two indices must point to the same next — that's the cycle. The duplicate value is the cycle entry index. Floyd's tortoise-and-hare finds it in O(1) space with no array modification.

slow (step 1) fast (step 2) slow + fast meet cycle entry (answer) ⤴ reset (Phase 2)
phase: — slow = — fast = — slow2 = — duplicate = —
—

The kernel

Phase 1 (detect cycle): slow = nums[slow], fast = nums[nums[fast]] until they meet.
Phase 2 (find entry): reset slow2 = nums[0]. Advance both 1 step at a time until they meet — that meeting index is the duplicate.
O(n) time, O(1) extra space, no array modification.

Step 1

Brute force — feel the cost

Walk the array left-to-right and remember each value in a hash set. The first value that's already in the set is the duplicate. O(n) time but O(n) extra space — the set grows with the input. Step through to see the set fill up until a hit.

i = —  ·  nums[i] = —  ·  seen = {}

Cost: O(n) time, O(n) space

Each insert + lookup is O(1) amortised, n total — fast. The cost is the hash set. The optimal Floyd's algorithm keeps O(1) extra space by treating the array as an implicit linked list.

int findDuplicate_BF(vector<int>& nums) {
    unordered_set<int> seen;
    for (int v : nums) {
        if (seen.count(v)) return v;
        seen.insert(v);
    }
    return -1;
}

Step 2

Translations — every optimisation, named

The optimization from hash set to Floyd's cycle detection eliminates the O(n) extra space. Instead of storing elements, we use the array's implicit linked-list structure and two pointers to detect the cycle and find its entry point.

1
Hash set
Iterate and store each element in a set. Return the first duplicate seen.
O(n) time, O(n) space
2
Floyd's cycle detection (taught)
Treat array as linked list. Use slow/fast pointers to find cycle, then find the entry point (the duplicate).
O(n) time, O(1) space

Step 3

The algorithm in plain English

1
Phase 1 (Detect cycle): Initialize slow = nums[0], fast = nums[0]. Move slow one step and fast two steps until they meet.
2
Phase 2 (Find entry): Reset slow = nums[0]. Keep fast at the meeting point.
3
Advance both one step at a time (slow = nums[slow], fast = nums[fast]) until they meet.
4
Return slow (the cycle entry, which is the duplicate).

Step 4

Code

int findDuplicate(vector<int>& nums) {
    int slow = nums[0];
    int fast = nums[0];
    // Phase 1: Detect cycle
    do {
        slow = nums[slow];
        fast = nums[nums[fast]];
    } while (slow != fast);
    // Phase 2: Find cycle entry
    slow = nums[0];
    while (slow != fast) {
        slow = nums[slow];
        fast = nums[fast];
    }
    return slow;
}

Step 7

Corner cases

1
Minimal: [1, 1]
Both slow and fast start at nums[0]=1. Phase 1: slow=nums[1]=1, fast=nums[nums[1]]=nums[1]=1. They meet immediately. Phase 2 finds entry at 1.
2
Duplicate at start: [2, 1, 1, 3]
Duplicate is 1. Path follows 0→2→1→1 (cycle at index 1). Algorithm finds 1 as the entry point.
3
Duplicate at end: [1, 2, 3, 3]
Duplicate is 3. Path: 0→1→2→3→3 (cycle at index 3). Algorithm correctly identifies 3 as the cycle entry.
4
Many duplicates: [1, 4, 4, 2, 4]
Duplicate is 4 (appears 3 times). Cycle is centered at value 4. Algorithm finds 4 as the cycle entry on first encounter.
5
Long cycle: [2, 5, 9, 6, 4, 3, 8, 6, 7, 1]
Duplicate 6 appears twice, creating a long cycle. Phase 1 and phase 2 together find 6 as the entry point.

Step 9

Approaches — trade-offs

O(n) O(1)

Two-phase algorithm: detect the cycle with fast/slow pointers, then find the entry point. No modification, no extra space. Optimal and elegant.

int findDuplicate(vector<int>& nums) {
    int slow = nums[0], fast = nums[0];
    do {
        slow = nums[slow];
        fast = nums[nums[fast]];
    } while (slow != fast);
    slow = nums[0];
    while (slow != fast) {
        slow = nums[slow];
        fast = nums[fast];
    }
    return slow;
}
O(n) O(n)

Store each element in a hash set. Return the first element already in the set. Simple and intuitive, but uses O(n) extra space.

int findDuplicate(vector<int>& nums) {
    unordered_set<int> seen;
    for (int num : nums) {
        if (seen.count(num)) {
            return num;
        }
        seen.insert(num);
    }
    return -1;
}
O(n) O(1)

Mark visited indices by negating nums[i]. If nums[i] is already negative, nums[i] is a duplicate. O(1) space but modifies the input.

int findDuplicate(vector<int>& nums) {
    for (int num : nums) {
        int idx = abs(num);
        if (nums[idx] < 0) {
            return idx;
        }
        nums[idx] = -nums[idx];
    }
    return -1;
}
