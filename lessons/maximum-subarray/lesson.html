Maximum Subarray

LC #53 Medium Arrays

Before you code

Clarifying questions to ask first

Each answer narrows the design space. The "all negatives" question alone rules out a whole family of wrong solutions.

Can the array contain only negative numbers?

Yes — the array has ≥ 1 element but every element may be negative.

→ rules out "track running sum, return 0 if it never goes positive". Answer for [-3,-1,-4,-2] is -1, not 0 — we accept the least bad single element.

Must the subarray be contiguous?

Yes — that's the defining constraint.

→ no subset-sum machinery; we only consider windows defined by (start, end) pairs.

Do we return the sum, or the subarray itself?

Just the sum (the integer).

→ no need to track start/end indices. Two integers — cur and best — are enough.

Are we guaranteed at least one element?

Yes; the constraint is n ≥ 1.

→ initialise cur = best = nums[0] and start the loop at i = 1. No empty-array branch needed.

Assumptions we carry forward

Non-empty integer array; negatives allowed; return a single integer (the sum). Initialise both running variables to nums[0] so an all-negative input still returns the maximum element.

The Insight

Best subarray ending at i: extend the previous one, or restart at i.

Watch the running sum walk the array. Where it stays positive, extending pays. Where it would go negative, dragging it forward only hurts — better to drop everything and restart at the current element. The optimal subarray ending at each position is one of these two choices; the global answer is the highest peak the running sum ever reaches.

The kernel

cur(i) = max(nums[i], cur(i−1) + nums[i])
best   = max(best, cur(i))
The recurrence depends only on cur(i−1), so two integers carry the entire state forward.

Step 1

Brute force — sum every (start, end) window

For every starting index i, walk forward summing into s, and at every position j compare s against the running best. n starts × up to n ends per start = O(n²) work.

start —  ·  end —  ·  window sum = —  ·  best = —  ·  additions: 0

Cost: O(n²) time

Every start re-sums prefixes the previous start already saw. Kadane's collapses this nested loop into a single pass by reusing one running sum.

int maxSubArray_BF(vector<int>& nums) {
    int n = nums.size(), best = nums[0];
    for (int i = 0; i < n; i++) {
        int s = 0;
        for (int j = i; j < n; j++) {
            s += nums[j];                    // O(1) per (i,j) pair
            best = max(best, s);
        }
    }
    return best;
}

Step 2

Four translations to O(n) time, O(1) extra space

The brute force re-explores every window from scratch. These four named translations turn the search into a single linear scan.

1

Translation 1 — Search end-positions, not (start, end) pairs

"Maximum sum over all windows" = "max over all i of (best window ending at i)". Reduces a 2D (start, end) search to a 1D pass over end positions.

→ identifies the right per-index quantity to track: cur(i), the best subarray ending at i.

2

Translation 2 — The DP recurrence

cur(i) is built from cur(i−1) by exactly one decision: extend the previous subarray with nums[i], or start a new subarray at nums[i]. Whichever is larger.

cur(i) = max( nums[i],   cur(i−1) + nums[i] )

→ each step is O(1). All windows ending at i collapse into one number.

3

Translation 3 — Restart ⇔ drop a negative prefix

Equivalent rewrite: cur(i) = nums[i] + max(0, cur(i−1)). If the running sum is negative, throw it away — the new subarray is just nums[i] on its own. This is the rule of thumb behind "extend vs. restart".

→ explains why the DP works: a negative prefix can only hurt every future window that contains it.

4

Translation 4 — Collapse the DP array to one variable

cur(i) only depends on cur(i−1), so we don't need an array — one integer cur overwritten each step. A second integer best tracks the running maximum of cur.

→ space: O(n) DP array → O(1). Two integers replace the whole table.

Step 3

The algorithm in plain English

1.Initialise cur = nums[0], best = nums[0].
2.For each i from 1 to n−1:
3.Decide — cur = max(nums[i], cur + nums[i]). Equivalent to: extend if cur ≥ 0, otherwise restart at nums[i].
4.Record — best = max(best, cur).
5.Return best.

Why initialise to nums[0], not 0

If we initialise best = 0, an all-negative input like [-3,-1,-4] wrongly returns 0 (an empty subarray, which the problem disallows). Starting at nums[0] ensures we always return a real element's contribution.

Step 4

Canonical C++ solution

Try to reproduce this from the five steps before revealing.

int maxSubArray(vector<int>& nums) {
    int cur = nums[0];
    int best = nums[0];
    for (int i = 1; i < (int)nums.size(); i++) {
        cur = max(nums[i], cur + nums[i]);   // extend or restart
        best = max(best, cur);                // record
    }
    return best;
}

Step 7

Corner cases

1

Single element — [7] or [-7]

Loop body never runs. Returns the initial best = nums[0]. Works for both positive and negative singletons.

2

All negatives — [-3, -1, -4, -2] → -1

Every step restarts (extending only worsens the sum). The answer is the largest single element. This is exactly why cur and best initialise to nums[0], not 0 — initialising to 0 would wrongly return the sum of an empty subarray.

3

All positives — [1, 2, 3] → 6

Every step extends; no restart ever fires. cur and best climb in lockstep to the total.

4

Lone positive between negatives — [-5, 3, -5] → 3

i=1 restarts at 3 (cur=−5+3=−2 < 3); best becomes 3. i=2 extends to −2; best stays 3.

5

Zero in the mix — [0, -1, 2] → 2

A zero "extends" without changing cur. The two branches of the max tie, so behaviour is well-defined regardless of which arm wins.

Step 8

Production readiness

✓

All-negative input handled: cur and best initialise to nums[0], so we never spuriously return 0.

✓

Single-element input handled: the loop runs zero iterations; best = nums[0] is returned directly.

✓

Order of updates: compute cur first, then update best from it. Reversing the order would miss the case where the new cur is itself the new global maximum.

✓

Integer overflow: per LC constraints (n ≤ 10⁵, |nums[i]| ≤ 10⁴), max possible sum ≈ 10⁹ — fits in int. Use long long if constraints loosen.

✓

One pass, O(1) extra space: two integer locals, no auxiliary array.

Step 9

Approaches — trade-offs

Time O(n)Space O(1)

Single pass, two integers. The DP recurrence collapses to one variable because cur(i) only depends on cur(i−1). The algorithm above.

Time O(n log n)Space O(log n)

Split the array at the midpoint. The maximum subarray is either entirely in the left half, entirely in the right half, or spans the midpoint. The cross-midpoint case requires an O(n) scan outward from the centre. T(n) = 2T(n/2) + O(n) → O(n log n). Strictly worse than Kadane's, but a reasonable interview alternative.

int solve(vector<int>& a, int l, int r) {
    if (l == r) return a[l];
    int m = (l + r) / 2;
    int bl = solve(a, l, m), br = solve(a, m+1, r);
    int sl = INT_MIN, s = 0;
    for (int i = m;   i >= l; i--) { s += a[i]; sl = max(sl, s); }
    int sr = INT_MIN; s = 0;
    for (int i = m+1; i <= r; i++) { s += a[i]; sr = max(sr, s); }
    return max({bl, br, sl + sr});
}
Time O(n²)Space O(1)

Iterate every (start, end) pair, maintaining a running sum across the inner loop. Correct but TLEs for large n. Useful only as the derivation anchor for the translations above.

Step 10

Complexity

Brute force

O(n²) / O(1)

Every (start, end) pair, with a running inner sum.

Divide & conquer

O(n log n) / O(log n)

T(n) = 2T(n/2) + O(n) for the cross-midpoint scan.

Kadane's ✓

O(n) / O(1)

One pass; two integer locals; recurrence collapses the DP table.

Take home

Related problems that use this pattern

The "best ending here" reframing: when a search asks for the optimum over all contiguous windows, ask instead for the optimum window ending at every i. That per-index quantity often satisfies a one-step recurrence and collapses the search to a single pass.

In an interview: brute force first (O(n²)), then state the recurrence cur(i) = max(nums[i], cur(i−1) + nums[i]), then point out the recurrence only references cur(i−1) so the DP array reduces to one variable.
