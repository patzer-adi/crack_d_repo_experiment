Majority Element II

LC #229 Medium Array

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

How many elements can appear more than ⌊n/3⌋ times?

At most 2. If 3 or more each appeared more than n/3 times, their combined count would exceed n — impossible.

→ We need exactly 2 candidate slots. This structural bound is the entire insight.

Is a result guaranteed? Can the output be empty?

Not guaranteed. There may be 0, 1, or 2 qualifying elements.

→ A verification pass is MANDATORY — Boyer-Moore finds candidates, not guaranteed winners.

Does output order matter?

No — return in any order.

→ We can return candidates in the order their slots were filled, without sorting.

What if an element matches a slot whose count is 0?

The match check (num == c1) runs before the "slot empty" check (k1 == 0). Matching wins even at count 0.

→ This ordering is subtle — it prevents a slot from being hijacked when the old candidate deserves re-votes.

Assumptions we carry forward

Output may be empty; order doesn't matter; verification pass is always required; match check before empty check.

The Insight

At most two elements exceed n/3 — keep two Boyer-Moore slots and cancel in triples.

Three values each appearing more than n/3 times would total more than n — impossible. So at most two slots can survive. Walk once with two candidate slots; mismatch on both cancels one from each (outsider + c1 + c2 form a triple that disappears). Verify survivors with a second pass — Boyer-Moore only narrows the field.

The kernel

keep (c1,k1) and (c2,k2). For each x: match → ++ that slot; empty slot → fill; else → −−both.
verify each survivor with a count pass; keep only those > n/3.
Triple-cancel removes one of each candidate plus the outsider — true winners can't all be eliminated.

Step 1

Brute force — feel the cost

For each element, scan the entire array to count its occurrences. If count > n/3, include it in the result. O(n²) time: each of the n outer elements triggers an n-element inner scan.

—
Checks: 0 Count so far: 0 Result: [ ] 
vector<int> majorityElement(vector<int>& nums) {
    int n = nums.size();
    vector<int> result;
    for (int i = 0; i < n; i++) {
        // skip if already found this value
        if (find(result.begin(), result.end(), nums[i]) != result.end()) { continue; }
        int count = 0;
        for (int j = 0; j < n; j++) {
            if (nums[j] == nums[i]) { count++; }
        }
        if (count > n / 3) { result.push_back(nums[i]); }
    }
    return result;
}

Step 2

Translations — every optimisation, named

Two improvements take O(n²)/O(1) brute force to O(n)/O(1) Boyer-Moore.

1

Translation 1 — Full rescan → hash map

One pass builds a frequency map. Scan the map for keys with count > n/3. For [1,1,2,2,3]: map = {1:2, 2:2, 3:1}. Check 2>5/3=1 → yes for 1 and 2, no for 3. Return [1,2]. No rescanning.

→ O(n²) → O(n) time; O(1) → O(n) space (hash map)

2

Translation 2 — Hash map → 2-candidate Boyer-Moore + verify

Instead of counting everything, track only 2 candidates. A "triple cancel" (element matches neither slot and both counts are > 0) discards one vote from each candidate: net effect is zero change in who is majority. The two survivors — if any actually exceed n/3 — are confirmed by a second verification pass. Without the verification, bogus candidates (survivors at count 0) could be returned incorrectly.

[1,2,3]: c1=1,c2=2 after idx 1; triple cancel at idx 2 → k1=0,k2=0.
Verify: 1 appears 1 time, 1>1? NO. 2 appears 1 time → NO. Return [].

→ O(n) time, O(n) space → O(n) time, O(1) space

Step 3

The algorithm in plain English

1.Initialize two slots: c1 = 0, k1 = 0, c2 = 0, k2 = 0.
2.For each num in the array:
3.   If num == c1, increment k1. Else if num == c2, increment k2.
4.   Else if k1 == 0, fill slot 1 (c1 = num, k1 = 1). Else if k2 == 0, fill slot 2.
5.   Otherwise cancel: k1 − −, k2 − −.
6.Verify: count c1 and c2's occurrences; include in result if count > n/3.
7.Return the result (0, 1, or 2 elements).

Why step 3 runs before step 4

Checking num == c1 before checking k1 == 0 is critical. If c1 = 1 and k1 = 0 and num = 1 arrives, num correctly matches c1 and k1 goes from 0 to 1 — not a "new fill." If step 4 ran first, c1 would be incorrectly replaced. See dry-run Ex 3, step i=4 for the live demonstration.

Step 4

Code

Try writing it from the seven steps above. Reveal when ready to compare.

vector<int> majorityElement(vector<int>& nums) {
    int c1 = 0, k1 = 0, c2 = 0, k2 = 0;
    for (int num : nums) {
        if      (num == c1) { k1++; }
        else if (num == c2) { k2++; }
        else if (k1 == 0)  { c1 = num; k1 = 1; }
        else if (k2 == 0)  { c2 = num; k2 = 1; }
        else               { k1--; k2--; }
    }
    vector<int> result;
    if (count(nums.begin(), nums.end(), c1) > (int)nums.size() / 3) { result.push_back(c1); }
    if (count(nums.begin(), nums.end(), c2) > (int)nums.size() / 3) { result.push_back(c2); }
    return result;
}

Step 7

Corner cases

1

All identical (e.g. [1, 1, 1])

c1 = 1 at i = 0, k1 climbs to 3. Slot 2 never fills. Verify c1 = 1: appears 3 times > 3/3=1 → YES. Verify c2 = 0 (initial): count=0 → NO. Return [1].

2

No winner (e.g. [1, 2, 3])

i=0→c1=1, i=1→c2=2, i=2→cancel. Both counts drop to 0. Verify: each element appears exactly once. 1 > 3/3=1? NO (strictly greater). Return []. Verification is what separates real winners from imposters.

3

n = 1 (e.g. [7])

c1 = 7, k1 = 1. Verify: 7 appears 1 time > ⌊1/3⌋=0 → YES. Return [7]. Single element always qualifies (1 > 0).

4

Match check before empty check (e.g. [1, 2, 2, 3, 1])

At i=3, num=3 cancels — k1 drops to 0. At i=4, num=1 matches c1=1 (even though k1=0), so k1 goes 0→1 not 0 then fill. If the empty check ran first, c1 would be overwritten with 1 again (same value, accidental correctness) or wrong in other inputs. The rule is: match always beats fill.

5

Two winners even though candidates change (e.g. [1, 1, 2, 2])

i=0→c1=1,k1=1; i=1→k1=2; i=2→k2=0→c2=2,k2=1; i=3→k2=2. Both survive. Verify: each appears 2 times > 4/3≈1.33 → YES. Return [1,2].

Step 8

Production readiness

✓Verification pass is mandatory — without it, surviving candidates at count 0 would be incorrectly included. Always re-count.
✓Match before empty check — if (num == c1) must precede if (k1 == 0). Swapping them causes wrong results when a slot has count 0 but still holds a valid candidate.
✓Empty output — [1,2,3] returns []. The result vector may have 0 elements; return it as-is.
✓n = 1 — single element always qualifies (1 > 0). Loop runs once, slot 1 fills, verify succeeds.
✓Integer range — k1 and k2 are at most n ≤ 5×10⁴; no overflow. std::count returns size_t; cast to int before dividing to avoid unsigned comparison issues.
✓Initial c1 = c2 = 0 — if the input contains 0 appearing > n/3 times, it legitimately fills slot 1 (num==c1 fires at i=0). Verification handles all edge cases regardless.

Step 9

Approaches — trade-offs

O(n)O(1)

Two passes: vote scan + verification. Two scalar variables per slot. Requires knowing the structural bound (at most 2 winners). The general pattern — k-1 slots for "elements appearing > n/k times" — is the Misra-Gries heavy-hitters algorithm. Same code as Step 4.

O(n)O(n)

One pass to count all frequencies, then filter for count > n/3. Straightforward — no structural reasoning needed. Good first answer; easy to explain why it's correct without rehearsal. Upgrade to Boyer-Moore only if the interviewer explicitly asks for O(1) space.

vector<int> majorityElement(vector<int>& nums) {
    unordered_map<int,int> freq;
    for (int x : nums) { freq[x]++; }
    vector<int> result;
    for (auto& [k, v] : freq) {
        if (v > (int)nums.size() / 3) { result.push_back(k); }
    }
    return result;
}

Step 10

Complexity

Time

O(n)

Two linear passes: vote scan + verification. Each element is processed in O(1) per pass.

Space

O(1)

Four integers (c1, k1, c2, k2) plus the output vector (at most 2 elements, treated as output not auxiliary).

Related problems that use this pattern

LC 169 — Majority Element. The n/2 version with 1 candidate slot. No verification needed because majority is guaranteed and always exactly one winner exists. Start here before this problem.

General Misra-Gries algorithm. For "find all elements appearing > n/k times," use k-1 candidate slots. Boyer-Moore (k=2) and this problem (k=3) are the two most common interview variants. The generalization to arbitrary k is the heavy-hitters problem in streaming algorithms.
