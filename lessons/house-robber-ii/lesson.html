Clarifying questions to ask first

This problem is one tiny rule away from regular House Robber (LC 198). The questions below pin down exactly what changed.

Are the houses really arranged in a circle? What does "circle" mean for adjacency?
Yes — the array is cyclic. House 0 and house n-1 are neighbours, on top of all the usual i ↔ i+1 pairs.

Can I just run plain linear House Robber and patch the answer?
No. Linear HR may rob both nums[0] and nums[n-1] — they don't look adjacent in the linear view. The algorithm has to know about the new constraint up front.

Assumptions we carry forward

Cyclic array of n ≥ 1 non-negative integers; adjacency includes both i ↔ i+1 AND 0 ↔ n-1; return the max sum. Prerequisite: you already know how to solve linear House Robber (LC 198) in O(n) time and O(1) memory with two rolling variables prev2, prev1.

The Insight

Break the circle: one of the two endpoints is always free of robbery, so solve linear House Robber twice.

Going from a line of houses to a circle adds exactly one new rule: house 0 and house n-1 are now neighbours. Everything else is unchanged. Because adjacent houses can't both be robbed, the optimal plan cannot include both endpoints — at least one of them must be skipped. So we try the two cases: Case A drops the last house and solves linear House Robber on what's left; Case B drops the first house and does the same. The answer is whichever case gives the bigger total. Each case is just LC 198 — same rolling-pair DP, same O(n) time, same O(1) memory — run twice.

The kernel

If n == 1 return nums[0]. Otherwise compute caseA = linearRob(nums, 0, n-2) and caseB = linearRob(nums, 1, n-1), where linearRob is the LC 198 rolling-pair DP over an inclusive index range. Return max(caseA, caseB). One pass per case, O(n) total, O(1) auxiliary memory.

Step 1

Brute force — feel the cost

As with LC 198, the safest first move is to try every possible plan and keep the best legal one. The only change here is the legality check.

A "plan" is still one yes/no decision per house: rob it or leave it, so for n houses we have 2^n plans. For each plan we now check two things instead of one: (1) No linear adjacency — no two robbed houses sit at consecutive indices i, i+1. (2) No circle adjacency — house 0 and house n-1 aren't both robbed. If both checks pass, sum the values; keep the best legal total.

The animation below enumerates every plan as a binary mask. Houses turn green when picked in a legal plan, amber when the plan is illegal (either kind of adjacency). Watch the counter: it's still 2^n plans, so doubling the houses still doubles the work.

Cost: O(2^n · n) time, O(n) space

Same exponential cost as LC 198 — the extra circle check only adds a constant to each plan. n = 30 still means a billion plans; the LeetCode constraint allows n = 100, which is hopeless. The whole point of this lesson is that we don't need to look at every plan — we just need to look at two linear sub-problems.

int robBrute(vector<int>& nums) {
    int n = nums.size();
    int best = 0;
    for (int mask = 0; mask < (1 << n); mask++) {
        bool legal = true;
        int sum = 0;
        int prevBit = -2;
        for (int i = 0; i < n; i++) {
            if ((mask >> i) & 1) {
                if (i - prevBit == 1) { legal = false; break; }
                sum += nums[i];
                prevBit = i;
            }
        }
        // Circle adjacency: bit 0 AND bit n-1 both set is also illegal
        if (legal && ((mask & 1) && ((mask >> (n - 1)) & 1))) { legal = false; }
        if (legal) { best = max(best, sum); }
    }
    return best;
}

Step 2

Translations — every optimisation, named

We already know how to solve linear House Robber (LC 198) in one O(n) pass. The job here is just to connect the circular problem to that. Five small steps.

1
Step 1 — Notice that "linear House Robber on the original array" is wrong.
If we naively run the LC 198 algorithm on nums as if it were a line, it can pick both nums[0] and nums[n-1] (they're 4-or-more apart in the linear view, so the per-index check doesn't catch them). On a circle, that's illegal. Example: [100, 1, 1, 100] — linear HR returns 200, but the correct circular answer is 101. So the line-based algorithm needs help.
→ no code change yet — we just spotted what's broken
2
Step 2 — Isolate what actually changed.
Compare linear House Robber's rules to circular House Robber's rules. Linear forbids every pair {i, i+1}. Circular forbids the same set of pairs plus exactly one more: {0, n-1}. That's the entire difference. Everything else — the values, the goal, the per-index "rob or skip" choice — is the same.
→ scope reduced: one extra forbidden pair, nothing else
3
Step 3 — Use the new rule to split the problem into two cleaner ones.
"House 0 and house n-1 cannot both be robbed" means in any legal plan, at least one of them is skipped. So every legal plan falls into one of two buckets: plans that skip house n-1 (Case A), and plans that skip house 0 (Case B). Some plans skip both — those plans live in both buckets, which is fine. We just need to find the best plan in each bucket and take the bigger one.
→ one hard problem → two simpler sub-problems
4
Step 4 — Inside each case, the circle is gone.
In Case A we've already decided to skip house n-1. The remaining houses are nums[0..n-2], and the only adjacency we still need to honour is the plain linear one (i ↔ i+1). The pair {0, n-1} can never trigger because n-1 is no longer in the picture. So Case A is exactly LC 198 on the sub-array nums[0..n-2]. Case B is the same logic on nums[1..n-1]. We already have the LC 198 code — just pass it the right slice.
→ each case = one call to LC 198's rolling-pair DP
5
Step 5 — Combine and handle the one edge case.
Compute caseA = linearRob(nums, 0, n-2) and caseB = linearRob(nums, 1, n-1), then return max(caseA, caseB). There's one annoying edge case: when n == 1, both slices are empty (the ranges [0, -1] and [1, 0] have no elements), and the helper returns 0 — but the right answer is nums[0]. So short-circuit n == 1 at the top.
→ O(n) time, O(1) memory. Same complexity as LC 198, two passes instead of one.

Step 3

The algorithm in plain English

1
Edge case. If n == 1, return nums[0]. Single house, no circle, no work needed.
2
Case A — exclude the last house. Run linear House Robber on the inclusive range nums[0 .. n-2]: start with prev2 = prev1 = 0, walk the slice left to right, and at each step compute cur = max(prev1, prev2 + nums[i]) then slide prev2 = prev1; prev1 = cur. Save the final prev1 as caseA.
3
Case B — exclude the first house. Same rolling-pair DP, but on the inclusive range nums[1 .. n-1]. Reset prev2 = prev1 = 0 before the loop so Case B doesn't see any leftover state from Case A. Save the final prev1 as caseB.
4
Return max(caseA, caseB).

Step 4

Code

int rob(vector<int>& nums) {
    int n = nums.size();
    if (n == 1) { return nums[0]; }

    // Case A — exclude last house, linear HR on nums[0..n-2]
    int p2A = 0, p1A = 0;
    for (int i = 0; i <= n - 2; i++) {
        int curA = max(p1A, p2A + nums[i]);
        p2A = p1A;
        p1A = curA;
    }

    // Case B — exclude first house, linear HR on nums[1..n-1]
    int p2B = 0, p1B = 0;
    for (int i = 1; i <= n - 1; i++) {
        int curB = max(p1B, p2B + nums[i]);
        p2B = p1B;
        p1B = curB;
    }

    return max(p1A, p1B);
}

Step 7

Corner cases

1
Single house — [5] → 5
The n == 1 short-circuit returns nums[0]. Don't try to run either linear pass — Case A on the range [0, -1] and Case B on [1, 0] are both empty and the rolling pair returns 0, which is wrong. The early return is mandatory.
2
Two houses — [3, 10] → 10
They're adjacent both linearly and on the circle, so we can rob exactly one. Case A on [3] (just index 0) returns 3; Case B on [10] (just index 1) returns 10; the max is 10. The rolling pair works on a single-element slice because the seeds are 0.
3
Triangle — [2, 3, 2] → 3
In a 3-cycle, every pair of houses is adjacent (linearly and via the wrap-around), so any legal plan robs at most one house. Both Case A on [2, 3] and Case B on [3, 2] return 3 (rob the biggest). The two cases tie, which is fine — max handles it without special logic.
4
All same — [4, 4, 4, 4] → 8
In a 4-cycle the optimum robs two opposite houses (indices 0 & 2, or 1 & 3) for a total of 8. Both cases compute 8. Confirms the algorithm finds the alternating pattern even when no house "looks special" — the recurrence does the work.
5
Bait at the endpoints — [100, 1, 1, 100] → 101
This is the example that fails if you mistakenly run linear House Robber on the original array — linear HR happily robs both 100s for a total of 200, but they're adjacent on the circle so that plan is illegal. Case A excludes the last 100 and gets 101 (rob index 0 plus index 2); Case B excludes the first 100 and gets 101 (rob index 1 plus index 3, or index 3 alone — depends on the slice). Either way the answer is 101. If your solution returns 200 on this input, you forgot to split into cases.

Step 8

Production readiness

✓
The n == 1 guard is mandatory — without it, both slices are empty and the helper returns 0 when the right answer is nums[0].
✓
Reset the rolling pair between cases — Case B must start with fresh prev2 = prev1 = 0, not whatever Case A left behind. If you use a helper function this is automatic; if you inline both passes, write it out.
✓
Get the slice bounds right — Case A is the inclusive range [0, n-2], Case B is [1, n-1]. Off-by-ones here silently produce wrong answers on small inputs.
✓
Slide-order bug — same trap as LC 198: write prev2 = prev1 before prev1 = cur, or save the old prev1 into a temp first.
✓
Integer overflow — under the LC constraints (n ≤ 100, nums[i] ≤ 1000) the worst-case sum is 50 000; int is fine. If a variant raises the bounds, switch to long long.
✓
"Just run linear HR" is the canonical bug — explicitly mention the case split to the interviewer to show you spotted the trap. Test on [100, 1, 1, 100] if you're not sure.
✓
Variant awareness — name House Robber I (LC 198) as the reused helper and House Robber III (LC 337, tree variant) as the next step in the family.

Step 9

Approaches — trade-offs

O(n) time O(1) space

A small helper linearRob(nums, lo, hi) runs the LC 198 rolling-pair DP over an inclusive sub-range. The main function handles the n == 1 edge case, calls the helper twice with (0, n-2) and (1, n-1), and returns the max. This is what you'd write on the whiteboard — clear, obviously correct, no duplication.

int linearRob(vector<int>& nums, int lo, int hi) {
    int prev2 = 0, prev1 = 0;
    for (int i = lo; i <= hi; i++) {
        int cur = max(prev1, prev2 + nums[i]);
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}

int rob(vector<int>& nums) {
    int n = nums.size();
    if (n == 1) { return nums[0]; }
    return max(linearRob(nums, 0, n - 2),
               linearRob(nums, 1, n - 1));
}
O(n) time O(1) space

Same algorithm, but with both linear passes spelled out in one function — no helper. Slightly longer, but some interviewers prefer "show all the logic in one place" and it's what the code visualisation above traces. Identical complexity.

int rob(vector<int>& nums) {
    int n = nums.size();
    if (n == 1) { return nums[0]; }

    int p2A = 0, p1A = 0;
    for (int i = 0; i <= n - 2; i++) {
        int curA = max(p1A, p2A + nums[i]);
        p2A = p1A;
        p1A = curA;
    }

    int p2B = 0, p1B = 0;
    for (int i = 1; i <= n - 1; i++) {
        int curB = max(p1B, p2B + nums[i]);
        p2B = p1B;
        p1B = curB;
    }

    return max(p1A, p1B);
}
O(n) time O(1) space

It's possible to compute both cases in a single traversal by carrying two rolling pairs in parallel — one that's allowed to include house 0 (started at i = 0) and one that isn't (started at i = 1). This trades clarity for one fewer loop. Asymptotically the same, harder to read, and rarely worth it. Useful to mention if the interviewer asks "can it be done in one pass?", but two passes is the recommended write-up.

int rob(vector<int>& nums) {
    int n = nums.size();
    if (n == 1) { return nums[0]; }
    // Pair A walks nums[0..n-2]; pair B walks nums[1..n-1]
    int p2A = 0, p1A = 0;
    int p2B = 0, p1B = 0;
    for (int i = 0; i < n; i++) {
        if (i <= n - 2) {
            int curA = max(p1A, p2A + nums[i]);
            p2A = p1A; p1A = curA;
        }
        if (i >= 1) {
            int curB = max(p1B, p2B + nums[i]);
            p2B = p1B; p1B = curB;
        }
    }
    return max(p1A, p1B);
}

Step 10

Complexity

Time
O(n)
Two passes over disjoint sub-ranges of nums, each constant work per element. 2n total operations → O(n).
Space
O(1)
Four scalars in total — two rolling pairs (p2A, p1A, p2B, p1B) — plus a per-iteration temporary. No DP array, no recursion.
