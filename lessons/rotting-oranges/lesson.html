Rotting Oranges

LC #994 Medium Graphs — BFS / DFS

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

Does rot spread diagonally?
No — only to the four orthogonal neighbours (up, down, left, right).
→ a 4-direction neighbour helper, not 8
Do all rotten oranges spread at the same time?
Yes — every rotten orange rots its neighbours simultaneously, each minute.
→ multi-source BFS: every rotten cell is a seed at minute 0
What if there are no fresh oranges at all?
The grid is already done — the answer is 0 minutes.
→ early return when fresh == 0
What if a fresh orange is walled off by empty cells?
It can never rot, so the task is impossible → return -1.
→ check for leftover fresh after the BFS drains

The Insight

Rot spreads in waves — start every rotten orange at once

You probably tried rotting one orange, rescanning the whole grid, then doing it again — and watched it crawl. The fix is to stop thinking one source at a time: every rotten orange spreads simultaneously, so drop them all into one queue and let the rot fan out in synchronized waves, one wave per minute.

The kernel

Seed a BFS queue with every rotten cell at once (multi-source). Each round, pop the entire current layer and rot its fresh orthogonal neighbours, enqueuing them for the next round; one round = one minute. The answer is the number of rounds — or -1 if any fresh orange is still standing when the queue drains.

Step 1

Brute force — feel the cost

The naive simulation rescans the entire grid every minute: for each rotten cell, look at its neighbours, collect the fresh ones, rot them, then repeat the full scan next minute. Each minute costs O(m·n) cell-visits, and the rot can take up to O(m·n) minutes — so the whole thing is O((m·n)²). Watch the cell-scan counter climb.

minute: 0 fresh left: 0 cell-scans: 0

Cost: O((m·n)²) time, O(m·n) space

The whole grid is rescanned every minute even though only the rot frontier changes. The cell-scan counter is the point — each minute re-examines cells that already settled long ago.

int orangesRotting(vector<vector<int>>& grid) {
    int m = grid.size(), n = grid[0].size(), minutes = 0;
    while (true) {
        vector<pair<int,int>> toRot;
        // full rescan of the grid every single minute
        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                if (grid[r][c] != 2) { continue; }
                int dr[] = {1,-1,0,0}, dc[] = {0,0,1,-1};
                for (int d = 0; d < 4; d++) {
                    int nr = r+dr[d], nc = c+dc[d];
                    if (nr>=0 && nr<m && nc>=0 && nc<n && grid[nr][nc]==1) {
                        toRot.push_back({nr,nc});
                    }
                }
            }
        }
        if (toRot.empty()) { break; }
        for (auto& p : toRot) { grid[p.first][p.second] = 2; }
        minutes++;
    }
    for (int r = 0; r < m; r++) {
        for (int c = 0; c < n; c++) {
            if (grid[r][c] == 1) { return -1; }
        }
    }
    return minutes;
}

Step 2

Translations — every optimisation, named

Three swaps turn the quadratic resimulation into a single linear pass over the grid.

1
Per-orange resimulation → one shared queue
Instead of asking "what does each rotten orange do" separately, drop every rotten cell into a single queue and let them all spread together (multi-source BFS).
drops the "which source" outer factor
2
Full grid rescan each minute → process only the frontier
Pop exactly the cells that rotted last minute and rot only their neighbours. Settled cells are never revisited.
O((m·n)²) → O(m·n)
3
"Did anything change?" sentinel → a fresh counter
Count fresh oranges up front and decrement on each rot. Termination and the -1 verdict both read straight off this one integer.
O(1) termination test; -1 case falls out

Step 3

The algorithm in plain English

1
Scan once. Enqueue every rotten cell and count the fresh ones.
2
Short-circuit. If there are no fresh oranges, return 0.
3
Process one layer at a time. While the queue is non-empty and fresh remain, snapshot the current queue size and pop exactly that many cells — the whole current minute's wave.
4
Rot neighbours. For each popped cell, rot its fresh orthogonal neighbours, decrement fresh, and enqueue them for the next layer. After the full layer, do minutes++.
5
Report. When the queue drains, return minutes if fresh == 0, otherwise -1.

Step 4

Code

int orangesRotting(vector<vector<int>>& grid) {
    int m = grid.size(), n = grid[0].size();
    queue<pair<int,int>> q;
    int fresh = 0;
    for (int r = 0; r < m; r++) {
        for (int c = 0; c < n; c++) {
            if (grid[r][c] == 2) { q.push({r, c}); }
            else if (grid[r][c] == 1) { fresh++; }
        }
    }
    if (fresh == 0) { return 0; }
    int minutes = 0;
    int dr[] = {1, -1, 0, 0}, dc[] = {0, 0, 1, -1};
    while (!q.empty() && fresh > 0) {
        int sz = q.size();          // snapshot: this minute's wave
        while (sz--) {
            auto [r, c] = q.front(); q.pop();
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nr >= m || nc < 0 || nc >= n) { continue; }
                if (grid[nr][nc] != 1) { continue; }
                grid[nr][nc] = 2;            // rot it; mutation = visited mark
                fresh--;
                q.push({nr, nc});
            }
        }
        minutes++;
    }
    return fresh == 0 ? minutes : -1;
}

Step 7

Corner cases

1
No fresh oranges
fresh == 0 after the initial scan. Return 0 immediately — never enter the BFS loop, which would otherwise leave minutes at 0 anyway but the early return makes intent explicit.
2
No rotten oranges, but fresh exist
The queue starts empty, so the loop never runs and fresh stays > 0. Return -1 — nothing can ever rot them.
3
Fresh orange sealed off by empties
Like [[2,1,1],[0,1,1],[1,0,1]]: the BFS rots everything reachable, but the orange at (2,0) has only empty neighbours. fresh ends > 0 → -1.
4
Single-cell grids
[[0]] → 0 (no fresh). [[2]] → 0 (no fresh). [[1]] → -1 (a lone fresh orange with no rot source).
5
Everything already rotten
fresh == 0 from the start → 0. The queue may be full of seeds, but the early return fires first.

Step 8

Production readiness

✓
Bounds-check all four neighbours before reading the grid — an out-of-range index is undefined behaviour in C++.
✓
Count fresh up front; the -1 verdict is just "fresh > 0 at the end" — no second full scan needed.
✓
Snapshot the queue size (sz = q.size()) so each loop layer = exactly one minute. Counting per-pop would overcount.
✓
Early-return 0 when fresh == 0 to avoid an off-by-one minute on already-finished grids.
✓
Mutate in place (grid[nr][nc] = 2) — the rot value doubles as the visited marker, so no separate visited set.
✓
minutes is bounded by m·n, so no integer-overflow concerns even on the largest grids.

Step 9

Approaches — trade-offs

O(m·n)O(m·n)

Seed the queue with every rotten cell and expand level by level. Each cell is enqueued at most once; minutes counts the BFS layers. This is the intended solution — simple, linear, and the queue's level structure maps exactly onto "minutes".

O(m·n) amortisedO(m·n)

DFS from each rotten cell, stamping every fresh cell with the earliest minute it could rot (the min over all sources). It works but is fiddlier: a cell may be reached by a later source first and must be re-stamped, so you revisit cells and lose the clean "one layer = one minute" structure BFS gives for free.

// dfs(r,c,t): if t < time[r][c], stamp it and recurse into
// neighbours with t+1. Answer = max stamp - initial, or -1 if
// any fresh cell was never stamped. Re-stamping makes it subtler
// than BFS, with no asymptotic win.
O((m·n)²)O(m·n)

The brute force from Step 1: rescan the whole grid each minute, rot every fresh-adjacent-to-rotten cell, repeat until nothing changes. Correct and easy to reason about, but quadratic because settled regions are re-examined every minute.

Step 10

Complexity

Time
O(m·n)
Each cell is enqueued at most once and its four neighbours inspected a constant number of times.
Space
O(m·n)
The BFS queue can hold up to every cell in the worst case (e.g. a grid that is all rotten at the start).
