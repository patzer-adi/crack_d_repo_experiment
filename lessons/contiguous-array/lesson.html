Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

What is a 'contiguous subarray'?

A contiguous subarray is defined by a start and end index. All elements between (inclusive) must be included.

→ track start and end positions; compute length

If no balanced subarray exists, what do I return?

Return 0 — no array with equal 0s and 1s has been found.

→ answer is always ≥ 0; initialize max_length = 0

Can the input be all 0s, all 1s, or empty?

Yes — the algorithm must handle all edge cases gracefully.

→ initialize the balance map with {0: -1} to handle subarrays from index 0

Do I need to return the indices, or just the length?

Just the maximum length. Return type is an integer.

→ compute (current_index - first_index); track the max

Assumptions we carry forward

Input is an array of 0s and 1s. We want the maximum-length contiguous subarray where count(1) = count(0). If no such subarray exists, return 0. The output is a single integer: the maximum length.

The Insight

Trade 'count-per-subarray' for 'balance-at-position'.

The naive approach checks every subarray and counts its 0s and 1s — O(n²) subarrays times O(n) counting each = O(n³), or with a sliding window O(n²). The key insight: convert the problem. Assign each 1 a value of +1 and each 0 a value of −1. Walk left-to-right and accumulate the balance. Whenever the balance returns to a value we've seen before, the subarray between those two positions has a net balance change of 0, meaning equal 0s and 1s. The length of that balanced subarray is the distance between the two positions.

The kernel

Walk i from 0 to n−1. Keep a hash map first_balance from balance value to the first index where it was seen. Maintain a running balance: for each element, add 1 if it's a 1, subtract 1 if it's a 0. If this balance has been seen before, compute the span and update max_length. Otherwise, record this balance with its current index. The initial entry {0: −1} handles subarrays starting at index 0.

Step 1

Brute force — feel the cost

For each start index i, try every end index j ≥ i; count 0s and 1s in the subarray, and if they're equal, record the length. About n²/2 subarrays to check. Each count is O(n), so total is O(n³), or O(n²) with a running count.

i=—  j=—  ·  zeros: 0  ones: 0  length: 0

Cost: O(n²) time, O(1) space

Two nested loops over n elements. In the worst case (answer at the very end), we check all n(n+1)/2 ≈ n²/2 subarrays. For each we count 0s and 1s in O(n), giving O(n³) total, or O(n²) with a running count. For LC's 10⁴ limit that is up to 5×10⁷ operations — borderline TLE.

int findMaxLength_BF(vector<int>& nums) {
    int n = nums.size();
    int maxLen = 0;
    for (int i = 0; i < n; i++) {
        int zeros = 0, ones = 0;
        for (int j = i; j < n; j++) {
            if (nums[j] == 0) zeros++;
            else ones++;
            if (zeros == ones) {
                maxLen = max(maxLen, j - i + 1);
            }
        }
    }
    return maxLen;
}

Step 2

Translations — every optimisation, named

The brute force asks "are 0s and 1s equal in this subarray?" once per subarray. Two translations turn that into one lookup per element.

1

Translation 1 — Counts → balance

Instead of counting 0s and 1s separately, map 0 → −1 and 1 → +1. Then "equal 0s and 1s" becomes "balance = 0". More generally, if the cumulative balance at two different positions is the same, then the subarray between them has a net balance of 0, hence equal 0s and 1s. The problem now is: for each position, if we've seen its balance before, that's a candidate balanced subarray. Track the maximum length.

→ the problem is now "recurrence of balance values", not "explicit 0-1 equality"

2

Translation 2 — Track first occurrence, in one pass

For each balance value, we want to find the earliest position at which it occurred — to maximise (current_index − earliest_index). Maintain a hash map balance → first_index; at each position, compute the balance and check if we've seen it. If yes, compute the span and update max_length; if no, record this balance with its current index. One pass; each step is O(1) average.

balance = (1s so far) − (0s so far)
if balance in first_balance → span = i − first_balance[balance] · maxLen = max(maxLen, span)
else → first_balance[balance] = i  // record ONCE per balance

→ O(n²) pair-check becomes O(n) hash-map lookup

Why "store first occurrence"

If balance B appears at indices 2, 5, and 9, then subarrays [3, 5], [6, 9], and [3, 9] are all balanced (net balance 0). The longest is [3, 9] with length 9 − 2 = 7 (distance from first to last). So we store only the *first* occurrence; every future match against B uses that same index to compute the span, maximising the result.

Step 3

The algorithm in plain English

1.Initialise a hash map first_balance with entry {0: −1}. This handles subarrays that start at index 0.
2.Set max_length = 0 and balance = 0.
3.Walk i from 0 to n−1.
4.Update balance: if nums[i] == 1, add 1; else subtract 1.
5.If first_balance contains balance, compute span = i − first_balance[balance] and update max_length = max(max_length, span).
6.Else (first time seeing this balance), store first_balance[balance] = i.
7.Return max_length after the loop completes.

Step 4

Code

int findMaxLength(vector<int>& nums) {
    unordered_map<int, int> first_balance;  // balance → first index
    first_balance[0] = -1;                          // handle subarrays starting at 0
    int n = nums.size();
    int maxLen = 0;
    int balance = 0;
    for (int i = 0; i < n; i++) {
        if (nums[i] == 1) balance++;
        else balance--;
        if (first_balance.count(balance)) {
            int span = i - first_balance[balance];
            maxLen = max(maxLen, span);
        } else {
            first_balance[balance] = i;             // store FIRST occurrence
        }
    }
    return maxLen;
}

Step 7

Corner cases

1

All 0s — [0, 0, 0]

balance: −1, −2, −3. No balance ever repeats (except the initial 0 at index −1, but we never return to 0). max_length stays 0. Correct — no subarray has equal 0s and 1s.

2

All 1s — [1, 1, 1]

balance: +1, +2, +3. No repeat. max_length stays 0. Correct.

3

Single element — [0] or [1]

A single element cannot have equal 0s and 1s (one is 0, the other is 0). The algorithm returns 0. Correct.

4

Entire array is balanced — [0, 1, 1, 0]

balance: −1, 0, +1, 0. At i=3, balance is 0 (seen at index −1 initially), so span = 3 − (−1) = 4. Correct.

5

Empty array — []

The loop never runs, max_length stays 0. Correct — an empty array has no balanced subarray (or is trivially balanced with length 0).

6

Why initialise first_balance[0] = −1?

If a subarray from index 0 to j has equal 0s and 1s, its balance at index j is 0. We want to compute span = j − first_position_of_balance_0 = j − (−1) = j + 1, which is the length of the subarray [0, j]. By pre-storing 0 at index −1, we handle this automatically without special-casing.

Step 8

Production readiness

✓

Initialise first_balance[0] = −1: this trick enables handling subarrays starting at index 0 without a special case.

✓

Store first occurrence only: every time you see a balance, check if it's in the map. If not, insert; if yes, compute span and don't overwrite. This maximises the span for each balance value.

✓

Use count() or find(), not operator[]: first_balance[balance] would insert a default value on a miss, corrupting the map. Use count(balance) to check membership safely.

✓

Balance must be a signed integer: balance ranges from −n to +n. Use int or long long depending on input size.

✓

Return max_length, not indices: the output is an integer length, not a pair of indices.

Step 9

Approaches — trade-offs

Time O(n)Space O(n)

The solution taught above. Walk once, maintain a balance map. Optimal time complexity. The space cost (O(n) for the map) buys the O(1) average lookup that makes the linear time possible. In practice, the map size is much smaller than n because repeated balances are expected (the birthday paradox with balance values).

Time O(n²)Space O(1)

Nested loops over all subarrays; count 0s and 1s in each. Correct and simple, but slow. Passes LC's 10⁴ limit with tight constants, but a clear signal of not reaching for the optimal O(n) technique.

Step 10

Complexity

Time

O(n)

One pass; each step does an O(1) average hash probe and potentially an O(1) insert. Worst case is O(n) per step under adversarial hashing, but amortised guarantees on unordered_map give O(n) total in practice.

Space

O(n)

The map stores at most n+1 unique balance values. In practice, many balances repeat (birthday paradox), so the map is often much smaller. No recursion, no stack concerns.

Take home

Related problems that use this pattern

The pattern: scan once with a running prefix value, record when a prefix repeats, and compute spans from the first occurrence. This technique applies to any problem asking for the longest subarray with a property tied to cumulative prefix value.

Key transformation: "count property X and property Y" → "cumulative net value" → "recurrence of net value". The hash map stores (value → first index); on recurrence, compute the span between the two indices.

Related problems:

LC 560 — Subarray Sum Equals K — instead of "balance returns to a previous value", ask "cumulative sum equals K". Same map structure, different recurrence condition.
