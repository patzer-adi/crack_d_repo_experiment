Median of Two Sorted Arrays

LC #4 Hard Binary Search · Arrays

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains the solution.

Can either array be empty?

Yes — e.g. A=[], B=[1,2,3] is valid. One array may have zero elements.

→ boundary sentinels (−∞ / +∞) needed for empty-partition edges

Are both arrays guaranteed sorted?

Yes — both in non-decreasing order. That's the problem's given constraint.

→ sortedness is the invariant that makes binary search on the partition valid

What type should the median be?

double — for even total length, return average of the two middle elements.

→ must use /2.0, not /2, to avoid integer truncation

Can values repeat within or across arrays?

Yes — e.g. A=[0,0] B=[0,0] is valid.

→ duplicates handled naturally; no special case needed

Assumptions we carry forward

Both arrays are non-null and sorted. Total length ≥ 1. No overflow risk for the two-element average: cast to double before dividing. The problem requires O(log(m+n)) time — merging is off the table.

The Insight

The median is a partition. Find the right split — no merge needed.

Before any algorithm: what does the median actually mean? It is the value that splits a sorted sequence into two equal halves — every element on the left is ≤ every element on the right. Find that split across both sorted arrays directly, by binary-searching the partition index in the smaller array; the other index follows from half = ⌊(m+n+1)/2⌋ − i.

The kernel

Binary search on the partition point i in the smaller array. For each candidate i, set j = half − i so both halves together contain exactly ⌊(m+n+1)/2⌋ elements. The partition is correct when max(left_A) ≤ min(right_B) AND max(left_B) ≤ min(right_A). Binary search adjusts i left or right until that invariant holds. The algorithm reads at most O(log min(m,n)) partition-boundary values and never allocates any array.

Step 1

Brute force: merge then pick middle

Two pointers merge both arrays into a new array, then index the middle element(s). Watch the "merged" counter grow — that's what the O(log) approach eliminates.

Cost: O(m+n) time, O(m+n) space

Allocates a new array of m+n elements. The problem statement requires O(log(m+n)) time — this approach is used only to establish a baseline and to make the O(log) speedup feel concrete.

double findMedian_BF(vector<int>& A, vector<int>& B) {
    vector<int> merged;
    int i = 0, j = 0;
    while (i < (int)A.size() || j < (int)B.size()) {
        if (j >= (int)B.size() || (i < (int)A.size() && A[i] <= B[j])) {
            merged.push_back(A[i++]);
        } else {
            merged.push_back(B[j++]);
        }
    }
    int n = merged.size();
    if (n % 2 == 1) { return (double)merged[n / 2]; }
    return (merged[n/2-1] + merged[n/2]) / 2.0;
}

Step 2

Three translations from O(m+n) to O(log min(m,n))

The brute force allocates and scans the entire merged array. Three translations eliminate all of that work.

1

Translation 1 — Build merged array → partition invariant

Instead of building the merged array and finding the median index, find a partition: choose i elements from A and j = half−i elements from B such that every element in the left group is ≤ every element in the right group. When that invariant holds the median is max(left group) for odd total, or (max(left)+min(right))/2 for even. The invariant requires only four boundary values — A[i-1], A[i], B[j-1], B[j] — not the full arrays.

→ reduces problem to: find valid partition (i, j), reading O(1) elements per check

2

Translation 2 — Two free variables → one free variable

i and j are coupled: j = half − i where half = ⌊(m+n+1)/2⌋. Choosing i completely determines j. The search space is [0..m]: i=0 means A contributes nothing to the left half; i=m means all of A is in the left half. Example: m=2, n=2, half=2. Possible values: (i=0,j=2), (i=1,j=1), (i=2,j=0). Only three candidates to check.

→ 2D search collapses to 1D search over m+1 candidates

3

Translation 3 — Linear scan → binary search on i

The partition validity is monotone: if A[i-1] > B[j] the left half has too large a value from A — decrease i. If B[j-1] > A[i] the left half has too large a value from B — increase i. Increasing i always moves A[i-1] up and B[j-1] down (because j decreases). This monotonicity is the binary search condition. Ensure m ≤ n (swap if needed) so that j = half−i is always ≥ 0.

→ O(log(m+1)) steps where m = min(|A|,|B|)

Step 3

The algorithm in plain English

Say this before writing any code.

1.Ensure A is the smaller array. If A.size() > B.size(), swap A and B. This keeps the binary search range [0..m] small and guarantees j = half−i ≥ 0 throughout.
2.Set m=A.size(), n=B.size(), half=(m+n+1)/2. Initialize binary search lo=0, hi=m.
3.Each iteration: compute i=(lo+hi)/2, j=half−i. Read the four boundary values: maxLeft1=A[i-1], minRight1=A[i], maxLeft2=B[j-1], minRight2=B[j] — substituting −∞ at left edges (i=0 or j=0) and +∞ at right edges (i=m or j=n).
4.If maxLeft1 ≤ minRight2 AND maxLeft2 ≤ minRight1: partition correct. For odd (m+n): return max(maxLeft1,maxLeft2). For even: return (max(maxLeft1,maxLeft2) + min(minRight1,minRight2)) / 2.0.
5.If maxLeft1 > minRight2: i is too large — set hi=i−1. Otherwise (maxLeft2 > minRight1): i is too small — set lo=i+1. Repeat from step 3.

Step 4

Canonical C++ solution

Try writing from the five steps above before revealing.

double findMedianSortedArrays(vector<int>& A, vector<int>& B) {
    if (A.size() > B.size()) { swap(A, B); }     // ensure A is smaller
    int m = A.size(), n = B.size();
    int half = (m + n + 1) / 2;
    int lo = 0, hi = m;

    while (lo <= hi) {
        int i = lo + (hi - lo) / 2;
        int j = half - i;

        int mxL1 = (i == 0) ? INT_MIN : A[i-1];
        int mnR1 = (i == m) ? INT_MAX : A[i];
        int mxL2 = (j == 0) ? INT_MIN : B[j-1];
        int mnR2 = (j == n) ? INT_MAX : B[j];

        if (mxL1 <= mnR2 && mxL2 <= mnR1) {
            int mxL = max(mxL1, mxL2);
            int mnR = min(mnR1, mnR2);
            if ((m + n) % 2 == 1) { return (double)mxL; }
            return (mxL + mnR) / 2.0;
        } else if (mxL1 > mnR2) {
            hi = i - 1;               // i too large
        } else {
            lo = i + 1;               // i too small
        }
    }
    return 0.0;                      // unreachable for valid input
}

Step 7

Corner cases

1

One array empty — A=[], B=[1,2,3]

m=0, lo=hi=0. One iteration: i=0, j=2. mxL1=−∞ (sentinel), mnR1=+∞, mxL2=B[1]=2, mnR2=B[2]=3. Invariant holds immediately. Odd total → median = max(−∞, 2) = 2. No special-case code needed.

2

Single element each — A=[2], B=[3]

After swap check: A=[2], B=[3]. m=1, n=1, half=1. i=0,j=1: mxL2=B[0]=3 > mnR1=A[0]=2 → lo=1. i=1,j=0: mxL1=A[0]=2, mnR2=B[0]=3 → invariant holds. Even: (2+3)/2.0 = 2.5.

3

All same value — A=[0,0], B=[0,0]

m=2,n=2,half=2. i=1,j=1: mxL1=0, mnR1=0, mxL2=0, mnR2=0. All boundary values equal — invariant trivially satisfied. Even: (0+0)/2.0 = 0.0.

4

No overlap — A=[1,2], B=[3,4]

i=1,j=1: mxL2=3 > mnR1=2 → lo=2. i=2,j=0: mxL1=A[1]=2, mnR2=B[0]=3, mxL2=−∞ → invariant holds. Even: (2+3)/2.0 = 2.5. All of A ends up in the left half.

5

Integer division for even total

Write (mxL + mnR) / 2.0. With A=[1], B=[2]: mxL=1, mnR=2. Integer division gives (1+2)/2 = 1 (wrong). Floating-point gives (1+2)/2.0 = 1.5 (correct).

Step 8

Production readiness

✓

Empty array: INT_MIN/INT_MAX sentinels handle i==0 or j==0 edges — no bounds check needed anywhere.

✓

Size swap: always swap so A is smaller — guarantees j = half−i ≥ 0 throughout. Without the swap, j can go negative.

✓

Even median division: use (mxL + mnR) / 2.0 — the .0 promotes to double before division.

✓

Sentinel overflow: INT_MIN and INT_MAX are only compared, never added together — no overflow risk.

✓

half formula: use (m+n+1)/2 — the +1 rounds up for odd totals, making the left half the larger half (or equal). Consistent for both odd and even.

✓

Binary search bounds: lo=0 and hi=m (inclusive) — i=0 means A contributes nothing; i=m means A is entirely in the left half. Both extremes are valid and reachable.

Step 9

Approaches

Time O(log min(m,n))Space O(1)

Binary search on the partition point in the smaller array. Reads at most four array elements per iteration. No extra memory beyond the handful of integer variables. The approach shown in this lesson.

Time O(m+n)Space O(m+n)

Merge both arrays using the standard two-pointer merge, then index the middle. Correct but allocates O(m+n) space and does linear work. Useful as a reference implementation for verifying the O(log) solution.

Time O(log(m+n))Space O(log(m+n))

Reframe as "find the kth smallest across two sorted arrays." At each step, compare the k/2-th elements of each array and eliminate the smaller half. Recurse with k halved. Same asymptotic class as the partition approach but uses O(log) stack space and the recursion bookkeeping is trickier to get right under interview pressure.

Step 10

Complexity

Time

O(log min(m,n))

Binary search range is [0..m] where m ≤ n. Each step halves the range. At most ⌈log₂(m+1)⌉ iterations — at most 17 for m ≤ 10⁵.

Space

O(1)

No arrays allocated. Only: m, n, half, lo, hi, i, j, and four boundary values. The swap is a pointer swap, not a copy.

Take home

What to remember for similar problems

The binary search on partition pattern is about searching for a split point that satisfies a cross-structure invariant. Whenever you see "find a position in a sorted structure such that everything to the left is ≤ everything to the right," think partition binary search.

The sentinel trick (−∞ at left edge, +∞ at right edge) eliminates all boundary special-case code. The invariant check becomes uniform: mxL1 ≤ mnR2 && mxL2 ≤ mnR1 — no if-i==0 branches. Use sentinels in any binary search where empty partitions are possible.

The half = (m+n+1)/2 formula (with the +1) is the canonical way to bias the left half to be the same size as or one larger than the right half. This makes the median formula work identically for odd and even totals — just always compute max(left) and min(right) and decide based on parity.

Related: LC 4 generalization — kth smallest in two sorted arrays (replace half with k); LC 410 (Split Array Largest Sum — binary search on the answer, monotone feasibility check); LC 875 (Koko Eating Bananas — binary search on a monotone predicate, same structure as checking the partition invariant).
