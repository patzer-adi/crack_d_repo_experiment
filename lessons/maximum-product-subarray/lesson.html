Maximum Product Subarray

LC #152 Medium Dynamic Programming

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer constrains what the solution needs to handle.

Q: Must the subarray be contiguous?

A: Yes — a subarray, not a subsequence. Elements between picks cannot be skipped.

→ unlocks: at each index we only choose "extend the previous run" or "start fresh here", enabling a single linear scan

Q: Can numbers be negative or zero?

A: Yes — -10 ≤ nums[i] ≤ 10. The whole point of the problem.

→ unlocks: a negative can flip a tiny min into a huge max — tracking only the running max would miss the flip

Q: Is the array guaranteed non-empty?

A: Yes — 1 ≤ n ≤ 2·10⁴.

→ unlocks: seed both running variables and the answer with nums[0]; no empty-array guard needed

Q: Does the answer fit in a 32-bit int?

A: Yes — the problem guarantees every prefix product fits.

→ unlocks: plain int in C++ is enough; no long long or BigInt gymnastics

Assumptions we carry forward

Contiguous subarray of a non-empty array of small signed integers (zeros allowed). Linear single-pass DP is feasible; the optimisation insight is what we carry between indices.

The Insight

A negative number isn't a dead end — it's a flipper. Carry the smallest product, not just the biggest.

Whatever the optimal subarray ending at index i looks like, multiplying it by a negative nums[i+1] would invert its sign — so today's worst product can become tomorrow's best. Carry both the running max and the running min from index to index.

The kernel

cur_max[i] = max(nums[i], nums[i]·cur_max[i−1], nums[i]·cur_min[i−1])
cur_min[i] = min(nums[i], nums[i]·cur_max[i−1], nums[i]·cur_min[i−1])
Three candidates per index: restart at nums[i], extend the previous best, extend the previous worst. Snapshot both before either is overwritten — order matters when nums[i] < 0.

Cost: O(n²) time, O(1) space

Two nested loops touch every (i, j) pair, multiplying out the running product. The checks counter makes that quadratic blow-up visible — for n = 2·10⁴ the inner work is on the order of 4·10⁸ multiplications.

int maxProduct(vector<int>& nums) {
    int n = nums.size();
    int best = nums[0];
    for (int i = 0; i < n; i++) {
        int prod = 1;
        for (int j = i; j < n; j++) {
            prod *= nums[j];
            if (prod > best) { best = prod; }
        }
    }
    return best;
}

Step 2

Translations — every optimisation, named

The O(n²) brute force redoes work: the product of nums[i..j] is just the product of nums[i..j−1] times nums[j]. Below are the named steps that collapse the two loops into one.

1
Best subarray product ending at i → running variable cur_max
Instead of revisiting all j ≤ i starting points, carry the best product that ends exactly at i. Either restart at nums[i] or extend the previous best: cur_max = max(nums[i], nums[i]·prev_max).
→ O(n²) products → O(n) — one pass, one variable
2
Worst subarray product ending at i → also carry cur_min
A negative nums[i] turns the previous min into a new max. So at every index, three candidates compete: nums[i], nums[i]·prev_max, nums[i]·prev_min. Pick the largest for cur_max, the smallest for cur_min.
→ correctness restored under negatives; still O(n) time, O(1) extra space
3
Snapshot before overwrite
Compute both cur_max and cur_min from the previous step's values before assigning either. If you assign cur_max first and then use it inside the cur_min expression, you've used a stale-but-now-wrong value — and the bug only surfaces when nums[i] < 0.
→ removes the subtle ordering bug; same complexity, correct under all signs

Step 3

The algorithm in plain English

1
Seed cur_max = cur_min = best = nums[0].
2
For each i from 1 to n−1, let x = nums[i].
3
Compute the three candidates: x, x·cur_max, x·cur_min.
4
Set the new cur_max to the largest of the three and the new cur_min to the smallest. Both must be derived from the old values — snapshot before overwriting either.
5
Update best = max(best, cur_max).
6
Return best.

Step 4

Code

int maxProduct(vector<int>& nums) {
    int cur_max = nums[0];
    int cur_min = nums[0];
    int best = nums[0];
    for (int i = 1; i < (int)nums.size(); i++) {
        int x = nums[i];
        int a = x * cur_max;
        int b = x * cur_min;
        int new_max = max(x, max(a, b));
        int new_min = min(x, min(a, b));
        cur_max = new_max;
        cur_min = new_min;
        if (cur_max > best) { best = cur_max; }
    }
    return best;
}

Step 7

Corner cases

1
Single element — nums = [-3]
Loop body never runs. Seed already sets best = nums[0] = -3. Return -3. Be sure not to start best at 0 or INT_MIN — an all-negative array would silently report the wrong answer.
2
All negatives, even count — nums = [-2,-3,-4]
Answer is 12 = (-3)·(-4). cur_min becomes a huge magnitude after the first product, then the next negative flips it into the new cur_max. Demonstrates why both running variables are necessary.
3
Zero in the middle — nums = [-2,0,-1]
At i=1, all three candidates collapse to 0: cur_max = cur_min = 0. The running products restart cleanly from nums[i+1]. Answer is 0 here because no non-zero contiguous subarray beats it.
4
Snapshot bug — assigning cur_max before computing cur_min
If you write cur_max = max(x, x·cur_max, x·cur_min); cur_min = min(x, x·cur_max, x·cur_min); the second line uses the just-overwritten cur_max. On [-2,3,-4] that yields -12 instead of 24. Always compute both new_max and new_min from the old values first.
5
Tracking only running max — the classic trap
On nums = [-2,-3] a max-only Kadane returns -2; the optimum is 6. The instant two negatives can meet, ignoring the running min is wrong. This is the entire reason the problem isn't a straight Kadane copy.

Step 8

Production readiness

✓
Single-element array — seed best = nums[0] so a one-element negative still returns correctly.
✓
All-negative input — never initialise best to 0; the answer can be negative.
✓
Zero handling — three candidates collapse to 0 on a zero element; both running variables reset naturally. No special branch needed.
✓
Snapshot discipline — compute new_max and new_min from the previous values before assigning either; never re-read mid-update.
✓
Integer overflow — the problem guarantees products fit in int; for unconstrained inputs use long long for the running products.
✓
Loop bounds — outer index runs from 1 to n−1; index 0 is the seed, not the first iteration.
✓
Constant extra space — only three ints carried across the loop; safe at any input size.

Step 9

Approaches — trade-offs

O(n) O(1)

Single linear pass with two running variables and a global best. Constant space, branch-free body, no recursion. This is the canonical interview answer.

int maxProduct(vector<int>& nums) {
    int cur_max = nums[0], cur_min = nums[0], best = nums[0];
    for (int i = 1; i < (int)nums.size(); i++) {
        int x = nums[i];
        int a = x * cur_max, b = x * cur_min;
        int nm = max(x, max(a, b));
        int nn = min(x, min(a, b));
        cur_max = nm; cur_min = nn;
        if (cur_max > best) { best = cur_max; }
    }
    return best;
}
O(n²) O(1)

Two nested loops compute the running product of every nums[i..j] and track the max. Conceptually simplest; quadratic time makes it infeasible at the upper input bound. Useful as a "feel the cost" baseline in interviews.

int maxProductBrute(vector<int>& nums) {
    int n = nums.size(), best = nums[0];
    for (int i = 0; i < n; i++) {
        int p = 1;
        for (int j = i; j < n; j++) {
            p *= nums[j];
            if (p > best) { best = p; }
        }
    }
    return best;
}
O(n) O(1)

Multiply left-to-right, resetting to 1 on every zero; multiply right-to-left the same way; answer is the maximum across both passes. Same asymptotic, no min-tracking — the trick is that the optimal subarray's product is captured by one of the two scan directions because negatives in between flip the sign an even number of times overall.

int maxProductTwoPass(vector<int>& nums) {
    int n = nums.size(), best = nums[0], p = 1;
    for (int i = 0; i < n; i++) {
        p *= nums[i];
        if (p > best) { best = p; }
        if (p == 0) { p = 1; }
    }
    p = 1;
    for (int i = n - 1; i >= 0; i--) {
        p *= nums[i];
        if (p > best) { best = p; }
        if (p == 0) { p = 1; }
    }
    return best;
}

Step 10

Complexity

Time
O(n)
Exactly one pass over the array; constant work per index (three multiplications, three comparisons).
Space
O(1)
Three running ints — cur_max, cur_min, best — plus a couple of temporaries. No auxiliary array.
