**Created:** 2026-05-07

## 1. Context & motivation

PLAN-001 established the project skeleton. Nothing else can be validated until the core
value loop runs end-to-end at least once:

```
skill files + plan.md  →  Claude in VS Code  →  lesson.html  →  browser
```

3Sum (LC #15, Arrays, Medium) is the right POC problem because:
- The user already has a reference 3Sum HTML lesson as the quality bar.
- It naturally uses two key skills — **Array** (DS) + **Two Pointers** (pattern) — that will
  reappear in the most problems on the prep list.
- It has two distinct approaches (Sort + Two Pointers; HashSet), so it exercises the
  multi-approach tab structure from the start.

This plan produces three hand-authored source files and one Claude-generated output file.
**No Python code, no dashboard, no server.** If the generated lesson does not meet the quality
bar, we iterate on the skill files and plan.md before touching any tooling.

Per the spec architectural principle: *POC before tooling. Skill files are validated only
when a second problem uses them unchanged.*

## 4. Approach

### 4.1 Skill file format

Both skill files follow this fixed four-section template (enforced by spec §Feature 5):

```markdown
# [DS or Pattern Name] — Skill File

## What it is
One paragraph: the concept, when it appears, why it matters for interviews.

## Visual convention
Precise description of how to draw/render this DS or pattern in an HTML lesson.
Include: element shape, labels, colours, pointer/marker style, layout direction.
This section must be specific enough that two independently generated lessons
look identical for the same input.

## Animation rules
How state changes are shown step by step:
- What changes between frames
- What gets highlighted / greyed out / labelled
- Timing and sequencing conventions (e.g. "pointer moves before comparison label appears")

## Common pitfalls
Bullet list of mistakes to avoid in the lesson HTML — both visual (wrong index label
position) and conceptual (skipping duplicate-avoidance logic in the animation).
```

### 4.2 Content for `skills/ds/array.md`

**What it is:** A contiguous, zero-indexed sequence of elements. Appears in the majority of
interview problems. Visually the simplest DS; the foundation on which pointer, window, and
prefix patterns are drawn.

**Visual convention:**
- Each element: a fixed-width square box (min 40 px wide).
- Index label: shown **above** each box in a smaller muted font (grey, e.g. `#888`).
- Value: centred inside the box, bold.
- Active / highlighted element: box background changes to accent colour (e.g. `#3b82f6` blue).
- Processed / eliminated range: box background grey (`#d1d5db`), value muted.
- Pointer marker: a small labelled triangle or arrow **below** the box, coloured per pointer
  (e.g. `L` in blue, `R` in red). Label is the variable name, not the index value.
- Layout: always left-to-right, horizontal, single row unless the problem explicitly uses
  a 2-D grid (separate skill file).

**Animation rules:**
- Each animation step is a discrete frame (button-driven or auto-play with pause).
- A step shows: previous state → highlight active element(s) → move pointer(s) → label the
  decision taken (e.g. "sum < target → move L right").
- Pointer movement: marker slides to the new position; the old position fades out in the
  same frame.
- When a range is "locked in" or "eliminated", grey it out before moving to the next frame.
- Show the current sum / result value in a side panel next to the array, updated each step.

**Common pitfalls:**
- Index labels start at 0, not 1. Never omit the index row.
- Pointer label must show the variable name (`left`, not `0`). Showing the index value only
  confuses problems where the pointer skips indices.
- Do not move both pointers in the same animation frame — show one move at a time.
- Do not skip the duplicate-avoidance step in problems like 3Sum; animate `while nums[L] == nums[L-1]: L++` explicitly.

### 4.3 Content for `skills/patterns/two_pointers.md`

**What it is:** Two index variables (`left`/`right`, or `i`/`j`) scanning the same array
from opposite ends (or both from left). Used when a brute-force O(n²) comparison can be
collapsed to O(n) by exploiting sort order or a monotonic property. Canonical problems:
Two Sum II, 3Sum, Container With Most Water, Trapping Rain Water.

**Visual convention:**
- Render the array using `skills/ds/array.md` conventions (boxes, index labels above).
- `left` pointer: blue triangle below the box, labelled `L`.
- `right` pointer: red triangle below the box, labelled `R`.
- The pair under consideration: both boxes highlighted in their respective pointer colour.
- When the pair produces a result (match, sum = target, area computed): show a brief
  "✓ found" or result annotation above the boxes before moving on.
- When a pointer is skipped for duplicate avoidance: show a dashed arrow from old to new
  position, labelled "skip dup".

**Animation rules:**
- Frame 0: show the sorted array (or explain why it is already sorted), both pointers at
  initial positions (`L=0, R=n-1` for inward sweep).
- Each frame: show the current pair, compute the relevant value (sum, area, etc.), then
  show the decision label *before* the pointer moves.
  Decision labels: `sum < target → move L →`, `sum > target → ← move R`, `sum == target → record`.
- Never move a pointer without showing the decision that caused the move.
- Duplicate skip frames: one frame per skip step, not collapsed into one jump.
- Final frame: show all results collected (e.g. the set of triplets), both pointers
  at their terminal position.

**Algorithmic template (include in lesson code tab):**
```
sort(nums)
for i in range(len(nums) - 2):
    if i > 0 and nums[i] == nums[i-1]: continue   # skip outer dup
    L, R = i+1, len(nums)-1
    while L < R:
        s = nums[i] + nums[L] + nums[R]
        if s == 0:   result.append(...); skip inner dups on L and R
        elif s < 0:  L += 1
        else:        R -= 1
```

**Common pitfalls:**
- Forgetting that the array must be sorted first — the animated dry run must show the sort
  step before the pointer sweep.
- Animating both pointers moving in the same frame.
- Not showing the outer-loop duplicate skip (`if i > 0 and nums[i] == nums[i-1]`).
- Showing the pointer label as the index value (e.g. `1`) instead of the variable name
  (`L`) — breaks comprehension when the pointer jumps.

### 4.4 Content for `lessons/3sum/plan.md`

The plan.md that Claude in VS Code will read. It must be self-contained — Claude should not
need to ask any questions after reading it.

```markdown
# Lesson Plan: 3Sum (LC #15)

## Problem
- **Name:** 3Sum
- **Number:** 15
- **Link:** https://leetcode.com/problems/3sum/
- **Difficulty:** Medium
- **Topic:** Arrays

## Data structures & patterns
- **DS:** Array → load `skills/ds/array.md`
- **Pattern:** Two Pointers → load `skills/patterns/two_pointers.md`
- **Secondary pattern:** Sorting (in-place, as prerequisite to two-pointer sweep)

## Skill files to load into context
1. `skills/ds/array.md`
2. `skills/patterns/two_pointers.md`

## Output file
`lessons/3sum/lesson.html` — self-contained, offline-capable, no CDN dependencies.

## Lesson sections (produce all of these)

### 1. Intuition
Why does sorting + two pointers work?
- Brute force is O(n³): fix i, fix j, scan for k. Too slow.
- Sorting lets us use a monotonic property: if sum < 0, move left pointer right (increases
  sum); if sum > 0, move right pointer left (decreases sum). This collapses the inner O(n²)
  to O(n).
- Key insight: after sorting, for a fixed outer element nums[i], the remaining two elements
  can be found in O(n) — not O(n²).
- Duplicate avoidance: skip repeated values at the outer and inner pointer positions to avoid
  producing the same triplet twice.

### 2. Animated dry run
Input: `[-1, 0, 1, 2, -1, -4]`
After sort: `[-4, -1, -1, 0, 1, 2]`

Walk through:
- i=0, nums[i]=-4: L=1 (−1), R=5 (2). sum=−3 < 0 → move L. … no triplet found.
- i=1, nums[i]=−1: L=2 (−1), R=5 (2). sum=0 → record [−1,−1,2]; skip inner dups → L=3,R=4. sum=0 → record [−1,0,1]; … 
- i=2: skip (nums[2]==nums[1]).
- i=3, nums[i]=0: L=4 (1), R=5 (2). sum=3 > 0 → move R. L≥R, stop.

Use the array.md visual (boxes, index labels) and two_pointers.md visual (L/R markers).
Show each step as a discrete animation frame with decision label.

### 3. Corner cases
| Case | Input | Expected | Why |
|---|---|---|---|
| Empty / too short | `[]`, `[0]`, `[1,2]` | `[]` | Need ≥ 3 elements |
| All zeros | `[0,0,0]` | `[[0,0,0]]` | Valid; duplicate-skip must not skip this |
| No valid triplet | `[1,2,3,4]` | `[]` | All positive; L+R always > 0 after sort |
| All duplicates | `[-1,-1,-1,-1]` | `[]` | sum = −3 ≠ 0; duplicate-skip fires |
| Target not reachable | `[-4,-1,-1,0,1,2]` | `[[-1,-1,2],[-1,0,1]]` | Baseline example |

Animate the "all zeros" case — it trips up naive duplicate-skip implementations.

### 4. Code (revealed after attempt)
Show the canonical Sort + Two Pointers solution in Python.
Include line-by-line comments keyed to the animation steps.
Use a "Reveal Code" toggle — code hidden by default.

### 5. Approaches (two tabs)
**Tab 1 — Sort + Two Pointers (primary)**
Time: O(n log n + n²) = O(n²). Space: O(1) or O(n) for output.
This is the canonical approach and the one animated in full.

**Tab 2 — HashSet**
Time: O(n²). Space: O(n).
For each pair (i, j), check if −nums[i]−nums[j] exists in a set.
Build the set from nums. Use a frozenset result set to avoid duplicates.
Provide code and a brief text walkthrough — no full animation needed for tab 2.

## Quality bar
Match the visual quality of the existing 3Sum reference lesson. Specifically:
- Smooth step-by-step animation (button controls or auto-play with pause/restart)
- Array rendered per `skills/ds/array.md` (boxes, index labels above, pointer markers below)
- Decision labels shown between pointer positions
- Corner cases section is interactive (click a case to see a mini dry run or explanation)
- Code is syntax-highlighted and hidden behind a "Reveal" toggle
- Tab switching between approaches is instant, no page reload
```

## 6. Risks & mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Claude generates a lesson that ignores the skill file visual conventions | Medium | High | Plan.md explicitly names each skill file and says "use the visual conventions in the skill files". If it still ignores them, add a more specific constraint line to plan.md and regenerate. |
| Animation is too complex for a single HTML file (janky, broken) | Low | Medium | Simplify the animation to pure CSS transitions + JS state machine; no canvas, no third-party animation lib. Flag in plan.md. |
| Lesson has CDN dependencies (fails offline) | Medium | High | Verification step 7 explicitly tests offline. If it fails, ask Claude to inline all dependencies and regenerate. |
| Duplicate-avoidance animation is wrong (shows incorrect skip) | Medium | Medium | Corner case §3 of the plan specifies the "all zeros" case precisely; include it in the quality review checklist. |
| Lesson is too long to load quickly in VS Code preview | Low | Low | View it in the system browser, not the VS Code WebView. |
| The reference 3Sum HTML is not accessible to compare | Low | Medium | User to confirm the reference file is available before task 8. |
