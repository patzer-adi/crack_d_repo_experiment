Algorithm Lesson

Breadth-First Search (BFS)

Graph Algorithms Tier 1 · primer O(V + E) time · O(V) space

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer decides whether BFS is even the right tool.

Do the edges have weights?
No — every edge costs 1 step.
→ BFS gives shortest paths. With real weights you need Dijkstra.
Is the graph directed or undirected?
Undirected here — an edge can be walked both ways.
→ each edge goes into two adjacency lists, not one
Is every node reachable from the start?
No. The graph can come in separate pieces.
→ unreachable nodes keep distance -1; never assume all are visited
Do we need the route, or only how far?
Only the distance.
→ one dist array is enough. Add a parent array to rebuild the route.

The Insight

A queue turns the search into rings, and the ring is the answer

Finding the shortest route feels like it needs comparing routes. It does not. A queue hands nodes back in the order they were reached, so you leave the start, then touch everything one step away, then everything two steps away — never skipping ahead. The first time you touch a node, you are already there by the shortest route.

not reached yet this ring distance fixed
Why the ring number is already the shortest distance:
1
The queue never lets you jump a ring
Nodes go in at the back and come out at the front. Everything at distance 1 was queued before anything at distance 2, so it all comes out first. The order out is sorted by distance without ever sorting anything.
2
First arrival wins, permanently
Suppose a node is first reached in ring 3. A shorter route would have reached it in ring 1 or 2 — but those rings are already empty. No shorter route exists, so there is nothing to compare and nothing to update later.
3
One array does two jobs
Because distances are final on first touch, "has a distance" and "already visited" are the same question. The dist array is also the visited set, so there is no second structure to keep in sync.

The kernel

Push the source with distance 0. Repeatedly pop a node and give every unlabelled neighbour a distance one greater, pushing it to the back. The queue guarantees nodes come out in non-decreasing distance order, so the label written on first contact is already the shortest distance and never changes.

Step 1

Brute force — feel the cost

If you did not know the ring trick you would do the obvious thing: walk every route out of the source, and for each node remember the shortest walk that ever reached it. It is correct, because the shortest route never repeats a node. It is also hopeless — the number of routes grows like the factorial of the node count. Watch the "routes walked" counter on a graph with six nodes.

routes walked: 0 current route: —

Cost: O(V!) time in the worst case

Every node is re-entered once per route that reaches it. The same short prefix is re-walked over and over, and the answer for a node is only trusted after every route has finished. BFS throws all of that away.

// Walk every simple route out of src; keep the shortest length per node.
void walk(int u, int len, vector<int>& best,
          vector<bool>& onPath, vector<vector<int>>& adj) {
    onPath[u] = true;
    if (len < best[u]) { best[u] = len; }
    for (int v : adj[u]) {
        if (onPath[v]) { continue; }   // no repeats on one route
        walk(v, len + 1, best, onPath, adj);
    }
    onPath[u] = false;             // back out and try another route
}

Step 2

Translations — every optimisation, named

Three swaps take the route walk from factorial down to linear.

1
Walk every route → expand one ring at a time
Stop following routes to the end. Grow the reached set outwards by one edge per round, so each node is entered once instead of once per route through it.
O(V!) → O(V + E)
2
Compare route lengths → trust the first arrival
The queue hands nodes back in distance order, so the first route that reaches a node is already the shortest. No minimum to track, no value to revise.
removes the per-node comparison entirely
3
Separate visited set → the distance array itself
Since a distance is written exactly once, "dist[v] is still -1" means "never reached". One array answers both questions and they cannot fall out of sync.
one array instead of two

Step 3

The algorithm in plain English

1
Set up. Give every node distance -1, meaning "not reached". Set the source to 0 and push it into the queue.
2
Take the front node u off the queue. Its distance is already final — nothing later can improve it.
3
Look at each neighbour v. If dist[v] is not -1 it already has a shorter or equal distance, so skip it.
4
Claim the new ones. Set dist[v] = dist[u] + 1 and push v to the back of the queue, so it is handled after everything in the current ring.
5
Stop when the queue empties and return dist. Any node still holding -1 cannot be reached from the source.

Step 4

Code

C++ first — that is the version the walkthrough below animates. The Python version is the same algorithm with the noise removed; read it if the C++ obscures the shape.

vector<int> bfs(int n, vector<vector<int>>& adj, int src) {
    vector<int> dist(n, -1);        // -1 = not reached
    queue<int> q;
    dist[src] = 0;
    q.push(src);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int v : adj[u]) {
            if (dist[v] != -1) { continue; }   // already final
            dist[v] = dist[u] + 1;
            q.push(v);
        }
    }
    return dist;
}
from collections import deque

def bfs(n, adj, src):
    dist = [-1] * n
    dist[src] = 0
    q = deque([src])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] != -1:
                continue
            dist[v] = dist[u] + 1
            q.append(v)
    return dist

Step 7

Corner cases

1
The graph is in pieces
One BFS only covers the source's own component. Nodes elsewhere keep -1. If the task is "visit everything", wrap the BFS in a loop that starts a fresh one from each node still holding -1.
2
Cycles
A cycle is harmless because a node is labelled once. Without the dist[v] != -1 guard the queue would refill forever. In the 4-cycle example node 3 gets distance 1 directly, not 3 the long way round.
3
Mark on push, not on pop
The most common bug. If you only set dist when a node comes off the queue, the same node can be pushed several times before its first pop, and the queue blows up to O(E). Label it the moment you push it.
4
Self-loops and repeated edges
Both are absorbed by the same guard: the node already has a distance, so it is skipped. No special handling needed.
5
A weighted graph
BFS is simply wrong here — it counts edges, not weight. If all weights are 0 or 1 use 0-1 BFS with a deque; otherwise use Dijkstra.

Step 8

Production readiness

✓
Label on push. Set dist[v] at the moment you enqueue v, so a node can never sit in the queue twice.
✓
Use a real queue. std::queue or a two-index ring buffer. Popping from the front of a vector is O(V) per pop and turns the whole thing quadratic.
✓
Build the adjacency list once before the search, in O(V + E). Scanning an edge list inside the loop is the usual accidental O(V·E).
✓
Return -1, not infinity, for unreachable nodes — and say so at the call site. Silent 0 for "unreachable" is a bug waiting to happen.
✓
Iterative, never recursive. BFS has no recursive form, which is exactly why it is safe on graphs deep enough to blow a call stack.
✓
Multi-source is free. Push every source at distance 0 before the loop and the answer becomes "distance to the nearest source" — no other change.

Step 9

Approaches — trade-offs

O(V + E)O(V)

The version above. One flat queue, one distance array, no notion of a "round". Use it whenever you want the distance number itself. This is the default and the one to write in an interview.

O(V + E)O(V)

Same cost, but the outer loop snapshots q.size() and drains exactly that many nodes, so each iteration is exactly one ring. Use it when the ring boundary matters and the distance number does not — printing a tree level by level, or counting minutes in a grid simulation.

while (!q.empty()) {
    int sz = q.size();        // this whole ring, and no more
    while (sz--) {
        int u = q.front(); q.pop();
        // ... push unlabelled neighbours ...
    }
    depth++;                 // one ring finished
}
O(V + E)O(V)

Swap the queue for a stack and you get DFS — same cost, but it dives down one branch before spreading. It answers reachability, cycles, and topological order well. It does not give shortest distances: the first route DFS finds to a node is usually not the shortest, so a distance written on first contact would be wrong.

Step 10

Complexity

Time
O(V + E)
The guard lets each node be pushed at most once, so there are V pops. Each pop scans that node's list, and across the run every edge is scanned from both ends — 2E work in total.
Space
O(V)
The distance array is V entries and the queue holds at most V nodes at once, since no node is ever enqueued twice.

Take home

LeetCode problems that are this algorithm

LC 102 — Binary Tree Level Order Traversal: the level-by-level variant, on a tree. Snapshot q.size() to cut the rings apart.

LC 994 — Rotting Oranges: BFS on a grid with many sources at once. Every rotten cell starts at distance 0, and the ring number is the minute.

LC 542 — 01 Matrix: multi-source BFS from every zero. The distance array is the answer grid.

LC 127 — Word Ladder: the graph is implicit — nodes are words, edges are one-letter changes. Same BFS, built on the fly.

The trick to carry: the moment a problem says "fewest steps" or "shortest" and every step costs the same, it is BFS. Your only real job is deciding what a node is.
