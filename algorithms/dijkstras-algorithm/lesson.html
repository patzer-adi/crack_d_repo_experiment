Dijkstra's Algorithm

Graph Algorithms Tier 1 · primer O((V + E) log V) time · O(V) space

Before you code

Clarifying questions to ask first

Ask these before writing anything. The first one decides whether Dijkstra is allowed at all.

Can any weight be negative?
No — all weights are zero or more.
→ this is the precondition the whole algorithm rests on. One negative edge and you need Bellman-Ford.
Directed or undirected?
Undirected here.
→ every edge is relaxed from both ends
Is every node reachable?
Not necessarily.
→ unreachable nodes stay at infinity; report -1 rather than 0
Cost only, or the actual route?
Cost only.
→ one dist array. A parent array would rebuild the route for free.

The Insight

The cheapest node on the frontier is already finished

BFS works because every edge costs 1, so arrival order is cost order. Weights break that — two cheap edges can beat one expensive edge. Dijkstra repairs it by taking the cheapest unsettled node instead of the earliest. Since no edge ever lowers a running total, nothing found later can undercut it.

unreached (cost ∞) on the frontier — cost is a guess cheapest guess → settle it now settled, cost final
Why the cheapest guess can be trusted:
1
Any other route must leave through the frontier
To reach node u by some route we have not considered, that route has to step outside the settled set at some point — and the first such step lands on a frontier node.
2
That detour already costs at least as much
We picked u because its guess is the smallest on the frontier. So the alternative route has already spent at least as much just getting to its own frontier node, before going any further.
3
And the rest of the detour cannot refund it
This is where non-negative weights earn their keep. Extra edges can only add. With a negative edge the tail of a detour could pay the difference back, the argument collapses, and Dijkstra returns wrong answers.

The kernel

Keep a best-known cost per node and always settle the cheapest unsettled one. Any competing route must exit through the frontier, where it has already spent at least as much, and non-negative weights mean the rest of that route can only add. So the cheapest guess is final the moment it is chosen.

Step 1

Brute force — feel the cost

The obvious method is to walk every route that never repeats a node and keep the cheapest total that reaches each one. It is correct — a cheapest route never revisits a node when weights are non-negative — but the route count grows factorially. Watch the counter on a five-node graph.

routes walked: 0 current route: — cost: 0

Cost: O(V!) time in the worst case

Every route through a node is walked separately, and each one re-pays for the prefix it shares with all the others. Dijkstra settles each node once and never revisits it.

// Walk every simple route; keep the cheapest total per node.
void walk(int u, long long cost, vector<long long>& best,
          vector<bool>& onPath, vector<vector<pair<int,int>>>& adj) {
    onPath[u] = true;
    if (cost < best[u]) { best[u] = cost; }
    for (auto& [v, w] : adj[u]) {
        if (onPath[v]) { continue; }        // no repeats on one route
        walk(v, cost + w, best, onPath, adj);
    }
    onPath[u] = false;                  // back out, try another route
}

Step 2

Translations — every optimisation, named

Three swaps take the route walk down to a heap-driven single pass.

1
Walk every route → keep one best cost per node
A node does not need its history, only its cheapest known total. Shared prefixes are then paid for once instead of once per route through them.
O(V!) → polynomial
2
Scan all nodes for the cheapest → a min-heap
Finding the smallest unsettled distance by scanning costs O(V) each round. A priority queue hands it over in O(log V).
O(V²) → O((V + E) log V)
3
Decrease-key → push a duplicate, skip stale pops
Standard heaps cannot cheaply lower a key. Push the improved pair instead and, on pop, discard any entry whose stored cost no longer matches dist[u].
plain heap, one extra comparison

Step 3

The algorithm in plain English

1
Set up. Every distance starts at infinity except the source, which is 0. Push (0, src) onto a min-heap.
2
Pop the cheapest pair (d, u). If d > dist[u] this is a stale copy left over from an earlier, worse guess — throw it away.
3
Settle u. Its distance is final and will never be touched again.
4
Relax its edges. For each (u, v, w), if dist[u] + w beats dist[v], write the better value and push (dist[v], v).
5
Stop when the heap empties. Anything still at infinity is unreachable — report it as -1.

Step 4

Code

C++ first — that is the version the walkthrough below animates. Note the stale-pop guard on line 8; without it the algorithm is still correct but does redundant work.

vector<long long> dijkstra(int n, vector<vector<pair<int,int>>>& adj, int src) {
    const long long INF = LLONG_MAX;
    vector<long long> dist(n, INF);
    priority_queue<pair<long long,int>,
                   vector<pair<long long,int>>, greater<>> pq;
    dist[src] = 0;
    pq.push({0, src});
    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();
        if (d > dist[u]) { continue; }        // stale copy
        for (auto& [v, w] : adj[u]) {
            if (d + w < dist[v]) {
                dist[v] = d + w;
                pq.push({dist[v], v});
            }
        }
    }
    return dist;
}
import heapq

def dijkstra(n, adj, src):
    INF = float('inf')
    dist = [INF] * n
    dist[src] = 0
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        for v, w in adj[u]:
            if d + w < dist[v]:
                dist[v] = d + w
                heapq.heappush(pq, (dist[v], v))
    return dist

Step 7

Corner cases

1
A negative edge
Dijkstra returns a wrong answer and gives no warning. Settling a node assumes no later route can be cheaper, and a negative edge can make one cheaper. If negatives are possible, use Bellman-Ford — do not "fix" Dijkstra by adding a constant to every weight, which changes which route is shortest.
2
Unreachable nodes
They are never pushed, so they keep the sentinel. Report -1 or infinity — never 0, which reads as "already there".
3
Stale heap entries
A node can sit in the heap several times with different guesses. The d > dist[u] check discards the outdated copies. Without it the code still gives the right answer but re-relaxes edges it did not need to.
4
Overflow on the sentinel
dist[u] + w where dist[u] == LLONG_MAX wraps around and can look like an improvement. Either guard with if (dist[u] == INF) continue; or use a sentinel that leaves headroom, such as 4e18.
5
Zero-weight edges
Perfectly fine — the proof only needs weights that are not negative. Ties settle in an arbitrary order and the distances come out the same.

Step 8

Production readiness

✓
Assert weights are non-negative at the boundary, or document it loudly. This is the failure that produces plausible wrong numbers rather than a crash.
✓
Keep the stale-pop guard. One comparison saves re-relaxing every edge of an already-settled node.
✓
Use 64-bit distances. V·maxWeight overflows 32 bits on large graphs long before anything looks wrong.
✓
Never add to the infinity sentinel. Guard the relaxation or leave headroom in the sentinel value.
✓
If you only need one target, stop the moment it is popped — everything after that is wasted work.
✓
For the route, store parent[v] = u at each improvement and walk it back. Do not re-run the search to find it.

Step 9

Approaches — trade-offs

O((V + E) log V)O(V)

The version above. The default for sparse graphs, which is almost everything you meet in an interview — road networks, grids, state spaces.

O(V²)O(V)

Drop the heap and scan the distance array for the cheapest unsettled node each round. Better when the graph is dense — with E ≈ V² the scan is free next to the edge work, and you avoid the heap's constant factor and its stale entries entirely.

for (int it = 0; it < n; it++) {
    int u = -1;
    for (int v = 0; v < n; v++) {          // scan, no heap
        if (!done[v] && (u < 0 || dist[v] < dist[u])) { u = v; }
    }
    if (dist[u] == INF) { break; }
    done[u] = true;
    // ... relax every edge out of u ...
}
O(V·E)O(V)

Slower, but it is the answer when weights can be negative — and it detects negative cycles, which Dijkstra cannot even represent. Reach for it the moment the problem mentions refunds, discounts, or profits along an edge.

Step 10

Complexity

Time
O((V + E) log V)
Each successful relaxation pushes one heap entry, so at most E entries exist. Every entry is pushed and popped once at O(log V), and each pop scans one adjacency list.
Space
O(V)
One distance per node. The heap can hold up to O(E) entries at once because improvements push duplicates rather than decreasing a key.

Take home

LeetCode problems that are this algorithm

LC 743 — Network Delay Time: Dijkstra unchanged; the answer is the largest finite distance, or -1 if any node is unreachable.

LC 1631 — Path With Minimum Effort: same loop with a different combine rule — the cost of a route is the maximum edge on it, not the sum. Dijkstra works for any rule that never decreases along a route.

LC 787 — Cheapest Flights Within K Stops: the extra "at most K stops" makes a node's state (city, stops used). Once you widen the node, it is Dijkstra again.

LC 778 — Swim in Rising Water: a grid where the cost is the highest cell on the route. Same max-rule variant, implicit graph.

The trick to carry: if all weights are 1, use BFS. If they are not, use Dijkstra — and if any is negative, stop and use Bellman-Ford.
