Algorithm Lesson

Bellman-Ford Algorithm

Graph Algorithms Tier 2 · core O(V·E) time · O(V) space

Before you code

Clarifying questions to ask first

Ask these before writing anything. The answers decide whether the question even has an answer.

Can a weight be negative?
Yes — that is the whole reason to be here.
→ Dijkstra is ruled out; its greedy claim needs non-negative weights
Can there be a negative cycle?
Possibly.
→ then "shortest" has no answer at all, and the algorithm must say so instead of returning numbers
Directed or undirected?
Directed.
→ a negative edge in an undirected graph is a negative cycle: walk it back and forth
How do we mark an unreachable node?
With null, not -1.
→ with negative weights, -1 is a perfectly legal distance. A numeric sentinel would be ambiguous.

The Insight

After round k, every route of k edges has been priced

You cannot settle nodes one at a time any more — a negative edge could always undercut a finished answer. So stop being clever. Relax every edge, then do it again. Each full round extends every correct distance by one more edge, and a shortest route never repeats a node, so V-1 rounds is enough.

still ∞ has a value, may still fall proved final by this round
Why V-1 rounds is exactly the right number:
1
A round adds one edge to every answer
Suppose the true shortest route to v is correct up to its second-to-last node u. A round relaxes every edge, including u→v, so after that round v is correct too. Order inside the round does not matter — it can only help.
2
A shortest route uses at most V-1 edges
If it repeated a node it would contain a cycle. Without negative cycles, dropping that cycle is never worse, so some shortest route has no repeats — and a route with no repeats touches at most V nodes, hence V-1 edges.
3
So one extra round is a negative-cycle detector
After V-1 rounds everything reachable is final. If a V-th round still lowers something, the improvement must come from a route with more than V-1 edges — a repeat — and it only helped because that cycle pays. There is no answer to return.

The kernel

Relax every edge, V-1 times over. Round k makes every route of k edges correct, and a shortest route in a graph with no negative cycle needs at most V-1 edges, so the answer is complete. One more round that still improves something proves a reachable negative cycle exists.

Step 1

Brute force — feel the cost

The naive method is to walk every route that never repeats a node and keep the cheapest total per node. It is right whenever no negative cycle exists — but the route count grows factorially, and it cannot say anything useful when a cycle does pay. Watch the counter.

routes walked: 0 current route: — cost: 0

Cost: O(V!) time — and it cannot report a negative cycle

Restricting to routes with no repeats is what keeps it finite, but that same restriction hides the negative cycle: the walk simply refuses to go round it, and returns numbers that look fine.

// Walk every simple route; keep the cheapest total per node.
void walk(int u, long long cost, vector<long long>& best,
          vector<bool>& onPath, vector<vector<pair<int,int>>>& adj) {
    onPath[u] = true;
    if (cost < best[u]) { best[u] = cost; }
    for (auto& [v, w] : adj[u]) {
        if (onPath[v]) { continue; }   // this is what hides the cycle
        walk(v, cost + w, best, onPath, adj);
    }
    onPath[u] = false;
}

Step 2

Translations — every optimisation, named

Three swaps turn the route walk into V rounds of edge sweeping.

1
Track which route → keep only the best number
A node never needs its history. Relaxing an edge blindly is enough, because a wrong guess can only be replaced by a better one.
O(V!) → O(V·E)
2
Loop until nothing changes → stop after V-1 rounds
The bound is not a guess. A shortest route has at most V-1 edges, and round k prices every route of k edges, so round V-1 finishes the job.
a guaranteed termination bound
3
Separate cycle hunt → one extra round
No second algorithm is needed. If round V still improves something, the improvement used more than V-1 edges, which means a cycle that pays.
detection for one extra O(E) pass

Step 3

The algorithm in plain English

1
Set up. Every distance starts at infinity except dist[src] = 0.
2
Do V-1 rounds. In each round walk the entire edge list once, in any order.
3
Relax each edge. If dist[u] + w < dist[v], lower dist[v]. Skip edges whose source is still infinite.
4
Stop early if a round changes nothing — the answer has already settled and further rounds are wasted work.
5
Run one more round. If anything still improves, report a negative cycle. Otherwise return the distances, with null for unreachable.

Step 4

Code

C++ first — that is the version the walkthrough below animates. The dist[u] == INF guard is not optional: without it the sentinel overflows and looks like an improvement.

struct Result { vector<long long> dist; bool neg; };

Result bellmanFord(int n, vector<array<int,3>>& edges, int src) {
    const long long INF = 4e18;
    vector<long long> dist(n, INF);
    dist[src] = 0;
    for (int round = 1; round < n; round++) {
        bool changed = false;
        for (auto& [u, v, w] : edges) {
            if (dist[u] == INF) { continue; }      // never add to the sentinel
            if (dist[u] + w < dist[v]) { dist[v] = dist[u] + w; changed = true; }
        }
        if (!changed) { break; }                // settled early
    }
    for (auto& [u, v, w] : edges) {              // one extra round = detector
        if (dist[u] != INF && dist[u] + w < dist[v]) { return {{}, true}; }
    }
    return {dist, false};
}
def bellman_ford(n, edges, src):
    INF = float('inf')
    dist = [INF] * n
    dist[src] = 0
    for _ in range(n - 1):
        changed = False
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                changed = True
        if not changed:
            break
    for u, v, w in edges:
        if dist[u] + w < dist[v]:
            return None, True          # reachable negative cycle
    return [None if d == INF else d for d in dist], False

Step 7

Corner cases

1
Adding to the infinity sentinel
If dist[u] is LLONG_MAX, then dist[u] + w with a negative w is smaller than the sentinel and looks like a real improvement — so unreachable nodes acquire nonsense distances. Guard with if (dist[u] == INF) continue; or use a sentinel like 4e18 that leaves headroom.
2
A negative cycle the source cannot reach
It never affects any distance, so arguably the answer is still valid. The plain detector reports it anyway, because it checks every edge. If that matters, restrict the final check to edges whose source has a finite distance — which is what the code above does.
3
Using -1 for unreachable
A real bug here, unlike in BFS. Negative weights make -1 a perfectly ordinary distance, so a caller cannot tell "cost -1" from "no route". Return null or keep the infinity sentinel.
4
An undirected graph with a negative edge
There is no answer, ever. Walking that edge back and forth is a cycle of twice its weight, so it is negative. If a problem gives you undirected negative weights, one of your assumptions is wrong.
5
Dropping the early exit
Not a correctness bug, but on most real graphs the distances settle in far fewer than V-1 rounds. The changed flag usually turns O(V·E) into something close to O(E).

Step 8

Production readiness

✓
Guard the sentinel before every relaxation. This is the bug that produces distances for nodes that have no route at all.
✓
Keep the early-exit flag. Free, and it usually cuts the round count to a handful.
✓
Return the cycle verdict in the type, not as a magic number. A caller must not be able to use the distances without seeing the flag.
✓
Use 64-bit distances. V·maxWeight overflows 32 bits, and negative weights let it overflow in both directions.
✓
To name the cycle, record parent[v] on each relaxation, then walk back V steps from a node that improved in the extra round — that lands you inside the cycle.
✓
If all weights are non-negative, use Dijkstra. Bellman-Ford is O(V·E); paying that when you do not have to is the real mistake.

Step 9

Approaches — trade-offs

O(V·E)O(V)

The version above. Simple, predictable, and the standard answer when weights can be negative or when you must detect a negative cycle. Also the easiest to adapt to "at most K edges" — just run K rounds.

O(V·E) worst caseO(V)

Only relax edges out of nodes whose distance actually changed, kept in a queue. Much faster in practice, same worst case — and adversarial inputs really do hit it, so do not rely on the average when the input is not yours.

queue<int> q; q.push(src); inQ[src] = true;
while (!q.empty()) {
    int u = q.front(); q.pop(); inQ[u] = false;
    for (auto& [v, w] : adj[u]) {
        if (dist[u] + w < dist[v]) {
            dist[v] = dist[u] + w;
            if (!inQ[v]) { q.push(v); inQ[v] = true; }
            if (++cnt[v] >= n) { return NEGATIVE_CYCLE; }
        }
    }
}
O(V³)O(V²)

Gives every pair at once and also handles negatives. Better than running Bellman-Ford from every source (which is O(V²·E)) whenever the graph is dense, and it detects negative cycles from the diagonal. Worse if you only need one source.

Step 10

Complexity

Time
O(V·E)
Each round scans the whole edge list, O(E), and there are V-1 rounds plus one detector round. The bound is tight: a path relaxed in the worst order needs every round.
Space
O(V)
One distance per node. The edge list is the input, and nothing else is stored — no queue, no heap, no visited set.

Take home

LeetCode problems that are this algorithm

LC 787 — Cheapest Flights Within K Stops: the cleanest fit anywhere on LeetCode. Run exactly K+1 rounds and the "at most K stops" limit falls straight out of the round count — but relax from a copy of the previous round's distances, or one round can chain several flights.

LC 743 — Network Delay Time: weights are non-negative so Dijkstra is better, but Bellman-Ford is a correct and much shorter answer worth knowing.

LC 1976 — Number of Ways to Arrive at Destination: shortest paths plus a count. The counting layer works on top of either algorithm.

The trick to carry: "at most K edges" is the giveaway. Dijkstra has no notion of round number, but a Bellman-Ford round is an edge count.
