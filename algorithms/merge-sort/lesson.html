Algorithm lesson

MergeSort

Foundational Algorithms Tier 2 D&C Sort
Section 1

Explain the algorithm in plain English

MergeSort is a divide-and-conquer algorithm designed to sort a collection by breaking it into smaller pieces. Instead of sorting a large stack of cards all at once, you divide it in half, sort each half independently, and then zip (merge) the two sorted piles back together. By comparing the top card of each pile and taking the smaller one, you assemble a fully sorted deck in linear time.

Is MergeSort stable?
Yes. If two elements have equal values, we prefer the one from the left subarray during merge, preserving their original relative order.
→ unlocks: stable sorting of identical keys
Can we sort in-place?
Standard array MergeSort requires O(n) auxiliary space to copy elements to temp buffers during merge to prevent overwriting.
→ unlocks: need for temporary buffers L and R

The kernel

Divide the unsorted array in half at its midpoint. Recursively sort the left and right halves. Once sorted, merge the two halves together by zipping them: compare elements from each half sequentially, taking the smaller element, and copy the sorted result back into the main array.

Section 3

Algorithm in plain English

1
Inefficient Local Scan → Divide and Conquer
Instead of scanning elements iteratively to bubble/insert them, split the array recursively down to size-1 subarrays.
→ reduces complexity from O(n²) to O(n log n)
2
Two Sorted Halves → Linear Merge
Zip two sorted segments together in a single linear pass by comparing their head elements, picking the smaller one.
→ merges in O(n) time at each recursive level
1
Check base case: if the range size is 0 or 1, it is already sorted — return.
2
Compute midpoint: mid = left + (right - left) / 2.
3
Divide and sort: recursively call MergeSort on left half [left, mid] and right half [mid + 1, right].
4
Copy to buffers: duplicate left and right segments into temporary arrays L and R.
5
Merge: compare heads of L and R, write smaller to main array, advance index. Repeat until one buffer is empty.
6
Flush remaining: copy any leftover elements of L or R back into the main array.

Section 5

C++ code

void merge(vector<int>& nums, int left, int mid, int right) {
    int n1 = mid - left + 1;
    int n2 = right - mid;
    vector<int> L(n1);
    vector<int> R(n2);

    for (int i = 0; i < n1; i++) {
        L[i] = nums[left + i];
    }
    for (int j = 0; j < n2; j++) {
        R[j] = nums[mid + 1 + j];
    }

    int i = 0;
    int j = 0;
    int k = left;
    while (i < n1 && j < n2) {
        if (L[i] <= R[j]) {
            nums[k] = L[i];
            i++;
        } else {
            nums[k] = R[j];
            j++;
        }
        k++;
    }

    while (i < n1) {
        nums[k] = L[i];
        i++;
        k++;
    }

    while (j < n2) {
        nums[k] = R[j];
        j++;
        k++;
    }
}

void mergeSort(vector<int>& nums, int left, int right) {
    if (left >= right) {
        return;
    }
    int mid = left + (right - left) / 2;
    mergeSort(nums, left, mid);
    mergeSort(nums, mid + 1, right);
    merge(nums, left, mid, right);
}

Section 7

Time and space complexity

Time
O(n log n)
The recursion tree has a depth of log n. At each level of the tree, merging n elements across various segments takes O(n) total operations. Therefore, overall time is O(n log n) in all cases (best, average, worst).
Space
O(n)
Allocating auxiliary temporary arrays L and R of combined size n is required during the merge step, alongside O(log n) stack frame space for recursion depth.

Common misconception

MergeSort always requires O(n) extra space. While true for arrays, it can sort linked lists in O(1) auxiliary space (using only O(log n) call stack space) because node links can be re-pointed without copying values.
