Algorithm Lesson

Topological Sort

Graph Algorithms Tier 1 · primer O(V + E) time · O(V) space

Before you code

Clarifying questions to ask first

Ask these before writing anything. Two of them decide whether an answer exists at all.

Are the edges directed?
Yes — u → v means u must come before v.
→ an undirected graph has no topological order; the question would be meaningless
Can the graph contain a cycle?
Yes, and then no valid order exists.
→ the algorithm must detect it, not spin or return a wrong order
Is the order unique?
Usually not — several orders can be valid.
→ break ties by smallest id so the output is deterministic and testable
What should a cycle return?
An empty list.
→ the caller checks result.size() != n, which is also the cycle test

The Insight

Count what is still waiting in front of you

You do not have to look ahead to know a node is safe to place. It is safe exactly when nothing is still waiting to come before it — when its count of incoming edges has fallen to zero. Placing it removes its edges, which may drop a successor to zero as well. The order builds itself out of a countdown.

still blocked (label = edges waiting) ready — nothing left in front placed in the order
Why a zero count is enough to commit:
1
Zero incoming means no unmet requirement
Every edge into a node is a "do this first". If none is left, every requirement has already been placed, so putting the node next cannot break any edge. No lookahead needed.
2
Placing a node can only help others
Removing a node deletes its outgoing edges, so successors' counts only ever fall. A node that becomes ready stays ready — there is nothing to undo and no backtracking.
3
Getting stuck is exactly a cycle
If the ready set empties with nodes left over, every leftover still has an incoming edge from another leftover. Follow those edges backwards and you must eventually repeat a node — that is a cycle, and no order exists.

The kernel

Count incoming edges per node. Repeatedly take a node whose count is zero, append it, and decrement each successor. Counts only fall, so a ready node never becomes unready and no backtracking is possible. If fewer than V nodes come out, the leftovers form a cycle and no order exists.

Step 1

Brute force — feel the cost

Without a stored count you would rescan. Each round, walk every unplaced node and, for each one, walk the whole edge list to ask "does anything unplaced still point at me?". Take the smallest node that passes, place it, and rescan from scratch. Correct, but each of the V rounds re-reads all E edges for every candidate. Watch the check counter.

rounds: 0 edge checks: 0 order so far: —

Cost: O(V²·E) time

Nothing is remembered between rounds, so the same edges are re-read V times over — and for every candidate within a round. Storing one integer per node removes all of it.

// Rescan for a node nothing unplaced still points at.
vector<int> topoSlow(int n, vector<pair<int,int>>& edges) {
    vector<bool> placed(n, false);
    vector<int> order;
    for (int round = 0; round < n; round++) {
        int pick = -1;
        for (int u = 0; u < n && pick < 0; u++) {
            if (placed[u]) { continue; }
            bool blocked = false;
            for (auto& e : edges) {      // full edge scan, per candidate
                if (e.second == u && !placed[e.first]) { blocked = true; break; }
            }
            if (!blocked) { pick = u; }
        }
        if (pick < 0) { return {}; }     // stuck => cycle
        placed[pick] = true;
        order.push_back(pick);
    }
    return order;
}

Step 2

Translations — every optimisation, named

Three swaps take the rescan down to a single pass over the edges.

1
Rescan the edges → store one count per node
Compute every in-degree once up front. "Is this node ready?" becomes a single array lookup instead of a scan.
O(V²·E) → O(V² )
2
Search for the next ready node → keep a ready set
When a node is placed, decrement its successors and push any that hit zero. A node is discovered ready exactly once, by the edge that freed it.
O(V²) → O(V + E)
3
Separate cycle check → count what came out
No extra traversal is needed. If the loop ends with fewer than V nodes placed, the rest are locked in a cycle.
cycle detection for free

Step 3

The algorithm in plain English

1
Count incoming edges. Walk the edge list once and add 1 to indeg[v] for every edge u → v.
2
Seed the ready set with every node whose in-degree is 0 — nothing has to come before them.
3
Take the smallest ready node and append it to the order. Smallest-first is only for determinism; any ready node is correct.
4
Release its successors. For each edge out of it, decrement indeg[v]; if that hits 0, add v to the ready set.
5
Stop when the ready set is empty. Return the order if it holds all n nodes, otherwise return an empty list — the leftovers form a cycle.

Step 4

Code

C++ first — that is the version the walkthrough below animates. The min-heap is only there to make the output unique; a plain queue is just as correct and slightly faster.

vector<int> topoSort(int n, vector<vector<int>>& adj) {
    vector<int> indeg(n, 0);
    for (int u = 0; u < n; u++) {
        for (int v : adj[u]) { indeg[v]++; }
    }
    priority_queue<int, vector<int>, greater<int>> ready;
    for (int u = 0; u < n; u++) {
        if (indeg[u] == 0) { ready.push(u); }
    }
    vector<int> order;
    while (!ready.empty()) {
        int u = ready.top(); ready.pop();
        order.push_back(u);
        for (int v : adj[u]) {
            if (--indeg[v] == 0) { ready.push(v); }
        }
    }
    if ((int)order.size() != n) { return {}; }   // stuck => cycle
    return order;
}
import heapq

def topo_sort(n, adj):
    indeg = [0] * n
    for u in range(n):
        for v in adj[u]:
            indeg[v] += 1
    ready = [u for u in range(n) if indeg[u] == 0]
    heapq.heapify(ready)
    order = []
    while ready:
        u = heapq.heappop(ready)
        order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                heapq.heappush(ready, v)
    return order if len(order) == n else []

Step 7

Corner cases

1
A cycle
Every node in the cycle keeps a positive in-degree forever, so none ever becomes ready. The loop exits early with a short order. The size() != n test is both the cycle detector and the error signal — do not add a second traversal for it.
2
No edges at all
Every in-degree is 0, so every node is ready immediately and the answer is just the nodes in id order. Correct, and worth stating out loud — an empty edge list is a valid DAG.
3
A disconnected graph
Nothing special is needed. Separate pieces contribute their own zero-in-degree nodes to the same ready set, and the pieces interleave freely in the output.
4
A duplicate edge
If u → v appears twice, indeg[v] is 2 and is decremented twice — consistent, so it works. But a self-loop u → u makes u permanently blocked, which is right: it is a cycle of length one.
5
Reading the edge direction backwards
The commonest bug, and it fails silently on symmetric-looking inputs. In LC 207 the pair [a, b] means "b before a", so the edge is b → a. Write the direction down before you write the loop.

Step 8

Production readiness

✓
Always check order.size() == n before trusting the result. Skipping it turns a cycle into a silently truncated answer.
✓
Decrement once per edge, inside the successor loop. Recomputing in-degrees each round is the accidental quadratic.
✓
Use a plain queue unless the output must be unique. The min-heap costs a log factor and buys only determinism.
✓
Confirm the edge direction against the problem statement, in writing. Reversed edges still produce a plausible-looking order.
✓
Iterative, not recursive. The DFS formulation is elegant but recurses to depth V; this one has no stack limit.
✓
To report which nodes form the cycle, return the set with non-zero in-degree at the end — no extra pass required.

Step 9

Approaches — trade-offs

O(V + E)O(V)

The version above. Iterative, detects cycles for free, and lets you control tie-breaking — which is what you want when the problem asks for the smallest valid order, or for "can this be scheduled at all".

O(V + E)O(V)

Run DFS; when a node has no unexplored successors left, push it onto a list. Reverse the list at the end. Shorter to write and natural when you already need DFS for something else, but it recurses to depth V and cycle detection needs an explicit third colour ("on the current path") rather than falling out.

void dfs(int u) {
    colour[u] = GREY;                 // on the current path
    for (int v : adj[u]) {
        if (colour[v] == GREY) { hasCycle = true; }
        if (colour[v] == WHITE) { dfs(v); }
    }
    colour[u] = BLACK;
    out.push_back(u);            // reverse `out` at the end
}
O(V²·E)O(V)

The brute force from Step 1: each round, rescan for a node nothing unplaced points at. Only worth knowing as the thing the in-degree array replaces — it makes clear that the counts are pure memoisation of a question you would otherwise re-ask.

Step 10

Complexity

Time
O(V log V + E)
The in-degree pass reads each edge once. Each node enters and leaves the ready set once, and each edge is decremented once. The log V is only the min-heap; with a plain queue it is O(V + E).
Space
O(V)
One in-degree per node, plus a ready set that can hold at most every node at once, plus the output list.
