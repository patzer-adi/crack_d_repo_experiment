Algorithm Lesson

Depth-First Search (DFS)

Graph Algorithms Tier 1 · primer O(V + E) time · O(V) space

Before you code

Clarifying questions to ask first

Ask these before writing anything. Each answer changes what the traversal has to handle.

Is the whole graph connected?
No — it can come in separate pieces.
→ one dive is not enough; restart from every node still unvisited
Directed or undirected?
Undirected here.
→ "connected" is symmetric. On a directed graph you need strongly connected components instead.
How deep can the graph get?
A path of every node — depth V.
→ use an explicit stack; recursion dies somewhere around 10⁴–10⁵ frames
Does the order inside a component matter?
No, only the grouping.
→ sort each component before returning so the answer is unique

The Insight

One dive drains one whole component

DFS commits to a direction. It follows an edge as far as it will go before it ever considers the second option, and it only backs up when there is nothing new ahead. So a single dive cannot stop halfway through a group of connected nodes — it keeps going until the group is exhausted. That is the whole component finder.

not visited where the dive is now waiting on the stack done, component fixed
Why one dive is exactly one component:
1
Nothing reachable is left behind
The dive only ends when the stack is empty, and the stack only empties when every neighbour of every node it touched was already visited. So no reachable node can escape it.
2
Nothing unreachable is pulled in
The dive only ever moves along an edge. A node in a different piece has no edge into this one, so it can never be reached. The group it collects is exactly the component.
3
So the restarts count the pieces
After a dive, the next node still marked unvisited must be in a piece nothing has touched. Each restart therefore begins a brand new component, and the number of restarts is the number of components.

The kernel

Push a start node and repeatedly pop, marking each neighbour the moment it is pushed. The dive ends exactly when the reachable set is exhausted, so the nodes it collected are one connected component. Loop over all nodes and restart the dive on any that are still unmarked; each restart is one more component.

Step 1

Brute force — feel the cost

Without traversal you would do label propagation: give every node its own label, then sweep the whole edge list pulling both endpoints down to the smaller label, and repeat until a whole sweep changes nothing. It is correct — labels can only fall, so it must settle — but a long chain moves the news one edge per sweep, so it costs O(V·E). Watch the sweep counter.

sweeps: 0 edge checks: 0

Cost: O(V·E) time

Each sweep touches every edge but may move a label only one hop. On a path of V nodes the label at one end needs V sweeps to reach the other, and every sweep re-checks all E edges even where nothing can change.

// Label propagation: sweep the edge list until nothing changes.
vector<int> labels(int n, vector<pair<int,int>>& edges) {
    vector<int> lab(n);
    for (int i = 0; i < n; i++) { lab[i] = i; }
    bool changed = true;
    while (changed) {
        changed = false;
        for (auto& e : edges) {         // a full sweep, every time
            int m = min(lab[e.first], lab[e.second]);
            if (lab[e.first]  != m) { lab[e.first]  = m; changed = true; }
            if (lab[e.second] != m) { lab[e.second] = m; changed = true; }
        }
    }
    return lab;                       // equal labels = same component
}

Step 2

Translations — every optimisation, named

Three swaps take repeated sweeping down to a single pass.

1
Sweep until stable → walk once
Instead of pushing news one hop per sweep, follow the edges directly. Reachability is transitive, so one walk settles a whole group in one go.
O(V·E) → O(V + E)
2
Compare labels afterwards → collect during the walk
The nodes a dive touches are the component. Append them as you pop, so there is no second grouping pass over the label array.
drops a full post-processing pass
3
Mark on pop → mark on push
If a node is only marked when it comes off the stack, the same node can be pushed once per incoming edge. Marking at push time caps the stack at V entries.
stack stays O(V), not O(E)

Step 3

The algorithm in plain English

1
Mark everything unvisited and start with an empty list of components.
2
Walk the nodes in order. Skip any that is already visited — it belongs to a component you have finished.
3
Start a dive. Push the node, mark it, and repeatedly pop a node u, adding it to the component being built.
4
Push unvisited neighbours, marking each one as you push it so nothing enters the stack twice.
5
When the stack empties the component is complete. Sort it, record it, and go back to step 2.

Step 4

Code

C++ first — that is the version the walkthrough below animates. The Python version is the same algorithm with the noise removed.

vector<vector<int>> components(int n, vector<vector<int>>& adj) {
    vector<bool> seen(n, false);
    vector<vector<int>> comps;
    for (int s = 0; s < n; s++) {
        if (seen[s]) { continue; }      // already in a component
        vector<int> comp;
        stack<int> st;
        st.push(s); seen[s] = true;
        while (!st.empty()) {
            int u = st.top(); st.pop();
            comp.push_back(u);
            for (int v : adj[u]) {
                if (seen[v]) { continue; }
                seen[v] = true;             // mark on PUSH, not on pop
                st.push(v);
            }
        }
        sort(comp.begin(), comp.end());
        comps.push_back(comp);
    }
    return comps;
}
def components(n, adj):
    seen = [False] * n
    comps = []
    for s in range(n):
        if seen[s]:
            continue
        comp, st = [], [s]
        seen[s] = True
        while st:
            u = st.pop()
            comp.append(u)
            for v in adj[u]:
                if seen[v]:
                    continue
                seen[v] = True
                st.append(v)
        comps.append(sorted(comp))
    return comps

Step 7

Corner cases

1
Isolated nodes
A node with no edges is still a component of size one. The outer loop reaches it, the dive pops it immediately, and it is recorded. Forgetting the outer loop is how people report 0 components for an edgeless graph.
2
Marking on pop instead of on push
The classic bug. If seen[v] is set only when v is popped, a node with three unvisited neighbours can sit on the stack three times and be added to the component three times. Mark it the moment you push it.
3
Deep graphs and the call stack
A recursive DFS on a path of 10⁵ nodes overflows. The explicit stack above has no such limit — it is the same algorithm with the frames moved to the heap.
4
Self-loops and repeated edges
Both are absorbed by the seen guard and change nothing. A self-loop points at an already-marked node; a repeat finds the neighbour already marked.
5
A directed graph
This does not find components on a directed graph. Reachability stops being symmetric, so "u reaches v" no longer means they belong together. Use Kosaraju or Tarjan for strongly connected components.

Step 8

Production readiness

✓
Mark on push. It bounds the stack at V entries and stops duplicates entering a component.
✓
Iterative, not recursive, on anything user-sized. A stack overflow is a crash, not an exception you can catch.
✓
Keep the outer restart loop. Without it you silently return only the component containing node 0.
✓
Sort the output (or document that it is unordered). An unsorted component list makes tests flaky when the adjacency order changes.
✓
Build the adjacency list once, in O(V + E). Re-scanning an edge list inside the dive is the usual accidental O(V·E).
✓
If you only need the count, skip collecting nodes and just count restarts — same traversal, O(1) extra memory.

Step 9

Approaches — trade-offs

O(V + E)O(V)

The version above. Best when you already hold an adjacency list and want the component contents, a spanning tree, or entry/exit times for later work like cycle detection or bridges.

O(E·α(V))O(V)

Merge the two endpoints of every edge, then read off the classes. Nearly linear, and the only option when edges arrive over time — you can answer "same component?" after each one without redoing any work. DFS would have to restart from scratch.

int find(int x) { return p[x] == x ? x : p[x] = find(p[x]); }
void join(int a, int b) { p[find(a)] = find(b); }
// components = number of x with find(x) == x
O(V + E)O(V)

Swap the stack for a queue and you get BFS — identical cost and identical components, since the reachable set does not care about visit order. Prefer BFS when you also want shortest distances; prefer DFS when you want depth structure such as back edges, bridges, or topological order.

Step 10

Complexity

Time
O(V + E)
Marking at push time lets each node enter the stack once, so there are V pops across all restarts. Each pop scans one adjacency list, and every edge is scanned from both ends — 2E in total.
Space
O(V)
The seen array is V entries and the stack holds at most V nodes, since no node is ever pushed twice.

LC 200 — Number of Islands: the grid is the graph and a cell's four neighbours are its edges. Counting islands is counting restarts.

LC 547 — Number of Provinces: components from an adjacency matrix, almost unchanged from the code above.

LC 695 — Max Area of Island: same dive, but return the size of each component instead of its contents.

LC 207 — Course Schedule: DFS on a directed graph, where the depth structure matters — a back edge to a node still on the stack is a cycle.

The trick to carry: "how many groups" and "what is in my group" are always one traversal plus a restart loop. What changes between problems is only what counts as a neighbour.
